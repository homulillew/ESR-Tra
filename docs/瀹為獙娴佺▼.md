# 一、实验背景

当前研究关注长程 Search Agent 中两个问题：

```text
搜索 → Evidence → State → 后续搜索
```

以及：

```text
最终 Reward → 中间 Action Credit
```

AREX 的 bad case 中已经观察到：

1. 搜索结果中已经包含相关内容，但模型没有真正读取并形成可用 Evidence；
2. 模型已经读到正确 Evidence，但 State 中进行了错误解释；
3. Evidence 已经找到，但人物、条件、Claim 和 Evidence 之间的关系绑定错误；
4. 错误 Candidate 写入 State 后会持续影响后续 Search；
5. 长轨迹压缩后，错误 State 更难重新检查和修复；
6. Outcome-level GRPO 对长轨迹的信用分配较粗，成功轨迹中的无关动作可能一起得到正信用，失败轨迹中的有效动作可能得到负信用。

因此我们设计 ESR：

```text
Raw Evidence
     ↓
Claim-Evidence State
     ↓
Verification + Gap
     ↓
指导后续 Search
     ↓
State-based Credit
```

# 三、ESR最小前向设计

## 3.1 Raw Evidence

只有模型真正 `open / visit / read` 页面以后，Harness 才创建 Evidence。

Search Result 本身不能直接成为 Evidence。

```text
Evidence(
    evidence_id,
    source,
    raw_content
)
```

要求：

* `evidence_id` 唯一；
* Raw Evidence 由系统保存；
* Raw Evidence 不允许模型覆盖；
* Raw Evidence 不依赖 Context 压缩；
* 后续可以根据 `evidence_id` 重新读取。

需要支持类似：

```text
read_evidence(evidence_id)
```

的能力。

---

## 3.2 Finding / Evidence Directory

Research State 中不要长期放完整 Raw Evidence。

为真正读取过的 Evidence 保存一个简短 Finding：

```text
EvidenceDirectoryEntry(
    evidence_id,
    finding
)
```

Finding：

* 描述该 Evidence 中和任务相关的内容；
* 不负责判断最终答案；
* 不写置信度；
* 不写下一步搜索计划；
* 不把“我认为它支持 Candidate X”混入原始事实描述；
* 后续允许修正。

需要明确：

```text
Raw Evidence ≠ Finding ≠ Claim
```

---

## 3.3 Claim

TaskState 显式保存关键 Claim。

```text
Claim(
    claim_id,
    statement,
    status,
    supporting_evidence_ids,
    contradicting_evidence_ids
)
```

其中：

```text
status ∈ {
    unresolved,
    supported,
    contradicted
}
```

Claim 需要明确记录：

```text
Claim ↔ Evidence
```

的关系。

同一 Evidence 可以支持多个 Claim，也可能只支持其中一个 Claim。

不要仅维护一个扁平 Evidence List。

---

## 3.4 Gap

当前没有被充分解决的问题保存为 Gap：

```text
Gap(
    claim_id,
    description
)
```

Gap 需要和 Claim 对应。

Gap 用于指导后续 Search。

模型后续搜索时应该能够看到当前 Gap。

---

## 3.5 TaskState

V1 使用最小版本：

```text
TaskState(
    answer_or_candidate,
    claims,
    evidence_directory,
    gaps,
    verification_status
)
```

不要增加复杂知识图谱、概率字段、实体图、Requirement Graph 等额外结构，除非实际实现中完全必要。

# 四、State Update、Verify 和 Context Compression

这三个机制必须分开。

```text
State Update ≠ Verification ≠ Context Compression
```

---

## 4.1 update_state

当新 Evidence 会改变当前研究状态时，Policy 可以调用：

```text
update_state(...)
```

允许更新：

* Candidate / Answer；
* Claim；
* Claim-Evidence relation；
* Finding。

允许修正之前错误的 State。

但是：

```text
update_state 不能直接清除 Gap
```

Gap 必须经过 Verify 后才能清除。

---

## 4.2 Verify

Verify 是一次独立的 State Audit。

触发时机至少包括：

1. 当前 Candidate / Answer 基本形成；
2. 模型认为主要条件已经满足；
3. 模型认为某个 Gap 已经解决；
4. Submit 前必须执行。

Verify 时重新读取相关 Raw Evidence。

Verify Context 尽量只包含：

```text
Question
Current Candidate / Answer
Claims
Referenced Raw Evidence
Current Gaps（如需要）
```

不要把完整历史 Search trajectory、之前形成 Candidate 的长推理、Finding summary 全部送进去。

Verify 主要检查：

1. Claim 是否真正得到 Raw Evidence 支持；
2. Claim 和 Evidence 是否绑错人物、实体、论文、时间、关系等；
3. 是否存在 Evidence 明确 contradict 当前 Claim；
4. Answer 是否覆盖问题需要的关键 Claim。

Verify 可以：

```text
supported
unresolved
contradicted
```

并创建 Gap。

Gap 只有 Verify 才能清除。

---

## 4.3 Submit

Submit 必须经过 Harness gate。

至少要求：

```text
Current State 已经过最新 Verify
AND
verification_status == passed
AND
gaps == empty
```

否则拒绝 Submit，要求继续研究。

---

## 4.4 Context Compression

Context Compression 只由 token budget 触发。

正常 Research Context：

```text
System
+ Question
+ ResearchView(TaskState)
+ RecentTrajectory
```

ResearchView 至少包含：

```text
Candidate / Answer
Claims
Gaps
Evidence Directory
```

不要长期把完整 Raw Evidence 放在 Context。

上下文过长时：

```text
ResearchView(State)
+ Long History

→

ResearchView(State)
+ Recent Tail
```

Recent Tail 可以先设置为最近 2～3 个工具交互，具体参数可配置。

重要要求：

在删除旧工具 observation 前，必须确保已经真正读取的 Evidence 被注册到 Raw Evidence Store 中。

训练时仍然保存完整 rollout。

即：

```text
Training Trajectory ≠ Active Context
```

# 八、ESR-GRPO Credit设计

先使用保守 V1。

不要训练新的 Critic。

不要训练新的 Process Reward Model。

最终任务 Reward 仍然是主 Reward。

先按普通 GRPO 得到 trajectory-level group-relative advantage：

$$
A_i
$$

然后：

$$
A_i^+=\\max(A_i,0)
$$

只从最终成功并且结构合法的 trajectory 中分配 ESR 正信用。

定义：

$$
Z_i \\in \\{0,1\\}
$$

只有满足以下条件时：

```text
final benchmark answer correct
AND
latest state has passed Verify
AND
gaps == empty
AND
final Claim-Evidence relations structurally valid
```

才令：

$$
Z_i=1
$$

否则：

$$
Z_i=0
$$

# 九、动作回溯

主要使用两类 trace。

## 9.1 Final Support Chain

从最终答案回溯：

```text
Final Answer
    ↓
Claim
    ↓
Supporting Evidence
    ↓
Open / Read
    ↓
Related Search
    ↓
Related update_state
```

必须基于最终保留下来的：

```text
Claim ↔ Evidence
```

关系。

不能仅因为某个 Evidence 在轨迹里出现过就奖励。

---

## 9.2 Gap Repair Chain

如果 Verify 创建 Gap，并且该 Gap 后续真正解决：

```text
Verify
  ↓
Gap
  ↓
Search
  ↓
Open / Read
  ↓
Evidence
  ↓
update_state
  ↓
Verify
  ↓
Gap Resolved
```

则相关动作可以进入 Credit Mask。

不要简单奖励 Gap 创建和解决之间的所有动作。

必须根据：

```text
Gap
→ Evidence
→ State Update
```

的实际关系筛选。

# 十、Action Mask

为每个 Policy Action 构造：

$$
M_{i,t}\\in\\{0,1\\}
$$

V1 使用 action-level mask。

如果某个 action 属于：

```text
Final Support Chain
OR
Successfully Resolved Gap Repair Chain
OR
Necessary Final Verify / Submit
```

则：

$$
M_{i,t}=1
$$

否则：

$$
M_{i,t}=0
$$

最终 advantage：

$$
\\widetilde A_{i,t}
=
M_{i,t}Z_iA_i^+
$$

然后把 $\widetilde A_{i,t}$ 广播到该 action 对应的 Policy tokens。

环境 observation / tool result 不计算 policy loss。

---

# 十一、失败轨迹处理

V1 使用高精度正信用策略。

```text
成功轨迹 + 有效动作 → 正信用
成功轨迹 + 无关动作 → 0
失败轨迹           → 0
```

不要因为：

```text
Verify后来否定了某个Claim
```

就直接给之前动作负 semantic credit。

原因是 Verify 仍然由同一个 Policy 完成，并不能作为绝对 ground truth。

因此：

```text
Failure trajectory
```

仍然参与 group reward normalization / baseline 计算，但该 trajectory 本身不进行 ESR semantic policy-gradient update。

如果代码结构需要实现：

$$
A_i < 0
$$

则：

$$
A_i^+=0
$$

即可。

# 十六、实现原则

整个实现必须遵守以下原则。

## 原则1：最小化

V1不要增加：

* 复杂知识图谱；
* 额外Reward Model；
* Learned Critic；
* Claim概率；
* 搜索动作强制指定target claim；
* 复杂Candidate Graph；
* 多Agent Verifier。

先验证最核心假设。

---

## 原则2：保证公平对比

Baseline和ESR-GRPO之间，不要同时改变：

```text
Model
Retriever
Reward
Search Environment
Dataset
Evaluation
```

实验2中唯一核心变量应该是Credit Assignment。

---

## 原则3：记录完整轨迹

所有实验都必须保存完整trajectory和结构化event log。

不要只保存最终metric。

我们需要后续做bad_case分析。

---

## 原则4：不要静默修改实验设定

如果因为代码限制必须改变配置，例如：

* Model无法加载；
* Judge不可用；
* Retriever不可用；
* 显存不足；
* Context不足；
* RL trainer不支持action-level advantage；

必须明确记录：

```text
原计划
实际修改
修改原因
可能产生的实验影响
```

不要静默替换。

---

## 原则5：先保证正确，再追求规模

先在少量样本上检查：

```text
State correctness
Evidence provenance
Verify correctness
Credit mask correctness
```

确认没问题以后再扩大训练。

# 二十、最终报告格式

最终报告不要写成论文风格。

保持简洁，优先：

```text
实验配置
→ 实验结果
→ 现象
→ bad_case
→ 分析
→ 下一步
```

不要使用大量泛化语言。

每个主要结论尽量包含具体数字。

例如：

```text
ESR将High Recall Wrong从X条降低到Y条。

其中关系绑定错误从X条降低到Y条，但Evidence读取不足仍然存在。
```

而不是只写：

```text
ESR显著改善了Agent的Research能力。
```

不能由数据直接证明的结论使用：

```text
可能
初步说明
需要进一步验证
```

不要把相关性写成因果关系。
