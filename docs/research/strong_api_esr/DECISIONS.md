## 实际执行边界

默认使用 CPU 上新建的 SQLite FTS5 BM25 完整语料索引。索引完成标记和 corpus SHA256 已核对。不得把它写成下载的 Lucene 索引或稠密检索器。模型返回标识 glm-5.2，网关路由无法独立固定权重版本。thinking 参数未宣称已控制；真实请求省略该参数，各臂一致，保存实际响应字段。

第二组旧题运行显示：原 65,536 保守容量单位会在 baseline 真实输入仅 13,688 token 后阻止继续。计数探针 HTTP 200 只返回 `success`，不是计数服务。随后唯一一次长上下文合成探针成功，实测输入 130,069、输出 2 token。正式 pilot 之前，将各臂共同容量上限固定为 128,000，仍以 UTF-8 字节加 1,024 开销保守估计，且保留输出空间。该设置低于已观察的单次输入接受规模，但不宣称取得官方 tokenizer 或最大窗口认证。旧容量运行保留且不可与新容量直接归因比较。

第二组 E-off 在 a9/a10 同时引用和 dismiss 相同 ID。此前错误文字只陈述规则，未指出具体冲突集合；现在错误路径固定到 arguments.dismiss_observation_ids，并列出需要由模型移除的冲突 ID。状态在错误时仍完全不提交，不自动更正参数。

q594 的旧 E-soft 在 16 个动作内实际调用 auditor 9 次。多个无效报告自行新增 claim ID；普通重试没有稳定修复。改为把当前 ID 枚举与行数绑定到同一审核 schema，并用原生 audit_report 输出。已保存同一输入的离线诊断，一次真实调用得到合法的 c0 报告，输入 2,161、输出 1,175 token。它是固定输入诊断，不是自然 rollout 成绩。

pilot 开始前固定批跑暂停条件：基础设施终止/未完成；同一失败提案三次；两次审核协议失败；至少四个错误且占动作一半；连续三个错误。此前“累计三个错误即暂停”把分散且成功恢复的错误与执行死循环混在一起，现改为上述明确模式。暂停条件不改变 episode 内部决策、预算、评分或样本；所有旧暂停和失败保留。每个 pilot ID 跨版本最多两局，不能借代码版本变化无限重采样。


## Baseline 正文重复修复与 pilot 暂停

首批 pilot 前 7 题同时发送观察的 text 和内部 raw_parts，重复正文增加输入用量并诱发过早上下文停止。完整记录保留在私有目录；各局新增 difficulty_calibration_exclusion.json，不用于难度校准，仍计入预算及失败记录。第 7 局由操作者暂停，恢复脚本追加 operator_paused 终态，没有伪造模型提交或远端响应。

baseline 现在以与 ESR 一致的 visible_view 展示证据，每份独立正文完整保留，完全相同的重读指向历史中首次正文。全部查询、动作和结果历史仍在。该修复属于证据展示公平性的工程修复，不作为 ESR 科学机制收益。200 项测试通过，记录为 tests-09.txt。

固定 15 题 pilot 顺序与 9 题确认集不变。前 7 题只剩一次实际 episode 额度，难度只能标为单次健康观察；后 8 题仍允许两次。调度新增显式 start 偏移，只跳过原计划已经花费的次数，禁止按表现重排或补题。

## 搜索结果提交的容量检查

第二批 pilot 完成 12 题并中断第 13 题。6 题在搜索结果进入历史后触发 context_overflow。真实末次输入约 2.8 万至 3.3 万 token，低于长上下文探针的已接收规模；当前 128,000 上限是 UTF-8 字节的保守容量单位，不是已认证的最大 token 窗口。容量停止不用于把题目标为难。

源码显示 open/read/update 有提交前的下一轮输入检查，search 只有 focus 编辑检查，没有对完整返回结果做同样检查。补丁给 search 加入相同检查：过大返回不提交为可用命中，完整后端返回仍在原始检索日志，用量照计；下一轮明确说明可减少 top_k。两臂同样显示剩余容量，并在提交新内容时留出 2,048 个保守容量单位用于错误反馈。没有扩大上下文或生成预算，没有删除已经展示的独立证据。

## 开发集冻结与通用提示校准

15 题各两次 pilot 已用完。按预登记规则选出 9 题，实际全部暂列 medium；该档包含只有一次健康观测的情况。旧工程故障、协议卡死和已记录的 judge 争议不作为困难证据。因此没有完成可靠的易／中／难各 3 题校准，不能把这个不足用重新抽题或调整标签掩盖。确认集仍是最初锁定的 prior 1 易／5 中／3 难。选择清单、全部候选与失败位于私有 dataset_splits。

正式开发之前，给两臂相同的通用提示：结束前检查联合条件，返回原问题要求的目标与格式，包括明确要求的限定词和标点。原 ESR 独有的目标提醒移至共同提示。依据是已展示正确原文却在最后动作遗漏格式的真实断点；没有加入真实题答案、文档 ID 或定制查询。policy 版本 research-2.1.4，提示快照更新，209 项测试通过（tests-14.txt）。这是 baseline 与 ESR 的共同提示校准，不能单独归为 ESR 收益。

完整 CPU 索引 SHA256 已实际读取核验，记录在 index_fingerprint.json。后续每局记录该摘要，并核对路径、大小、修改时间；不声称每局重新读取全索引或获得防篡改存储。选候选规则在任何开发 ESR 结果之前登记：准确率优先，其次实际后端请求、在线模型请求、占用输入 token，相同时选更简单的 E-off；随后 B 与候选各重复一次验证。最终确认仍预留 54 局。
# 原生工具与审计引用的有界诊断（2026-09-09）

首个开发题的 E-soft 在 38 个动作后耗尽生成预算，其中调用审计 20 次。完整记录显示，审计把非连续原文当成逐字引文，并把一段真实引文归到了错误的 observation_id。修复只汇总所有错误引文的字段路径、claim_id 和 observation_id，让一次协议修复能处理全部已发现问题；原文匹配和允许证据范围仍严格检查。

对保存的失败前缀预登记了三个 policy 调用和一个审计修复调用。实验性的 take_action 单工具入口只通过一个 policy 前缀；另两个分别返回两个调用和一个未声明工具，故不启用该接口。其实现保留为默认关闭的诊断选项，便于复现失败。一次审计修复通过 schema 和原文校验，不能据此认定答案正确或保证后续审计可靠。

同时将多个工具、未声明工具名、非对象参数分开报错；全部原始提案和实际费用保留。保持 native 接口，使用同一通用适配器重新运行固定的开发队列，首个旧版本的三局单独报告，禁止混入新版本配对结果。

## 严格文本动作与 JSON 字符说明（2026-09-09）

第二个开发版本完成 8 局后暂停。第三题的 E-off 用 50 个动作提交，其中 19 次多工具响应被拒绝、1 次引用与 dismiss 冲突；其正式答案经固定 judge 判为正确。这是高成本恢复，不能因最后答对忽略错误。

随后只登记三个固定失败前缀，测试同一原问题、同一契约和已有历史下的文本 JSON 接口。三个输出均为单个 JSON 动作，两个通过完整参数校验；第三个使用无效的 focus.claim_id，严格拒绝。不给它追加诊断重试。原生单工具入口的两次失败仍保留；累计接口与审计诊断共 8 次，另有 4 次联通/容量探针，全部计账。

采用文本动作作为下一完整开发队列的共同接口：policy 的唯一工具契约留在系统消息，adapter 不再向 provider 声明原生 policy 工具；auditor 继续原生 audit_report。JSON 必须能整体严格解析，字段和证据不自动更正。枚举错误补充实际值和允许值，方便模型自行局部修复。该选择只得到小样本格式诊断支持，仍需完整队列验证。

第二题三臂都遗漏原问题要求的答案引号。固定 judge 判错，保留原分。共享提示补充 JSON 语法引号与字符串内容的区别，policy 版本 research-2.1.5；不包含真实题答案或定制查询。所有臂同时重新运行相同开发题，旧版本 11 局不混入新配对分母。这些是共同接口和格式修复，不能单独宣称为 ESR 研究机制收益。
