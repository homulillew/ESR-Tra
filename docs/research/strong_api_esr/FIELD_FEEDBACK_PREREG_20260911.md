# 审核报告字段反馈实验登记（2026-09-11）

本轮检验一个机制：校验器发现审核报告中 `status` 与 `need` 不一致时，给远程审核模型返回所有出错字段的位置和现有规则。模型仍须自行判断并生成完整报告；程序不改写答案、理由、状态或证据。默认审核配置在实验通过前保持不变。

## 证据与研究依据

起点为 `d09e9e1`，工作区干净，本地测试 334 项通过。三个独立失败前缀已存在：合成数量约束、合成时间范围、开发题 790。前两者的否定状态缺少 `need`，后者检测到答案缺少题目要求的引号，却在 `target.status=supported` 时填写了缺失条件。旧反馈只返回首个笼统错误，一次修复仍失败。原始记录在 `TASK_COVERAGE_20260910_FINISHED.json` 和 `TASK_LITERAL_20260910_FINISHED.json`，本轮不重新采样初始失败。

- [Diagnosis Before Recovery](https://arxiv.org/html/2608.11772v1)（2026-08）：按失败原因限制修复方式，并比较相同信息条件下的干预。本文实验仅借鉴诊断与有界修复，不移植其任务族策略搜索。
- [Closed-Loop Validation-Repair](https://arxiv.org/html/2607.24371v1)（2026-07）：向模型提供字段错误、原始输入、错误输出和 schema。本轮沿用已有一次修复上限。该论文的 schema 合规结果不能证明任务语义正确，本轮分别测量两者。
- [CAFE](https://arxiv.org/html/2608.24794v1)（2026-08）：研究搜索策略与反馈的共同训练。本轮只借鉴反馈调用需要通过结果与成本检验这一点，不运行训练，也不引用其提升作为本项目证据。
- [Reviewer Capability Governs Rejection Targeting, Not Repair Skill](https://arxiv.org/abs/2609.04270)（2026-09）：固定初始答案，区分发现错误和成功修复。本轮固定原始错误报告并单独记录误放行。

这是校验反馈接口的工程消融，不声称提出新的反馈算法。当前证据支持优先检验反馈精度，不支持增加证据图、多模型审核或新的训练奖励。

## 固定条件与假设

唯一新增变量为 `repair_feedback=generic|field_paths`。两组使用相同接受规则、完整证据、报告 schema、同一初始失败输出、EB-GLM-5.2、temperature=0.6、4096 最大输出 token、一次协议修复上限。字段反馈不能包含参考答案、离线标签、历史题解或论文正文。

为检验已经出现的语义检测结果，恢复历史提交 `d28b437` 的 `task_first_literal` 呈现方式作为**两组共同条件**：将原样答案放在不冲突的标记之间，题目、状态和完整证据另以 JSON 提供。其正文和答案呈现函数不改写。`atomic` 默认提示保持原样。这个恢复是固定实验条件，不作为本轮新机制，也不把它与字段反馈的效果混为一谈。

预测：字段反馈使三段失败报告在一次修复内成为合法的否定报告，至少一段优于同步 generic 对照；不会将缺失条件改判为全部 supported 来规避校验。如果它只改善格式、丢失语义否定或不能改善修复，则假设不成立。开发集进一步检验报告是否真正交给策略、策略是否据此改答案，以及最终判分和全部成本。

## 预算与固定顺序

开始累计请求 1,398 / 2,000；已登记 143 个 episode/诊断单位。总 episode 上限 240，确认集保留 54，开发及诊断剩余 43。本轮最多 36 个单位、477 次新增请求；保留所有失败，不每日清零。

1. 三段既有错误报告（数量、时间、790）的最后一次修复：每段 generic 与 field_paths 各一次，顺序交错。共 6 个单位、6 次真实请求。历史初始生成成本单列，不冒充新生成。
2. 若三段候选均合法且保持否定，并至少一段优于同步对照，运行一个合成正确答案 packet、790 原始 packet 的新审核（各最多 2 次），再运行一个合成完整策略 episode（最多 8 次）。共 3 个单位、至多 12 次请求。要求正确答案 supported、790 合法识别缺失引号、完整策略可提交且有完整动作回执。任一失败即不启动开发集。
3. 通过前两阶段后，固定开发题顺序为 149、790、26、785、301、1012、701、1044、718。每题 E-off、E-soft/literal/generic、E-soft/literal/field_paths 各一次，三条件按题循环轮换顺序。共 27 个 episode；每局至多 16 次在线请求，在线阶段全部结束后每个提交答案最多一次离线判分，最多 459 次请求。相同检索器、工具、上下文和状态配置，不挑题、不扩局、不重试直到正确。

继续遵守用户暂停 baseline 的要求。本轮 E-off 是 ESR 内部消融，不称为无 ESR baseline。确认集保持封存。当前九题的难度标签均为 provisional medium，不声称已有平衡分层。

传输错误、用量缺失、实际模型变化、回执/请求 schema 异常立即暂停。固定错误前缀中对照的预期报告错误计入结果；不要求对照也通过才能进入下一阶段。开发集中对照协议失败保留并继续其他独立题，候选连续两局出现审核协议故障则停止余下调度；请求耗尽按失败计，不自动扩额。缺失的调度单独列出，不以完整结果口径汇总。

## 判定与交付

固定前缀报告格式正确率、保持语义否定的修复率、错误放行率分开报告。自然 rollout 统计提交正确率（含未提交失败）、真实 policy/audit/repair/judge 请求、实际输入输出 token、检索后端调用、全部失败和成功耗时、审查之后的答案变化。只在同题同配置成对比较；不同模型的历史 baseline 仅供背景说明。

本轮最多实施这一个机制。固定前缀门槛失败则记录移除或仅保留工程改进，不用剩余预算继续调提示到通过；门槛通过后冻结代码再执行完整预登记调度。无训练，`supported` 不能直接当正的最终奖励。没有达到准确率、成本和速度目标时如实报告。
