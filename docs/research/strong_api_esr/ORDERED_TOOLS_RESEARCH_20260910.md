# ESR 顺序工具执行：失败分析与预登记（2026-09-10）

本研究检验一个问题：强策略已经知道下一组动作时，允许它在一次响应内按顺序更新状态、检索、审核或提交，是否能减少协议修复和无效等待，并提高正式提交准确率。ESR 保留 target、answer、claims、focus 和不可变原文；policy 与 auditor 仍通过同一个 Lanz-Medium 网关调用。本文件仅供离线研发阅读，不进入被测模型上下文。

## 1. 已确认的损失与尚未证明的解释

旧前七题模型请求 B/E-off/E-soft 为 53/65/85，后端调用为 85/58/50。ESR 少检索却多请求，主要成本转移到了状态维护、协议恢复和审核；两臂都答对的条件子集上，E-off 和 E-soft 的完成时间分别增加约 175.55% 和 118.47%。这不是整体更快。

另有待检验的状态假设：ESR 工作卡仅显示最近两次同 claim 的搜索，recent_actions 不包含旧查询及结果；原文引用后可从当前卡消失，旧 finding 也可能被替换。普通 baseline 保留完整历史，因此 ESR 可能损失桥接线索。目前先不同时改记忆，以免无法区分接口与上下文的作用。

q790 的更细核查说明，损失有两层：研究上已经抽取到目标词，操作上还欠旧观察的处理。旧动态 schema 将答案提交隐藏，只保留弃权，可能放大模型提前放弃；这是机制解释，不能从单条轨迹证明因果。顺序执行会保留提交工具、显示实际前置条件，但不会自动消除 pending。若该错误继续出现，应独立检验 pending 是否需要阻挡终止，而非为这道题补写引用或答案。

## 3. 唯一主要机制：有界顺序执行

配置 `ordered_tool_calls: true`。一个 policy 响应最多四个原生调用，按数组顺序执行；允许 update_state→search、update_state→submit，以及显式选择的 update_state→verify_answer→submit。每项仍是独立动作并逐项记账，审核仍是真实额外模型请求。

- 首个失败会阻止本响应后续调用，已有成功动作保留；不在更新失败后提交旧答案。
- 终止动作必须最后出现；未执行项仍保存回执。
- 只能使用该响应之前已有的搜索命中和已交付观察；新打开的正文不能在同一响应内被猜测引用。
- 每项搜索使用执行到该位置时已提交的 focus，作用域逐项保存在检索记录中。
- pending、answer、审核运行时前置条件保持；hard 仍要求 supported，soft 仍保留真实 verdict。
- 不自动提取答案、不补字段、不新增工具或模型，不改变检索器、state 结构、审核格式、采样或判分。
- 两臂共享顺序执行能力与限制；baseline 保留完整历史和自然 finish，重新采集同源码 baseline。

可证伪预测：混合动作和不同 focus 的协议拒绝消失；模型若采用显式连续动作，每个正式提交所需 policy 轮数下降，单局末尾只有 draft 的失败减少。若拒绝消失但准确率不升或请求不降，接口简化不足以解释主要损失。旧接口的固定合成回归与新接口的相同合成动作构成机制诊断；真实自然 rollout 不强行要求模型发出指定组合。

## 4. 新阶段预算与公平评价

用户本轮给定 `1,323 / 2,000`，按全历史请求总上限登记，保留 1,323 条已有请求及 9 条未知用量记录。允许增加的 677 次包含 policy、audit、协议修复、传输重试、fixture 和 judge。账本增加显式用户授权字段；默认仍禁止自行提高总上限。

旧阶段四轮主要机制记录保留。本轮新授权研究最多再引入两项主要机制，每项先看完整固定九题；连续无可信改善即停止。不得重复采样直到成功。

1. 一局合成 E-soft 联通，最多 16 次在线请求，不判 benchmark 分数。真实结构错误先停批跑。
2. 固定九题 149、790、26、785、301、1012、701、1044、718，B/E-off/E-soft 各一次。顺序按题目位置奇偶交错，分三题一批审核；每局在线最多 16 次（含 audit/重试），最多 64 个动作，每个已提交答案最多一次离线 judge。失败局不补跑。完整首轮最多 459 次请求，实际逐批检查。
3. 候选按完整九题正式准确率优先；同分时选在线模型请求少者，再比较后端调用及双方都正确题目的时间。成本改善不得补偿准确率下降。若出现相对 baseline 的准确率改善，预算允许时再按同顺序完成 B 与候选的第二次运行，然后才考虑冻结。
4. 若首项机制无准确率收益，基于新完整轨迹选择至多一个最小机制；必须有预算重建完整九题三臂对照，不能只重跑输题。如果不能负担则停止，留下未证实结论。
5. 确认集保持封存。原目标为九题、两臂、三次共 54 局；按 16 次在线加一次判分的最坏上界，仅确认就需 918 次，超过本轮全部新增额度。不能承诺完成该设计，也不擅自改成更少题、更低单局上限；只有可合理保障剩余完整流程时才启动。

基础设施错误保留计分；同局最多两次传输尝试。新出现且未恢复的服务错误暂停该批，先离线核查；重复系统性协议问题也暂停。不无限探测、不延长失败 episode。路由若改变则相关 baseline 重新建立，当前网关别名无法固定底层模型版本。

共同测量补丁单独提交：计时从 episode 收到原问题开始，包括输入、索引、预算预检，保留 preflight_seconds 分项；不能与旧计时直接拼成同版本实验。所有新比较保留模型调用、真实后端调用、动作、实测/未知 token 和双方正确条件下耗时。

## 5. 用户要求节省 baseline 请求后的调整

首批刚开始，用户提出已有 baseline 不必重跑。本轮据此停止新增重复 baseline，仅运行固定九题的 E-off/E-soft，复用旧阶段七题的合格 baseline 作开发参考。旧 q1044、q718 baseline 未运行，不用历史不合格 pilot 填补，也不声称九题都有对照。已启动的新 q149 B 两次 429 失败照常保留，不替换成旧成功记录，不补跑。

这一调整发生在新 ESR 结果产生之前。新 ESR 与旧 baseline 不是相邻时间块的严格配对：共享工具提示、调用调度配置和计时起点存在差异，网关也未固定底层版本。跨阶段比较仅作机制筛选，不能单独据此宣称公平验证胜过 baseline。若得到改善信号，正式确认仍需要最终冻结条件下的完整对照；当前先把请求用于 ESR 诊断和迭代。
