# 强 API 正式开发实验：首批对照与预算停止记录

执行日期：2026-09-10。全部在线实验使用提交 `eef3e27419d78d7ca2aee9c1ab201a7647345596`；功能补丁为 `1658bd6`。采集期间没有修改源码、提示、检索器、判分规则或题目顺序。

**已完成 10 局真实运行，新增 91 次 API 请求。首批三题中，baseline 答对 3/3，E-off 答对 2/3，E-soft 答对 3/3；两种 ESR 的模型成本和完成时间都高于 baseline。第四题的 E-soft 用满单局 16 次请求仍未提交，触发预先登记的扩批暂停。完整九题对照和确认集尚未完成。**

ESR（Evidence-State Research，保存原始证据、可修订结论和待解决问题的研究方法）由本地 harness 执行状态与证据规则。被测 policy、auditor 和独立上下文的离线 judge 均调用用户指定的远程 Lanz-Medium；Codex 只负责实验执行与离线分析。

## 1. 实验条件与样本范围

| 项目 | 实际设置 |
|---|---|
| API | Anthropic Messages 兼容格式，实际 POST `http://lanz.hikvision.com/v3/anthropic/model/v1/messages` |
| 模型 | 请求 Lanz-Medium；本次 91 份响应均返回 `DeepSeek-V4-Flash-0731`，权重版本无法固定 |
| 检索 | BC+ 全语料 SQLite FTS5 BM25，CPU 本地执行；使用已验证指纹的同一索引 |
| B | 普通多轮检索，保留历史观察，无 ESR 状态或语义审核门禁 |
| E-off | ESR 状态与 focus，关闭在线 auditor |
| E-soft | ESR 状态与 focus，同模型独立上下文审核，保留实际 verdict |
| 单局共同预算 | 16 次 policy＋audit＋修复＋传输尝试；64 个已执行动作；24,000 输出 token；900 秒 |
| 请求参数 | temperature=0.6，单次 max_tokens=4096，保守上下文上限 128,000；thinking 使用未核实的 provider 默认设置 |
| 工具 | 同一原生接口，每次决策至多 4 个可组合的检索调用，逐项回执；状态修改、审核和提交需要独立决策 |
| 判分 | rollout 结束后，独立进程读取原问题、正式提交答案和参考答案；固定官方 BC+ 模板，temperature=0，单答案最多 1 次 judge 请求 |
| 缓存与执行顺序 | 单并发，题内相邻运行三臂并交错先后；无跨局应用缓存，OS/provider 缓存状态无法完全控制 |

没有额外联通探针或合成 rollout。首批运行固定开发顺序的 q149、q790、q26，每题每臂一次，9 局全部结束。第二批预登记 q785、q301、q1012 的 9 局；q785 E-soft 先运行，触发停止后其余 8 局保留为未执行。最后三题 q701、q1044、q718 的下一批尚未启动。

完整开发设计为九题三臂，共 27 局，目前完成 10 局。下面的配对结果只描述预先登记且完整执行的首批三题。q785 的单臂失败单独报告；不将其与缺失的 baseline 拼成配对结果，不把未运行条目删除。

冻结开发表的经验难度标签全部为 provisional medium，原 pilot 的健康样本不足，且模型后来更换。因此本阶段不能宣称完成了可靠的简单／中等／困难分层验收；保留原样本和标签，没有根据本次 ESR 输赢换题或补题。确认集保持封存，0/54，未创建 `FINAL_FREEZE.json`。

## 2. 首批三题的真实对照

以下调用和 token 为三局合计；时间为全部三局的平均在线耗时，离线判分另计。

| 实验臂 | 正式答对 | 模型请求（policy＋audit） | 实际检索后端请求 | 输入 / 输出 token | 平均在线耗时 |
|---|---:|---:|---:|---:|---:|
| B | 3/3 | 11＋0 | 14 | 40,347 / 2,373 | 42.5 秒 |
| E-off | 2/3 | 27＋0 | 24 | 148,256 / 12,798 | 171.3 秒 |
| E-soft | 3/3 | 23＋6 | 13 | 134,772 / 12,236 | 151.6 秒 |

E-off 的一次失败是主动弃答，按正式口径计为未答对。不能将弃答耗时解释为正确完成速度改善。只在两臂都正确的题上比较：E-off 的正确完成耗时为 B 的 **4.12 倍**（两题），E-soft 为 B 的 **3.57 倍**（三题）。这是条件分析，不能推广到所有题目。

E-soft 的实际后端请求少 1 次，下降 7.1%，但模型请求增加 163.6%、输入 token 增加 234.0%、输出 token 增加 415.6%。E-off 的后端请求增加 71.4%，模型请求增加 145.5%，准确率低 33.3 个百分点。

在这三题上，B 已全部答对，两种 ESR 均未表现出更高准确率；E-soft 的检索节省也不足以抵消模型与审核成本。研究预登记的“准确率至少增加 5 个百分点、实际工具量下降 15%、正确完成耗时下降 10%”没有达到。三题不能支持总体统计结论，本报告没有对不完整样本生成置信区间。

完整九题比较入口实际拒绝了当前缺失的对照，错误日志保留在私有 `formal_development_full_cohort_guard_20260910.txt`。没有放宽比较程序来发布一个伪装成九题的结果。

## 3. 轨迹中的主要问题

### q149 E-soft：审核协议修复增加调用与耗时

运行 `20260910T055520156584Z_development_E-soft_149_0` 的 `d27/a4` 审核失败。首次审核同时声明 supported 和未解决关系；程序要求修复后，API 返回了空 `audit_report` 参数。后续策略再次研究并审核，又遇到 claims 数量错误，第二次格式修复才通过。

本局最终提交且独立判对，但实际使用 8 次 policy、4 次 audit。所有原始报告、修复要求和用量保留；失败审核没有伪装成成功缓存。

### q790 E-off：候选已存在，pending 证据尚未处理，策略选择弃答

运行 `20260910T060008467084Z_development_E-off_790_0` 的首次双检索因不同 focus 被整组拒绝，两项均有 `not_executed` 回执。后续搜索、打开与 `a5` 状态更新成功；`a6` 选择 `submit_answer(decision=abstain)`，理由明确提到尚未处理的观察与未核实段落。

终态草稿非空，但正式结果是弃答。这里没有将草稿转换成提交，也没有为它额外调用 judge。现有证据说明 pending 管理和停止选择仍有成本；不能仅凭其他臂答对，断言这局已经完成了相同证据核验。

### q26 E-off：持续搜索，直到单局最后一次请求才提交

运行 `20260910T060254147388Z_development_E-off_26_0` 使用 16 次 policy 请求，执行 16 次搜索、2 次打开及后续状态操作，约 388 秒后提交并判对。另有 4 项未执行调用来自不兼容的 focus 组合。部分远程响应约 49–54 秒，对应本地检索约 0.7–0.8 秒。

这局检验了接近预算边界时的成功提交，但没有体现少调用或快速完成的优势。所有搜索逐项计入后端成本，不因为多调用出现在同一响应中就少算。

### q785 E-soft：合法状态更新没有填写 answer，最终审核耗尽剩余预算

运行 `20260910T061605030633Z_development_E-soft_785_0` 是本阶段停止点，耗时 171.2 秒，共 14 次 policy、2 次 audit、11 次检索后端请求。

关键顺序：

1. `a5`、`a11`、`a14` 的局部状态更新均成功。finding 中包含候选结论，`answer` 始终为 `null`；不能把它描述为更新失败导致答案丢失。
2. `d54` 的 update＋search、`d88` 的 search＋verify 违反已声明的工具组合规则，4 项调用全部明确标记未执行。它们消耗两次策略请求，程序没有静默执行其中一项。
3. `d122/a15` 发起审核。首次响应的 claim.reason 为 **1,276 字符**，实际发送的 schema 上限是 **1,200**，因此触发唯一一次协议修复。
4. 修复响应的顶层只有 `claims`，其值是字符串；`coverage` 和 `target` 被嵌在字符串里，没有作为字段返回。harness 保存原始响应并返回 `audit_protocol_error`。
5. policy＋audit 共用的 16 次请求已用完，新策略请求在发送前被阻断，终态为 `request_budget_exhausted`。没有第 17 次远程调用，也没有正式答案。

本局 `evaluation.json` 按“未提交计为未答对”记录 `correct=false`，judge 请求为 0。未经新的独立诊断，不能把 finding 内的候选当成正确提交，也不能断言扩到 17 次请求就一定成功。

这是预先登记的扩批停止条件，和服务方每天 1,000 次的额度不同。本次没有遇到服务端每日配额错误。暂停后没有重跑失败题、增加单局上限或执行第二批剩余题目。

## 4. 记账、交付与完整性检查

本次新增 **91 次远程请求：75 policy＋8 audit＋8 judge**。在线部分 83 次；全部输入合计 411,328 token，输出 32,416 token，其中报告的缓存读取为 30,464 token。没有传输重试或新增未知用量。没有可靠价目表，因此不报告货币费用，也不把响应中的零 cost 字段当作免费证明。Codex 研发对话用量不属于这份远程 API 账本。

10 局共执行 90 个动作、62 次实际检索后端请求。75 份原生策略决策包含 102 项调用，保存 102 项回执，其中 12 项未执行、3 项已执行动作返回错误，共 15 项错误；涉及 27 份多调用响应。错误没有被隐藏在合并后的动作计数中。

所有已发送策略请求的调用配对与正文检查通过：108 次历史配对检查、27 次正文交付检查无缺失；83 份在线响应为 HTTP 200。最终因预算停止、没有下一轮策略请求的错误回执仍保存在日志，不将其声称为已经被模型接收。

只读账目核查：全历史 1,180 次请求，1,176 份已结算回执和 286 份导出核对通过，无用量不一致或缺失导出。四笔旧未知用量继续占用预算；一份历史计数探针使用独立记录，不在 episode ledger 内。历史 442 份 schema 受影响请求保留标记，本次没有新增 schema 污染。

额度分别记录：

- **本次正式实验实际新增：91 次。** 第一批登记最多 153 次，实际 75 次；第二批登记最多 153 次，在使用 16 次后按规则暂停。
- **研究累计：1,089 → 1,180 次。** 这是跨日期累计，不能当作今天已用 1,180 次。
- **本地控制：**阶段检查点经登记从 1,137 推进至 1,242，再到 1,317；现剩余 137 次。研究总上限保持 1,403，剩余 223 次，没有重置历史计数。
- **服务方每日额度：**用户说明第二天恢复为 1,000 次；这不是网关返回的剩余量。本地单局请求耗尽不代表服务方每日额度耗尽。

## 5. 尚未完成与下一项研究判断

已验证的改进是原生调用、回执、证据交付及真实记账能够支持这些自然 rollout。实际研究效率仍受 focus 组合限制、pending 管理、候选答案填写、持续检索和审核协议负担影响。

下一项最小可检验问题是：能否减少“已有局部结论却未填写 answer／未处理 pending／提前审核”引起的额外决策，同时保留合法证据约束。应先用本次失败前缀做离线诊断，再决定是否登记新的单一机制实验；不能把自动从 finding 提取答案、取消引用检查或放宽判分当成现版本成功。

本轮没有开始新的机制修改，也没有因首批成本差而挑换样本。九题完整开发比较、可靠难度分层、最终候选选择、冻结和一次性确认仍未完成。当前结论是：**接口执行和记录能够运行，首批 ESR 效果未达目标，整体研究尚无充分证据证明优势。**
