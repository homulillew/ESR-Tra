# 题目要求审核：开发实验与预登记

本轮从 `9328b3e8aac9e8697cfbc4683d4565b4b2a5ea50` 开始，分支 `research/strong-api-esr-20260909`，初始工作区干净。开始时累计请求 1,356/2,000，剩余 644；13 次历史未知用量继续保守占账。当前模型为 EB-GLM-5.2，上一阶段实际响应为 glm-5.2。确认集保持封存。本文首先记录实验前假设，结果另行追加并注明阶段。

## 当前可确认的失败

1. 策略遗漏答案要求：上一阶段 q790 E-off/E-soft 的 update_state 原始输入均未包含题目要求的字面字符；这些要求已在原题和工作卡中交付。直接失败是答案格式未满足。根因可能是模型忽略要求，不能据此认定当前状态无法表达要求。这是一个题目的两局，不能当作两个独立案例。
2. 审核错误支持：同题 E-soft 的 verify_answer 收到原题、候选和原文，仍返回 supported。其后更新仅改 focus/备注，没有修正答案。审核覆盖不足与反馈未触发有效修复需要分开测量。原始目录为 `20260910T083544753928Z_known-regression_E-soft_790_0`，完整轨迹在私有研究目录。
3. 确定性字面字符丢失：当前源码 state.apply_delta 与 engine._finish 对答案使用 strip，改变策略提交的首尾空白，也让仅改变这些字符的答案沿用旧审核。独立合成回归修复前 3 failed/2 passed，修复后 5 passed。提交 `373ba0a` 同时修复 baseline/ESR；空白答案仍非法，原文不变，旧账本只读重放不改写。此问题不是上述 q790 缺引号的原因。

更早 q785/q301 的混合调用拒绝已有确定性前缀重放和真实 GLM 工具回执覆盖，本轮复用顺序执行实现。旧模型的检索失败、审核 schema 失败和 pending 阻塞只作历史诊断，不伪称已在当前 GLM 独立复现。

## 本轮唯一研究机制

Hypothesis：现有 target/coverage 足以承载要求，但审核没有明确先将原题义务应用到实际 answer。仅改变审核检查顺序及两个现有字段的职责，能减少事实证据充分但实际答案不满足要求的错误支持。

Mechanism：增加可选择的 task_first 审核提示，原子审核 atomic 保持原样作为控制。审核先检查实际答案的目标和全部明确要求，再检查各 claim 的原文支持；原题始终具有约束力。两个提示使用相同 schema、同一原文包、同一模型及预算。报告的 target/coverage.need 表达具体未满足要求。harness 不自动提取或添加 requirement，不改 verdict，不补答案。

Expected benefit：降低错误支持，产生策略能落实的局部修正要求。Expected downside：提示增加输入 token，可能过度拒绝、增加复核循环，或检测正确但策略不修复。

Observable prediction：固定审核包中，新提示能识别旧提示遗漏的要求，同时保留合规正例；自然运行中，审核指出问题后出现对应答案或事实解释的有效变化，最终正式判分改善。

Falsification condition：没有可区分的检测改善；正例误拒增加；自然运行只有更多拒绝或工具成本而无正确修复；完整开发集效果不改善。按照结果作 keep/remove/inconclusive，不以 supported 比例代替准确率。

不新增状态字段的理由：原题、target、requirement、answer 已保留相应信息。尚无两个独立真实题证明必须增加 requirement manifest、依赖图或另一个在线模型。当前额外负担只在审核提示，策略状态和工具不变；弱模型是否受益仍需独立验证。

## 固定实验边界

先运行全库测试（改动前 329 passed）。新增测试覆盖答案字面保留、旧审核失效、持久化重放、原题/原文包不变、正负模型 verdict 原样保存、schema 不变和协议修复上限。

机制测试使用六类独立自造约束：字面引号、单位、顺序、数量、请求对象、时间范围。每类合规/违规候选各一份，两种审核提示各调用一次，共 24 份审核包，每份最多 2 次真实请求（含传输及协议修复），上限 48。另在 q790 已交付审核包上比较两种提示，各最多 2 次请求，上限 4。固定包测试没有搜索或新答案生成，只验证审核机制，不能当作 BC+ 自然答题成功。

通过条件：无基础设施/交付问题；新提示接受全部六个合规正例，检测至少五个违规例；至少一个相同包相对旧提示获得检测改善，或原始 q790 包被新提示正确指出缺少的要求。若没有机制信号，记录无收益并停止扩大此提示的实验。

通过后固定开发题全部运行：149、790、26、785、301、1012、701、1044、718。每题三条件：E-off、E-soft/atomic、E-soft/task_first，按题交错轮换顺序。每局最多 16 次在线请求、24,000 输出 token、64 动作、900 秒；每个正式答案最多 1 次原判分模板请求，27 局上限 459 次。三条件仅 auditor.profile 不同（E-off 无审核），其它配置、源码、索引一致。当前 CPU SQLite BM25 检索器不需要显卡。

用户此前暂停 baseline 重跑的要求继续生效，因此本轮不运行 B，不使用旧模型 B 合成新对照，也不作新的 ESR-vs-B 性能声明。E-soft 两种提示的对照用于归因审核变化；E-off 用于衡量新增审核的实际成本。整组上限 511 次请求，仍在剩余 644 内。检查点按阶段登记，未知用量和失败请求不删除。后续第二机制只在两个独立案例或确定性 bug 支持且剩余额度足够完整对照时启动，最多再一个；不承诺耗尽预算。

服务未恢复、实际模型名改变、交付/账目失败时停止批跑。正常单题预算耗尽是任务失败，保留并继续固定样本；重复协议崩溃先停止诊断。旧实验不覆盖，不按结果补采样。所有计划、原始请求/响应、状态、审核、判分和逐题归因留在私有 runs。

## 第一轮实测与第二轮预登记

第一轮版本 `4c931af`，实际新增 28 次审核请求，累计 1,384/2,000。12 个合成包各比较两种提示：task_first 接受全部六个合规例、拒绝全部六个违规例；atomic 在引号、单位和请求对象三个违规例中错误支持，顺序例正确拒绝，数量与时间例因 need/status 不一致各用两次请求后仍未形成有效报告。所有传输和用量已知，原始失败保留。

原始 q790 审核包中，两种提示均错误支持。task_first 的 coverage.reason 明确声称实际答案包含要求的引号，而解码后的 answer 字段并无这些字符。这说明短合成题上的改善没有修复这份长证据真实包，不能据此推广。原控制器同时要求所有报告均有效，因 atomic 两份协议失败记录 `packet_gate_not_met`，完整开发批次没有启动。这个停止结果不改写，也不重采旧失败。

**第一轮决定：不推广，真实问题仍未修复。** 保留 task_first 作为下一轮固定控制，其输入与提示不变。已核查的协议失败属于模型输出的 status/need 不一致，harness 按契约拒绝，没有借此放宽验证。

第二轮 Hypothesis：长证据包中，审核者把 JSON 字符串的语法引号当作答案字符。仅将候选答案从 JSON 中取出，用明确边界单独原样展示，能纠正这种误读；无需 requirement manifest 或新的在线核验器。

Mechanism：task_first_literal 与 task_first 使用同一审核规则、schema、原题、claims 和全部原文，唯一区别是答案展示方式。答案原文放在不与内容碰撞的 BEGIN/END 标记之间，JSON 中不再重复 answer。不增删实际答案字符；null 单独表示无候选。标记和 JSON 转换由 harness 机械维护，没有由模型填写的新字段，没有 qid 分支、参考答案或自动字符修复。新增提示只解释这项表示。

Expected benefit：减少候选字符与序列化符号混淆；Expected downside：额外边界说明、混合文本/JSON 输入可能仍被误读。Observable prediction：同样六类合成正负例保持全对，原始 q790 包明确指出缺少引号。Falsification condition：任一合规例误拒、协议/交付失败，或原始包仍未识别该要求，则不扩大此机制；连续两种最小机制未修复真实问题后停止继续加模块。

第二轮先只给新表示运行全部 12 个固定合成包及 1 个原始审核包，各最多两次请求，上限 26；上一轮 task_first 结果保留为已冻结固定包控制，不重采样。通过必须六正例接受、六负例识别、原始包报告明确指出遗漏的引号且新报告全部有效。通过后同一当前源码下完整跑九题三条件：E-off、E-soft/task_first、E-soft/task_first_literal，比较的唯一在线差异是审核 profile。该自然对照用于归因答案表示；不得称为对 atomic 或 B 的自然性能提升。仍各局 16 次在线加最多一次原 judge，上限 459，总计最多新增 485，未超剩余 616。

各题一次自然运行，轮换条件顺序；暂停 baseline、不打开确认集、不覆盖第一轮。若第二轮没有通过机制门槛，不为完成批次数而运行已证实仍错误的候选，也不缩减样本后宣称成功。

## 第二轮实测、机制结论及最终代码

第二轮在线版本 `d28b437`，新增 14 次审核请求。全部六个合规和六个违规合成例均在一次请求内得到正确有效报告。但原始 q790 包先后两次返回相同矛盾：coverage=contradicted，明确指出遗漏要求；target=supported，却仍填写要求修复的 need。当前契约要求 supported 的 need 为空，因此两次均被拒绝，未生成有效审核。模型看见了完整原题、相同证据及单独展示的原答案；harness 没有替模型清空字段或修改结论。

| 固定审核输入 | atomic（第一轮） | task_first（第一轮） | task_first_literal（第二轮） |
| --- | --- | --- | --- |
| 六个合规合成例 | 6/6 正确支持 | 6/6 正确支持 | 6/6 正确支持 |
| 违规：引号、单位、请求对象 | 三例均错误支持 | 三例均正确拒绝 | 三例均正确拒绝 |
| 违规：顺序 | 正确拒绝 | 正确拒绝 | 正确拒绝 |
| 违规：数量、时间 | 两例报告协议失败，各消耗两次请求 | 两例均正确拒绝 | 两例均正确拒绝 |
| 原始 q790 审核包 | 错误支持 | 错误支持，并错误声称要求已满足 | 识别遗漏，但报告矛盾；两次请求后仍无有效报告 |

这不是三组自然答题准确率。每列对固定候选进行审核，没有重新搜索、生成答案或执行 policy 修复；真实包来自一个已研究题目，不能当独立泛化样本。第二轮复用第一轮 task_first 的固定包控制，没有重新抽取对照响应，时间与采样差异仍是限制。

逐例分析显示三个不同阶段：

1. **理解要求**：原题信息已存在，新增字段不是必要条件。直接检查答案能改善简单独立约束的判断，但长证据包仍会把序列化引号当作答案字符。这是有原始报告支撑的错误解释，尚不能推论所有任务都是同一根因。
2. **形成可用报告**：答案单独展示后识别出了具体缺失，但仍无法使多个 status/need 字段一致。原子审核在另外两个独立合成例也出现相同类问题。当前“语义判断正确”与“能通过报告契约”是两个瓶颈。
3. **实际修复**：两轮都未通过预先登记的扩批门槛，因此没有把不合格报告交给自然 policy 继续运行。检测后的有效状态修改、修复成功率、损害率和任务准确率均未测量；不能将它们记作已改善，也不能用无效报告的理由替代模型动作。

**工程修复决定 Keep：** 答案首尾字符原样保存及字符变化使旧审核失效，有确定性失败/通过与持久化重放证据，保留 `373ba0a` 的修复和五项回归。

**第一轮研究决定 Remove；第二轮效果决定 Inconclusive，部署决定 Remove。** 第一轮对真实包仍错误支持；第二轮有一次可解释的检测改善，但两次均无有效报告，没有前向修复收益。最终从当前运行代码移除这两种可选审核 profile 和相关实验专属测试，恢复原审核及默认配置。合成材料、研究记录和实验提交 `4c931af`/`d28b437` 保留，便于在确切版本复查；不因已投入实现工作而增加默认系统负担。

触发停止条件：连续两种合理的最小干预均未通过真实包的完整机制门槛。没有发起第三轮提示试错，没有放宽 status/need 验证，没有重跑失败直到成功。固定开发九题的 27 条自然对照清单完整保留为未运行；没有把缺失条目当零成本成功、没有替换为合成准确率。没有选择最终 ESR 版本或打开确认集，目标未达成。
