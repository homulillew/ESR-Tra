## 1. 方法、版本和冻结条件

ESR（Evidence-State Research，保存原始证据并维护当前结论和待解决问题的方法）由本地 harness 执行工具、证据与状态规则。远程 API 负责策略选择和语义审核；Codex 负责代码检查、调度和离线分析。B 是保留完整交互历史的普通搜索策略；E-off 使用 ESR 状态但关闭审核；E-soft 使用同模型、独立上下文的审核。

|---|---:|---:|---:|---:|---:|---:|

正式实验共 **233 次请求：201 policy＋18 audit＋14 judge**。在线 219 次，判分 14 次单独计费；另有 1 次恢复联通检查，不计入算法在线成本。每个实际 HTTP 尝试计一次请求，多工具输出不会合并后端计数；一局研究和本聊天中的一轮消息都不等于一次 API 请求。

在线实测输入 1,313,243、输出 78,215 token；加上五笔未知请求的保守占用后，分别为 **1,459,926、98,695 token**。正式实验含 judge 的已知用量为输入 1,318,913、输出 79,036 token，其中缓存读取 272,128 token。恢复探针另计输入 915、输出 45。provider 成功回执中的 reasoning_tokens 为 0；这不能证明其内部没有未公开推理开销。没有可靠价目表，不虚构货币成本。

单局记录的计时合计 3,562.7 秒：policy 2,728.6 秒、audit 311.6 秒、检索 424.0 秒、其余未细分 98.5 秒。`elapsed_seconds` 从 `episode()` 内部计时点到运行结果生成，外层输入/索引预检及批间审查、冷却不在此计时内；不将它声称为覆盖全部外层处理的完整端到端测量。完整起止时间和原始分项保留在进度、manifest 和 ledger 中。

执行的工具分类：B 为 72 search、14 open、6 finish；E-off 为 45 search、17 open、9 update、5 submit；E-soft 为 63 search、14 open、13 update、11 verify、4 read、4 submit。open 读取缓存时不新增后端请求，因此动作数与后端数不同。

196 份成功原生策略响应含 301 项调用，保存 301 项回执；105 份响应包含多项调用。24 项调用明确未执行，其中 18 项 `batch_focus_conflict`、6 项 `serial_action_required`；另有 8 个执行动作返回错误。全部计为 32 项错误，没有静默丢弃后续工具。657 次已发送历史调用配对检查和 60 次正文交付检查均通过；停止后未再发送的回执只称已保存，不称已被模型接收。

最终账目核查覆盖 1,323 笔研究请求、1,314 份已知用量回执、324 份导出，没有账目不一致或缺失导出。九笔未知用量包括四笔旧记录和五笔本次正式实验记录，全部继续占账。历史 442 份受影响的 schema 请求保留标记，新正式运行没有新增污染。

## 5. 恢复规则与实际停止原因

续跑前检查了原先单局 16 次请求停止点，将已结束的预算失败保留为未答对，继续下一条固定任务。出现重复审核协议错误时暂停，用原始响应和实际请求 schema 做离线重放；确认是被测审核输出不符合契约后，仅允许后续独立题目继续。harness 的局内停止、错误上限、评分和源码没有改变。

服务先出现一笔 502 和一笔可恢复的 429，分别在预设第二次尝试成功；未知费用继续占账。q701 E-off 两次 429 均失败后暂停批跑。完成只读核查并冷却超过两分钟，仅登记了一次、无重试的联通检查，返回 HTTP 200、`API_OK` 和预期模型标识。此后仅继续未运行题目。

最终 q1044 E-soft 的 `792ef34bab6548869c0cf0db6e2f27bc` 请求读取超时，未收到响应，也没有后续成功请求；已经达到单局上限，没有发第 17 次。唯一联通检查已使用，本轮停止新请求。已知缺失项是该请求的服务端结果/实际用量，以及能稳定完成完整请求的 Lanz-Medium 路由。现有证据没有显示每日 1,000 次额度耗尽；不能把本地累计额度或 429 满载当作服务方今日余额。

所有恢复计划、暂停文件和中间汇总都以独立文件保存。恢复只改变局与局之间何时继续，没有延长失败局、替换失败题或挑选一次成功运行。

## 6. 尚未完成与下一项最小检验

未运行顺序明确保留：**q1044 E-off、q1044 B、q718 B、q718 E-off、q718 E-soft**。首轮补齐之后，原规范还要求 B 与候选完成 18 局第二遍开发复验，再冻结并运行 54 局确认及判分。现有 80 次请求无法按原单局额度为这些阶段预留完整预算；五局首轮本身的最坏请求数为 85。不能缩减样本、重复数或判分来宣称完成。

本轮结论为：**接口执行与记录可靠性得到实测支持，但 ESR 效果未达目标；完整九题及确认集证据不足，不能作最终统计判断。** 没有继续增加主要机制，四轮既有机制预算不扩张。

下一项最小可证伪的检验是：在固定前缀中，对比现有反馈与一条明确的提交前置条件提示。现有上下文已经包含 answer、pending 和预算字段；待检验的是将这些分散信息转为具体缺失步骤，是否减少最后一次请求才写答案、尚无答案就反复审核的行为。先使用合成状态和本次固定失败前缀做离线检查，不提供候选答案、不代替策略提交，再另行登记单机制对照。预测是减少这些特定失败和额外决策；若不能在完整固定开发集改善正确提交与总模型成本，应拒绝该机制。此建议未实现、未获得效果验证，不作为本轮成果。

检索停滞需要独立检验，不能与状态卡修改同时引入。相关一手研究与采用/拒绝记录见 [RESEARCH_NOTES.md](RESEARCH_NOTES.md)，已用机制及停止边界见 [DECISIONS.md](DECISIONS.md)。这些材料仅供离线研发，不进入被测模型。
