# 有界原生工具组合：实现与验收

日期：2026-09-10。用户在工具执行分析后授权继续实现。该改动修复各实验臂共用的工具执行协议，不重置此前机制迭代次数，不修改问题、检索器、审核标准或 judge。历史实现与失败记录保留。

## 实现范围

`max_tool_calls_per_decision: 4` 为当前研究配置启用 `native-retrieval-turn-1`。库的默认值仍为 1，以保持旧账本可读；新实验的不可变 header、adapter identity、compiler version、提示版本后缀及 manifest 均标识新路径。该配置同时传入 policy adapter 与 harness，不一致会拒绝启动。审核输出始终保持单报告。

`NativeTurn` 保存 provider request ID、完整 content 块、调用 ID、顺序、原始参数及本轮提供的工具名。同一模型响应中的多项独立检索顺序执行，每个实际动作有独立 action ID，并关联 decision ID、调用序号与原生调用 ID。

允许至多四项 search/open_page/read_evidence；需要已有 ID、明确搜索来源以及一致的有效 focus。批次入口固定 open 的搜索父节点，禁止引用尚未返回的搜索命中或新 observation。多项中包含状态更新、审核或结束时，整组逐项返回未执行原因；单项状态动作沿用原语义和辅助 note 警告路径。

部分参数不合法时，独立合法检索可以执行，非法项收到明确回执。超过组大小、整组动作余量、pending 容量或初始上下文预留时不执行前缀。重复或缺失 provider ID 无法形成合法原生配对，因此保存全部原提案并记录一次协议错误，不伪造 ID、不执行工具。

## 结果与证据交付

新日志事件记录原生决策、调用开始、未执行/未知回执及整组完成。实际成功/失败的工具事件直接构成该项结果，避免“工具已落盘、回执尚未落盘”造成重做。

待交付结果独立于 ESR pending：已引用证据重读不增加状态清理义务，但整组正文都保护到下一次 provider 请求。只有记录收到响应后才标记交付；超时保留 unknown。交付不表示模型已经理解证据。

两臂使用相同的 assistant `tool_use` 与 user `tool_result` 编码。baseline 按完整组保留历史，ESR 使用工作卡与未交付组。正文出现在对应原生结果中时，不在同一工作卡重复正文。模型返回的其他 content 块保留原样；不从思考或散文猜测额外动作。

检索结果沿用已有 compact result 的显式缩短标记：每项保留全部命中 ID，标题最多 200 字符、导航摘要最多 300 字符；原始完整结果保留在账本中。两臂一致，提示说明摘要缩短，正文仍通过 open/read 获取。此变化必须计入共同工具协议，不能把新 baseline 与旧版直接拼接。

上下文接纳检查覆盖实际编码后的整组消息。未知返回先为每项预留 8192 字节占位，并在每次真实结果产生后进行累计检查；它是容量估计，不是对任意后端输出的硬上界。已有窗口缩小和显式容量失败路径仍适用。执行后无法接纳的结果保留为 `unadmitted_output` 或检索原始记录，不冒充已交付证据；已发生的后端费用不回滚。pending 预留采用保守上界，可能拒绝实际上可复用视图的组，可要求更小组合。

## 恢复与成本

每项调用前落盘 started。若程序中断，已提交结果保留，started 但无结果的项标记 unknown，其余项标记未执行；恢复结束为 service_error，不自动重做整组。若中断发生在 provider 请求/响应之后、原生决策提交之前，也保留原始记录并停止，不再次采样同一决策。相同 decision ID 禁止再次执行。

错误停止的单位在新协议中明确为“包含错误的策略决策”：6 次累计或 3 次连续错误决策停止，审核协议错误仍受 2 次限制。同时保留逐项失败数量，防止一组多个失败被隐藏。工具动作数只统计实际交给 engine 的尝试；未执行项、结果未知项、全部提议数和回执数另列。实际 HTTP 模型请求和检索后端 I/O 的旧记账保持独立。

summary 新增 `native_tools`（模型决策、提议、回执、未执行、未知、失败和错误决策），`invalid_actions` 包括未执行的非法提议，`invalid_executed_actions` 保留实际动作中的错误数。不同版本的错误计数不可无说明合并。

`verify_answer` 的当前可调用性在新配置中与提供的工具一致：空状态、pending 或已有当前审核时不再显示 ready。保留程序直接读取审核缓存的能力。

## 离线验收

新增 `tests/harness_v21/test_native_tool_turns.py`，覆盖双检索、两臂双重读正文进入实际 provider body、合法/非法混合、缺失/重复 ID、超限、混合状态动作、前向引用、搜索父节点、动作/pending/上下文边界、部分失败、未知结果、中断恢复、旧账本 replay、原生往返、真实请求用量计数和错误停止。

首次定向运行 15 项通过，5 项因 Windows 默认 pytest 临时目录访问失败而未执行；改用研究目录下唯一的 `--basetemp`，未修改系统权限。之后 20 项定向测试通过，完整回归 254 项通过；增加恢复和边界覆盖后完整回归 259 项通过。每次进一步改动后的回归记录保存在私有研究目录，旧记录不覆盖。

可复现命令（仓库根目录）：

```powershell
$testStamp = Get-Date -Format yyyyMMddTHHmmssfff
python -m pytest -q --basetemp "runs/native-tests-$testStamp"
```

归档脚本和旧 `esr_grpo` 路径不重写；当前生产研究入口使用 `esr_harness`。此前缺陷复现脚本保留对历史机制和默认单动作工作卡的检查，新组合的修复由上述回归测试验证。

## 真实验收的预登记边界

开始前全历史模型请求 1065，总上限 1403，当前检查点 1137，剩余 72；未知历史用量 4 笔继续占用。计划只运行现有合成 fixture 一次，以及原开发集首题 B/E-off/E-soft 各一次，不换题、不重采样；先要求 fixture 完成真实 policy、工具、局部更新和 fresh-context audit。

为减少消耗，本阶段私有配置将共同每局模型请求上限从 32 降到 16，其余原预算保持；4 个 episode 最多 64 请求，正式已提交答案最多 3 个 judge 请求，总计最多 67。所有请求仍经过原全局账本和检查点。任一阶段出现系统性错误即停止后续批跑，保留失败。该小检查用于验证新协议可用性，不构成完整开发集对照，也不打开确认集。
