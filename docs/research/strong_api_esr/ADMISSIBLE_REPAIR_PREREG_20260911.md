# 审核修复可选规则实验登记（2026-09-11）

用户要求继续研究后，开启一轮独立登记。起点 `f02e225`，累计请求 1,404/2,000，149 个已登记单位；确认集保留 54 个，非确认阶段上限 186，尚有 37 个名额。上一轮字段反馈的失败和门槛不改写。

## 假设与机制

**观察：** 数量和时间范围两个独立合成前缀，以及真实题 790 的历史审核，都出现 status/need 冲突。上一轮精确字段位置仅部分有效。当前提示把 unknown 和 contradicted 的 need 都称为“缺失关系”，而明确反例下未必还缺证据。模型可能因此保留空 need；这是待检验的解释，不当作已证明的心理机制。

**假设：** 在发生状态与 need 冲突时，说明每种状态适用的条件及相应 need 要求，比只返回错误位置和规则更有助于一次修复。尤其明确 contradicted 的 need 应描述违反的要求或必要改正，即使无需增加证据也要填写。

**机制：** 新增 `repair_feedback=admissible` 实验选项，仅在已有 `AuditConsistencyError` 的修复消息中，在 `field_paths` 原文后附三种合法状态/need 组合及选择条件。三个状态一并提供，不替模型选状态，不生成具体修正答案，不自动填写 need，不修改 schema、接受规则、引用规则、初始提示或修复次数。原题、错误报告与证据始终保留。

**预计收益与代价：** 减少已有审核语义结果因跨字段冲突而被丢弃的情况；每次触发多用少量输入 token。可能仍无效果，也可能诱使模型改判以满足结构，需要分开测合法率、整体否定、具体缺失及错误放行。

**证伪：** 两个同步固定前缀候选没有全部形成合法否定报告、没有任何一个优于 field_paths 对照，或后续正例/真实包/完整合成策略校验失败，则不启动自然开发批次。不能通过放松报告接受规则、自动补字段或继续重采样来通过。

## 文献依据与边界

[Structured Feedback Improves Repair in an LLM Agent Loop](https://arxiv.org/html/2607.14167v1)（2026-07-15），原文第 2–6 节：其 TextWorld 消融表明提供可选修复动作比只有位置和值更有效，相同信息的自然语言与 JSON 表现接近。本轮只借鉴“说明已知的合法替代方式”；校验器仅能确定结构规则，不能像 TextWorld 那样提供语义上正确的动作列表。它不能决定题目答案或正确的审核状态。该文第一轮带有策略名称、使用转录词数计费代理，并替换过一条服务错误记录；本轮不采用这些做法，固定前缀实际 body 逐字段比较、使用实际 usage、保留全部失败。

[When JSON Is Not Enough](https://arxiv.org/html/2607.18261v1) 将结构合规与任务语义分别评测，提醒本轮合法报告也可能带错判。已有 [字段反馈报告](FIELD_FEEDBACK_RESEARCH_20260911.md) 的数量例同样显示这一边界。

可选规则属于常见修复接口设计，不作为新的算法创新；没有新增状态图、模型、训练、检索器或运行时题目特例。

## 固定调度与预算

全程 EB-GLM-5.2，预期实际响应 glm-5.2；temperature=0.6，单请求最多 4096 输出 token；保持一次协议修复。使用现有完整 BC+ CPU 索引和固定九题。新请求上限 **479**，新单位上限 **36**，都在当前余额内，按阶段提高检查点，不增加总上限。

1. 数量、时间两个历史**初始错误**前缀，field_paths 与 admissible 各一次真实修复。数量先对照，时间先候选。共 4 个单位、4 次请求，初始错误不重新生成。保持各自历史 atomic 输入；每对只允许最后修复消息不同。通过条件：候选两例均合法且整体 unknown/contradicted，并至少一例优于同步对照。局部 target/coverage 错判另记，不将整体否定当作所有字段正确。
2. 通过后，新审核三个固定合成正例：count-positive、time-positive、quoting-positive，以及不变的 790 历史 packet。均用 task_first_literal/admissible，各最多 2 次真实请求。要求三个正例 supported，790 合法且在 target 或 coverage 的 need 中指出引号缺失。随后运行一次完整 Orin 合成策略 episode（最多 8 次请求），要求合法提交、真实答案满足已给定的合成来源和引号要求、回执完整、无审核协议错误。共 5 个单位、最多 16 次请求。这些只用于机制门槛，不计 BC+ 准确率。
3. 通过后，九题 149、790、26、785、301、1012、701、1044、718，各运行 E-off、E-soft/literal/field_paths、E-soft/literal/admissible 一次。每题三条件按题序循环轮换，共 27 局，每局至多 16 次在线请求；在线全部结束后，每个正式答案至多一次独立判分，共至多 459 次请求。所有条件的普通策略、工具、状态、检索器、题目、预算相同。

用户暂停 baseline 的要求继续生效；E-off 是 ESR 内部消融，不能当成无 ESR baseline，不能产生新的 ESR-vs-B 性能结论。确认集保持封存。九题均为已有反复使用的开发题，难度标签仍为 provisional medium。

## 停止与分析

用量缺失、实际模型变化、基础设施错误或请求/回执异常停止新在线调用。开发集中保留对照失败；候选连续两局审核协议失败则停止余下调度。局内预算耗尽按失败计，不扩局。判分只在在线阶段结束后，参考答案不回流。未完成调度逐项报告。

统一分析正式提交正确率、真实 policy/audit/repair/judge 请求、输入输出 token、检索后端次数、成功与失败耗时、审核是否交给策略、审核后答案是否变化、错误修复和误改。固定前缀成功不等于自然策略修复成功。

本轮先完成这一项机制。若进入完整开发集，剩余单位不足以再做同规模公平比较，则如实停止，不自动扩 episode 上限。代码通过测试后冻结，整个已登记批次中不修改。保留全部原始记录并给出 keep / remove / inconclusive 决定。
