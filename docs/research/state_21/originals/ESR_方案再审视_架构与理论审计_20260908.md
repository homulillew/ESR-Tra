# ESR 方案再审视：从可回放 Harness 到可学习的证据状态

**日期：2026-09-08**  
**对象：ESR-Tra；以 4B 搜索 agent 为最终目标**  
**审阅快照：`6ee9c4a264cd80a50d8a15511c8ed80b39c763b6`**  
**范围：只读架构与理论审阅，不运行模型实验、不修改或推送仓库。**

## 执行结论

建议保留 ESR 的证据账本、实际视图、状态版本、审核指纹和统一运行入口，但不再把“审核全通过”和“最终被引用”直接当作学习正确性的保证。下一版最值得收敛为：

> 一个 4B policy，研究与审核两种角色；一个可恢复但有界的证据工作状态；一套与推理完全同源的上下文渲染；一个以最终结果为锚的训练目标。

当前 v2 已显著改善工程可检查性，但仍存在三个不同层次的缺口：

1. **上下文缺口：**完整 observation 目录随轨迹增长；核心 state 保存 requirement 和 ID，却缺少稳定的事实绑定；只删除 recent history 不能保证核心状态始终可装入上下文。
2. **审核缺口：**逐条件审核不自动保证跨条件实体一致性；selected-evidence support 不等于已知证据整体无反证；soft 模式仍强制先获得有效审核，因此仍可能被审核的服务或预算问题阻塞。
3. **学习缺口：**旧 positive-only provenance mask 与 v2 尚未接通；同一可训练模型生成审核时，审核输出必须纳入策略的随机计算过程；对 advantage 做有界正权重并不保证原目标梯度方向不变。

更合适的顺序不是继续增加模块，而是先把这些边界写成规范。理论上可以证明的是前缀因果性、上下文预算、回放一致性、某些梯度估计恒等式；不能仅凭结构化状态、quote 检查或权重有界，证明 4B 的任务正确率一定上升。

## 1. 当前实现：保留什么，重新界定什么

本次读取了当前 [DESIGN](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/docs/harness/DESIGN.md)、[engine](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/engine.py)、[runner](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/runner.py)、[audit](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/audit.py)、[protocol](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/protocol.py)、[client](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/client.py) 与 [旧训练接入](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_grpo/integrations/echo.py)。以下代码发现均基于静态审阅，而非新的模型运行结果。

| 当前设计 | 评价 | 应保持的边界 |
|---|---|---|
| 不可变 DocumentSnapshot / ObservationView | 保留，是 ESR 最可靠的基础 | 保存成功、返回给 runner、实际进入模型请求是三个事件 |
| 单一 schema、按模式分发 | 保留 | 语法正确不等于语义正确；未来约束解码须与训练采样一致 |
| no-op 不刷新语义状态、审核 fingerprint | 保留 | fingerprint 只保证同一审核输入的复用，不证明其结论正确 |
| fresh-context audit | 保留 | 独立上下文不等于独立错误；同一模型仍可能共享偏差 |
| 稳定 claim ID | 保留并补充作用域 | ID 必须绑定命题、实体与候选版本，而不只是条件文本 |
| pending 不静默删除 | 保留意图，调整实现 | 不应该允许 pending 累积到模型连修复动作都无法生成 |
| 原文新颖性计数 | 仅作诊断 | 新字符不等于信息增益，也不等于任务进展 |
| 全量账本与只读回放 | 保留 | 可复现不等于可识别因果贡献 |
| hard / soft / off | 明确不同目标 | soft 当前仍依赖审核成功返回；不能视为真正非阻塞 |
| 旧 positive-only + provenance mask | 保留为研究分支 | 暂不作为已经成立的训练理论 |

### 1.1 现在应区分三种“稳定”

**机械稳定：**非法 ID 不会写入状态，证据内容不会漂移，服务异常不会被伪装成缺证，事件可回放。

**决策稳定：**在相同事实与合理预算下，不因无关历史、措辞或审核偶然误拒而持续搜索、遗忘关键桥接实体或过早弃答。

**学习稳定：**训练概率对应实际采样过程；所有角色、上下文重建和终止被正确建模；优势归一化、截断与日志切段不会改变本应相同的样本含义。

单元测试主要覆盖第一层。第二、第三层不能由“100 项测试通过”推出。

## 2. 更清晰的形式化：ESR 是部分可观测决策中的外部工作记忆

令完整历史为

\[
H_t=(Q,a_1,o_1,\ldots,a_{t-1},o_{t-1}),
\]

外部状态为

\[
X_t=(D_t,O_t,W_t,F_t,V_t,B_t),
\]

其中 D 是文档快照，O 是实际观察档案，W 是紧凑工作状态，F 是可恢复的检索候选索引，V 是审核记录，B 是资源状态。它们可以是同一账本的不同派生视图，不要求实现六个独立模块。

模型实际接收

\[
C_t=\mathcal R_\omega(Q,X_t),\qquad a_t\sim\pi_\theta(\cdot\mid C_t),
\]

\(\omega\) 是冻结版本的渲染规则。

### 2.1 可恢复不等于信息充分

把某篇文档保存到 SQLite，只能说明它没有从系统中丢失。如果 prompt 只剩一个无语义的 ID，模型未必知道应该恢复它。

一个完全充分的状态需要保留与未来决策有关的区分；例如两条历史一条确定了桥接人物 X，另一条没有，若压缩后得到相同的工作状态，模型可能无法选择正确的下一次查询。ESR 没有必要声称它构造了精确 Markov 状态。更准确的定位是**可恢复的近似信息状态**。

这不妨碍使用策略梯度：对实际的历史依赖策略，REINFORCE 的 likelihood-ratio 恒等式并不要求展示给模型的字符串已经是精确 Markov 状态。真正需要的是把实际采样过程、模型生成的记忆以及后续上下文都记录正确。

### 2.2 先定义可证明的五项性质

1. **前缀因果性：**第 t 次请求只能由 Q、过去动作／观察和当前预算生成，不能使用未来轨迹、gold、事后审阅者的答案知识。
2. **实际曝光一致性：**任何被称为“模型看过”的证据，都能定位到某次真实请求中的完整文本／区间，而不只定位到一次 tool return。
3. **有界性：**每次请求满足输入 token＋预留输出 token不超过上限，且目录、状态和 pending 分别受到约束。
4. **恢复可达性：**对被归档的证据存在有限、合法、预算透明的重新读取路径；不能因没有写 finding 而无法读原文。
5. **语义与协议分离：**格式、服务、预算错误不改变 supported/unknown/contradicted 的语义记录。

这些性质可做证明或系统验证。至于压缩保留了多少任务信息、审核反馈能否帮助 4B 修复，则仍是经验问题。

## 3. 上下文管理：当前最应该重新设计的部分

### 3.1 全量目录不是有界工作记忆

`engine.context()` 每次遍历所有 observations，渲染 observation_id、docid、spans、view_hash。`runner.messages_for()` 超窗时只缩短 recent_actions，最后在 state＋pending 等核心内容仍放不下时终止。这意味着 prompt 成本随观察数量增长，尚无独立于轨迹长度的目录预算。大量 hash 与偏移对调试有价值，对每轮策略决策却未必有价值。

**建议：全量目录留在外部；模型只看活跃引用、最新结果和有限候选索引。** 旧条目通过同一 read 工具的分页／检索能力恢复，不再把全部档案反复塞回 prompt。优先为已有工具扩展清晰的定位能力，不新建记忆 agent。

### 3.2 requirement 不是 finding，更不是桥接事实

当前 CLAIM 只有 claim_id、requirement、observation_ids。以下两种状态不等价：

```text
c1: 找到 X 赢得的赛事和年份；refs=[o2]
```

```text
c1: X=某人物；赛事=某赛事；X 获胜年份=2010；refs=[o2]
目标年份=2008；待找该赛事该年的赢家。
```

一旦 o2 离开 recent window，前者只保存了任务要求，后者才保存了下一步查询需要的桥接信息。

建议在一个小型 slot 中同时表达：

```text
slot_id
requirement                  # 题目要求什么
binding / finding            # 当前实际提取到什么；允许 tentative
witness_refs                 # 支持或连接该事实的实际视图
counterevidence_refs          # 已知冲突，不默默删掉
```

不要求把所有自然语言解析成实体关系图。只记录会影响下一次搜索、候选选择或终止的绑定。finding 是可修订的导航摘要，不是新的外部证据。

### 3.3 拒绝静默丢证据，不应变成拒绝继续推理

pending 永不裁剪的出发点正确，但若一个合法动作把核心 prompt 推到上限以外，下一次模型连 dismiss 或缩短 state 的机会都没有，这是一种可避免的活性失败。

应采用“上下文准入”而不是“超窗后才终止”：

- 写入 active state 前，验证它与最小修复／结束空间可共存。
- 大页面在生成不可变观察前按真实 tokenizer 切成可读窗口；剩余内容保留可恢复的外部句柄。
- 新请求至少完整展示一次最新显式 read 的返回内容；之后允许移出活动上下文，但保留外部原文和恢复入口。
- 同一原文在 pending、recent result、raw_parts、text 中不要重复渲染。审计日志保留全部结构，policy 视图只展示一次。

不需要把每个字永远留在 prompt，才能承诺“没有不可逆丢失”。

### 3.4 推荐的固定渲染模板

\[
C_t=Q\oplus W_t\oplus B_t\oplus O^{\mathrm{latest}}_t
\oplus E^{\mathrm{active}}_t\oplus H^{\mathrm{recent}}_t.
\]

| 部分 | 内容 | 原则 |
|---|---|---|
| Q | 原始问题与目标关系 | 常驻、不可被摘要覆盖 |
| W | 必要 slots、当前绑定、候选、未解冲突 | 小而有语义；支持增量更新 |
| B | 剩余动作、生成 token、上下文与必要结束预留 | 使有限预算决策可见 |
| Latest observation | 最近明确请求读取的实际视图 | 至少一次完整曝光 |
| Active evidence | 当前最相关的少量证据卡片 | 可定位到原文；确定性去重 |
| Recent interactions | 完整的近期交互单位 | 先淘汰；不复制长旧 state 或 audit |

当证据卡片使用原文子区间时，要把区间及其曝光记录下来。不能把没给模型的全文段落拿来证明模型的行动是 grounded。

### 3.5 预算不能只在客户端里存在

当前 `UsageBudget` 统计 policy＋audit 的 completion tokens，但 `context()` 主要给出 remaining_actions。两个状态可能在模型可见内容上相同，只是一个还剩 12,000 生成 token、另一个只剩 300；它们显然不应采取相同的审核／搜索／结束策略。

建议把真实剩余生成预算传入渲染；`B_repair` / `B_finish` 作为准入时的预留，而不是在结束时自动打捞一个旧候选。外部调用重试成本未知时继续标记 unknown，不能宣称总算力已经精确对齐。输入 token、重试、检索成本也应单独记录，因为只对齐输出 token 并不等于对齐总计算。

## 4. 审核：把“认知反馈”和“结果认证”分开

### 4.1 先决定研究目标

如果目标是固定预算下的 BC+ 最终正确率，可以写为

\[
\max_\theta\;\mathbb E[R_{\mathrm{answer}}]\quad\text{subject to a fixed budget policy}.
\]

如果目标是可信交付，则更接近

\[
\max\;\mathrm{coverage}\quad
\text{subject to }P(\mathrm{error}\mid\mathrm{certified})\leq\delta.
\]

这不是同一个目标。全条件审核门禁可能提高提交精度，也可能降低覆盖、消耗预算；“全部判 supported”本身没有校准出上式的错误概率。

因此建议 ESR 的研究主线使用 advisory review：审核帮助下一步，不自动拥有否决结束的永久权力。hard 认证作为独立运行／研究条件保留，输出标签始终真实。当前仓库默认 hard，本轮未改动。

### 4.2 当前 soft 仍不是非阻塞

`_submit()` 在 soft 下仍要求 `current_audit` 存在。因此审核服务报错、审核输入过长或者剩余生成预算不足，仍可能使一个已经形成候选的 agent 无法结束。

若设计要表达真正的 advisory review，应该允许显式结束为 `unverified`，不伪造 supported，也不自动调用 finish 绕开状态。模式语义的修订必须版本化，不能与历史 soft 结果混报。

### 4.3 必须检查“同一个实体同时满足所有条件”

逻辑上，

\[
(\exists x\;C_1(x))\land(\exists y\;C_2(y))
\]

不推出

\[
\exists z\;[C_1(z)\land C_2(z)].
\]

逐 claim 都能找到一段支持 quotation，仍可能分别支持不同的人、作品或年份。新版 target audit 提供了方向，但 schema 还没有把每条 claim 的命题作用域表达完整。

建议把审核对象定义为绑定后的命题：

\[
p=(\mathrm{slot\_id},\mathrm{candidate\_binding},\mathrm{relation},\mathrm{scope}).
\]

candidate 改变后，相同 requirement 的 supported 是新候选的支持，不一定是旧命题得到修复。当前 resolved_claim_ids 主要比较 requirement 文本与状态转变；未来信用不能直接使用这个事件作为语义因果标签。

### 4.4 quote 是 witness，不是 entailment proof

目前 `validate_report` 能验证 quote 属于被引用的原文，而无法验证该 quote 是否真正蕴含 verdict；target 与 coverage 也主要依赖语义输出。这是合理的工程边界，不能包装成形式证明。

选中证据支持候选，也不等于系统已经见过的全部材料没有反证。当前审核只读 claim refs；新增视图若被 dismiss，旧 fingerprint 仍可能适用。这在“审核指定证据包”语义下不是程序 bug，却不足以支持“已检查所有已知反证”的更强主张。

建议在同一 slot 内保留明确的 counterevidence_refs，并在重新审核时同时展示。未发现反证不等于证明不存在反证；这些字段同样不能替代模型语义能力。

### 4.5 不把一个整题审核拆成很多不可恢复的硬门

若仅作说明，假设每个正确条件的单独审核召回为 0.95，且错误独立，8 个条件全通过的概率为 \(0.95^8\approx0.663\)。这不是对当前模型的测量，现实中的错误也不一定独立；它说明 AND 式多门禁可以放大误拒。

更稳妥的方式是一次批量审核，保留已支持条件，只针对变化的候选／证据重新评估。不要每个 claim 开一个独立 reviewer，更不要不断增加 reviewer 投票。全状态 fingerprint 已经足够作为第一版缓存；细粒度审核缓存只有在明确依赖关系后再考虑。

### 4.6 审核应优化“可修复性”，而不是判词严厉程度

一个有用反馈应指出具体的实体、关系或证据缺口，能够改变下一步行动。判 unknown 的准确率高但从不说明怎样修复，对 4B 仍可能没有帮助。

概念上的审核价值是同一前缀下的干预差：

\[
\Delta V_{\mathrm{review}}(h)
=\mathbb E[R\mid do(\mathrm{review}),h]
-\mathbb E[R\mid do(\mathrm{skip}),h]-\eta c.
\]

这只是目标定义，不建议现在引入新 critic 去估计它。自然发生的 call 与 skip 轨迹即使属于同一问题，也可能在难度和前缀状态上不同，不能把组间成功率差直接称为因果作用。

## 5. 训练归因：先修正理论表述，再挑算法

### 5.1 结果奖励的高方差，不等于结果策略梯度原则错误

对于固定环境、真实 on-policy 采样和动作无关 baseline，

\[
\nabla J(\theta)=\mathbb E\left[(R-b)\sum_t\nabla_\theta\log\pi_\theta(a_t\mid C_t)\right].
\]

单条失败轨迹里的好动作可能收到负权重，这是样本层面的噪声；不能因此断言该估计在期望上必然“错误奖励”或“错误惩罚”。真正的问题是稀疏结果、长时程、模型容量与有限样本下的方差和学习效率。[RLOO 原论文](https://arxiv.org/html/2402.14740v2)给出了简单的 leave-one-out baseline。

\[
A_i^{\mathrm{LOO}}=R_i-\frac{1}{G-1}\sum_{j\neq i}R_j.
\]

在同题独立同分布 rollout、固定环境等条件下，其他 rollout 构成动作无关 baseline。这是理论参照，不意味着加入 PPO clipping、组内 std 和多次离线更新后的整个生产算法仍完全无偏。

### 5.2 positive-only 不能一概判定“不会学失败”

对于非负二元奖励，普通 \(R\nabla\log\pi\) 没有显式负奖励项，也可以是正确的策略梯度估计。选择成功样本做更新并非天然无效。

但旧 ESR 使用的是组中心化后的正部分，再叠加合法提交、审核通过和最终 trace mask。它和纯 \(R\nabla\log\pi\) 不相同，会进一步改变任务权重和 token 覆盖。必须把它视为有意引入的学习偏置，而不是“删除错误梯度后保持正确梯度”的定理。

### 5.3 三种 provenance 不可混淆

| 类型 | 能回答的问题 | 不能直接回答的问题 |
|---|---|---|
| exposure provenance | 哪个请求／动作让哪些文本可见？ | 文本是否被实际理解？ |
| usage provenance | 哪些证据被保留、引用或用于状态更新？ | 它是否必要、是否足以导致成功？ |
| causal contribution | 去掉／替换该动作后成功率怎样改变？ | 不能仅由最终 citation 推出 |

关键反证、失败方向排除和桥接实体检索，可能不出现在最终答案的引用中；挂上多余引用也可能增加形式 trace。因此“最终引用＝全部因果贡献”不成立。

建议使用 provenance 作为高可解释性的贡献代理、数据筛选与复盘依据，不宣称它已经识别了真实因果 credit。

### 5.4 对此前有界加权建议的修正

此前建议过：

\[
w_t=\frac{1+\lambda m_t}{1+\lambda\bar m},\qquad \widetilde A_t=w_tA.
\]

它的平均权重为 1，且在 \(\lambda=1\) 时权重有界。但这**不保证梯度方向不变**。

取一维的两个梯度贡献：

\[
g_1=1,\quad g_2=-0.9,\quad g=0.1.
\]

若 \(m_1=0,m_2=1,\lambda=1\)，则

\[
w_1=2/3,\quad w_2=4/3,
\]

所以

\[
g_w=(2/3)\cdot1+(4/3)\cdot(-0.9)=-0.533\ldots.
\]

平均权重为 1、所有权重为正，更新仍能反向。这是代数反例，不是模型实验。

若 \(|w_t-1|\leq\epsilon\)，可以得到上界

\[
\|g_w-g\|\leq
\epsilon\;\mathbb E\sum_t |A_t|\|\nabla\log\pi_\theta(a_t\mid C_t)\|.
\]

但这个扰动界不保证 \(g_w\) 与真实梯度的夹角，也不保证回报上升。STAMP 的 sign-preserving modulation 同样应按其实际保证解读：advantage 的符号与每项缩放范围得到控制，不是 ESR 成功率的单调改进定理。

### 5.5 最关键的闭合问题：同一个 4B 生成的审核也属于 policy

若研究动作由 \(\pi_\theta\) 生成，审核反馈也由同一 \(\pi_\theta\) 生成，那么审核不是一个与参数无关的外部环境。

可以统一为角色条件策略：

\[
y_t\sim\pi_\theta(\cdot\mid C_t,\mathrm{role}_t),
\quad\mathrm{role}\in\{\mathrm{research},\mathrm{audit}\}.
\]

整个轨迹的 log probability 必须包含两类实际采样输出：

\[
\log P_\theta(\tau)=
\sum_{t\in\mathrm{research}}\log\pi_\theta(y_t\mid C_t)
+\sum_{u\in\mathrm{audit}}\log\pi_\theta(y_u\mid C_u)
+\log P_{\mathrm{fixed\ environment}}.
\]

只训练 verify_answer 调用的 JSON，却不记录／训练真正影响后续状态的审核输出，不能解释为对整个共享模型系统的完整策略梯度。

建议长期采用“一套权重、两种上下文、统一日志与 token 概率”。训练时所有可训练角色都要按被记录的采样分布生成；不能对 greedy 输出使用另一个随机分布的 logprob 然后声称 on-policy。缓存命中是确定性复用，不再次产生审核 token 损失。每条 rollout 内冻结模型和审核配置；跨版本缓存不能无条件复用。

前期若审核暂不训练，应显式使用冻结审核快照，并承认这是阶段性固定环境设计。不能让审核权重不断跟着研究 policy 变，却在学习推导中把它当成恒定工具。

### 5.6 切段与 token 契约比新 credit 公式更基础

每个真实模型调用需要保存：rollout_id、call_id、role、policy_version、实际 prompt_ids、sampled response_ids、old logprobs、采样设置、loss mask、展示的 observation IDs／spans、状态与预算版本。

必须满足：

\[
\mathcal L(\tau)=\sum_{\mathrm{calls}}\sum_{\mathrm{actually\ generated\ tokens}}\ell_t
\]

不因日志切成多少个 segment 而改变。同一个旧记忆被复制进十次 prompt，只监督它最初真正生成的那一次；tool observation 不计算策略生成损失。模型生成的摘要、状态更新、审核和前置 reasoning 若参与决策，则不能因为换了角色或上下文而自动丢出概率账本。

归一化也要明确：把每条轨迹除以其随机长度，或让多 segment 轨迹重复参加组统计，都会引入额外的样本权重变化。可用固定归一化常数／rollout 级聚合建立参照，再讨论工程上其他 reducer 的取舍。[Dr. GRPO](https://arxiv.org/html/2503.20783v1)对长度和标准差归一化的分析值得借鉴，但不能把数学任务的全部结论直接移植到 Agent Search。

### 5.7 正常预算终止与基础设施故障

旧 `compute_esr_segmented_advantage` 排除 overlong rollout。若正常 action/token budget exhaustion 被放进这一类，组内统计会被改变，甚至只剩一条成功样本而优势归零。v2 尚未接入这段训练逻辑，不能称该问题已修复。

应分别定义：正常错误／弃答／预算终止、模型生成被截断、上下文准入失败、服务故障。基础设施故障不是模型语义错误，但简单丢掉故障轨迹也可能有选择偏差——长轨迹更容易遇到超时。重试和统计口径必须预先固定。

### 5.8 两条理论更清楚的扩展，不同时引入

**势函数差分。** 对一个固定的前缀状态势函数 \(\Phi\)，设

\[
r'_t=r_t+\gamma\Phi(X_{t+1})-\Phi(X_t).
\]

则

\[
\sum_{t=0}^{T-1}\gamma^t r'_t
=\sum_{t=0}^{T-1}\gamma^t r_t-\Phi(X_0)+\gamma^T\Phi(X_T).
\]

若所有正常终态势函数归零，起点项固定，原始 return 排序保持不变。但若只把 shaped reward 再求和做 terminal GRPO，组优势基本不变，不会凭空得到局部 credit。要利用它，应使用按时间的 return-to-go／baseline，并正确处理终态与截断。

TRACE 的 frozen-reference gold-answer likelihood 提供一种价值代理，但属于训练期额外过程信息；它不等于只用一个最终 0/1 标量。该文全部混合、标准化和截断设置也不能仅凭上述恒等式获得统一保证。[TRACE 原文](https://arxiv.org/html/2607.13988v1)。

**重要性修正的动作采样。** 若只想用 provenance 分配训练计算，可冻结每个动作的采样概率 \(q_t>0\)，抽取 \(z_t\sim\mathrm{Bernoulli}(q_t)\)，使用

\[
\widehat g=\sum_t\frac{z_t}{q_t}g_t.
\]

条件于固定 rollout，\(\mathbb E_z[\widehat g\mid\tau]=\sum_t g_t\)，即期望保持原 surrogate gradient。它不增加因果信息，也不保证方差降低；transformer 的前缀计算还可能限制节省。它是理论上更清楚的计算分配方案，不建议现在增加到主线。

主线应先保留普通 outcome-based GRPO／RLOO 参照；provenance 加权单独作为有偏但可能有效的研究分支。

## 6. 最新与相关研究：只吸收与 ESR 决策直接相关的点

以下将“原文中可核对的机制”与“对 ESR 的建议”分开。近期论文多为预印本，没有独立复现保证。模型尺度、固定语料／开放网页、数据集切分与监督信号不同，不比较孤立的 leaderboard 数字。

### 6.1 Harness 与工作记忆

| 论文 | 可借鉴的机制 | 对 ESR 的具体取舍 |
|---|---|---|
| [Harness-1](https://arxiv.org/abs/2606.02373)，2026-06 | 把可恢复状态管理外置；相同 renderer 贯穿 teacher、SFT、RL、evaluation | 借同源渲染与紧凑工作状态，不照搬候选图、工具多样性奖励和自动 top-k curation。其主要目标是检索子 agent 的文档质量，不是同口径 4B BC+ 答案正确率 |
| [ECHO](https://arxiv.org/html/2606.31650v2)，2026 | source-indexed memory 与正信用 trace 共用索引 | 必须作为近邻；借 source 保留与上下文契约，不把 final-selected trace 解释为因果图 |
| [MEM1](https://arxiv.org/abs/2506.15841)，2025 | 紧凑状态与推理共同学习 | 借“记忆内容要能支持下一步”而非仅存目录；保留原始证据的恢复性 |
| [AgentFold](https://arxiv.org/abs/2510.24699)，2025 | 多尺度、主动上下文压缩 | 借“不同历史需要不同压缩强度”；暂不增加额外 folding action 与更多模式 |
| [ReSum: Unlocking Long-Horizon Search Intelligence via Context Summarization](https://arxiv.org/abs/2509.13313)，2025 | 摘要条件化推理与 segmented training | 借训练／推理摘要分布一致；不要把压缩边界当环境终态。这里指搜索 ReSum，不是 2026 年另一篇同名推理论文 |
| [CompactionRL](https://arxiv.org/html/2607.05378v1)，2026-07 | 把压缩生成纳入 agent RL 的长期过程 | 借压缩输出也需要信用与正确条件概率，不直接引入整套 critic 与折扣设置 |

### 6.2 信用分配与修复

| 论文 | 机制／监督来源 | 对 ESR 的取舍 |
|---|---|---|
| [STAMP](https://arxiv.org/html/2607.11172v1)，2026-07 | 训练期 evidence graph、引用验证、首次曝光归因、有界 sign-preserving advantage modulation | 与此前 ESR 加权建议高度接近，不能将“provenance＋bounded weighting”独立声称新颖。可借首次曝光防重复奖励，但 ESR 应区分曝光、使用、反证和修复 |
| [TRACE](https://arxiv.org/html/2607.13988v1)，2026-07 | 冻结参考模型的 gold-answer likelihood → 状态值／局部变化 | 借相邻状态的增量而非所有步骤同分；承认额外过程信息与参考模型成本 |
| [ABSeeker](https://arxiv.org/html/2608.05102v1)，2026-08 | 从标准答案回溯中间线索，对步骤评分，分别用于 SFT 与 RL；包含 Qwen3.5-4B | 借 clue／bridge 粒度与失败轨迹里的有效动作；不把 gold 回溯线索注入学生在线上下文 |
| [AREX](https://arxiv.org/html/2607.21461v1)，2026-07 | 约束审核产生可继续研究的状态；保留已有证据并修复错误方向 | 借 verification-as-transition，而不是单纯 final acceptance；不整套复制内外循环、额外 mid-training 和所有阶段 |
| [CAFE](https://arxiv.org/abs/2608.24794)，2026-08-25 | 共享参数的研究／反馈角色，失败前缀修复、在线与离线交替优化 | 借反馈要随 policy 的错误分布共同改善；不要让共享模型的审核在训练中成为隐形未建模环境。此项本次主要核对到原始摘要，未完成全文细节验证 |

### 6.3 2026 年 9 月的三个新信号

**[Iris: Climbing to the Search Frontier](https://arxiv.org/abs/2609.04304)，9 月 3 日。** 原始摘要报告单一 ReAct agent、不使用测试时 verifier，并强调上下文管理开启／关闭的对照。对 ESR 最有价值的不是分数，而是反证：额外测试时审核不是强搜索能力的必要条件。其模型规模与训练资源不能外推为 4B 结果。本次仅核对到原始摘要。

**[One Policy, Any Budget / AnySearch](https://arxiv.org/abs/2609.00813)，9 月 1 日。** 研究不同预算下的搜索策略与预算状态注入。对 ESR 的直接启示是把真实剩余预算变成模型可见状态。暂不照搬双阶段课程和复合效率奖励。本次仅核对到原始摘要。

**[Dense Process Supervision for Search Agents via Fact Utility Estimation](https://arxiv.org/abs/2609.00833)，9 月 1 日。** 将 raw observation 转成事实集合，对事实聚类并估计 utility。可借鉴稳定事实粒度，而不立即引入语义聚类与贝叶斯打分。组内事实与成功的关联不是自动识别出的因果效应。本次仅核对到原始摘要。

### 6.4 基础 RL 的简单性与稳定性

[RLOO](https://arxiv.org/html/2402.14740v2)提供无需 value model 的 baseline；[Dr. GRPO](https://arxiv.org/html/2503.20783v1)提醒长度与标准差归一化的副作用；[RAGEN](https://arxiv.org/abs/2504.20073)讨论多轮 agent 中的模式坍缩、奖励方差和采样粒度。对 ESR 最合适的借鉴是监测真正的 rollout 分布和有效梯度，建立同源的简单参照，而非同时引入每篇论文的全部优化组件。

[Search-R1](https://arxiv.org/abs/2503.09516)强调环境返回 token 不参与 policy 生成损失；这与“选择哪些 policy token 获得信用”的 semantic mask 是两件事，不应混在同一个 mask 中。

## 7. 推荐的最小收敛版方案

### 7.1 前向只保留一个循环

```text
原始问题与预算
    ↓
有界工作状态 + 最近真实观察 + 少量可恢复证据
    ↓
同一个 4B：检索 / 阅读 / 增量更新 / 可选审核 / 显式结束
    ↓
确定性执行、曝光记录、状态转移
    ↓
下一次请求
```

不增加多 agent、独立 controller、复杂候选知识图谱、每条件 reviewer 或每步过程 judge。

### 7.2 最小内部表示

```text
Archive                  # 完整、不可变、外部可恢复
  document snapshots
  observation views
  search/action provenance

WorkingState             # 有界、可修订、模型可用
  target
  candidate
  slots:
    id, requirement
    binding / finding
    witness_refs, counterevidence_refs
  active frontier
  resource state

Audit                    # 条件化意见，不是外部事实
  state fingerprint
  target / coverage / bound-claim verdicts
  exact witnesses

RequestReceipt           # 训练与回放共用
  renderer / policy version
  actual prompt + shown views
  generated tokens + role + sampling metadata
```

这些是同一个状态机的四类记录，不要求四个新服务。

### 7.3 必须删减的负担

从 policy prompt 移除完整 hash／偏移目录、旧完整 state 反复复制、重复原文和与当前候选无关的旧审核长理由。不要要求模型为无关页面写摘要，也不要要求每次只改一个引用却重写全部状态。

将底层搜索 action ID 绑定等可确定恢复的 bookkeeping 尽量交给 harness。对模型暴露短期稳定 handle；仍在账本保留真实父子动作关系，不能为了简洁而失去来源验证。

### 7.4 训练先保留一个主目标

主目标保持最终正确性及明确预算条件。可训练研究、记忆与审核输出按同一随机策略记录；外部检索内容、复制进 prompt 的旧记忆和缓存审核不重复计损失。

provenance 的第一用途是诊断、构造同前缀修复样本和识别可解释的有效片段。只有在主训练契约成立之后，才比较原始 positive-only、STAMP 风格加权或其他时间信用；不要同时改变审核门禁、数据课程和 advantage，使效果不可归因。

如果还要求模型主动校准弃答，需承认纯 0/1 正确性奖励通常不提供偏好弃答而非有概率猜中的信号；改变错误／弃答效用会改变目标。操作上区分 abstain 很必要，但类型字段本身不能解决激励设计。

## 8. 现在不需要实验，也能先冻结的设计决定

| 设计决定 | 建议 |
|---|---|
| ESR 的主目标 | 有界预算下的正确搜索与作答；groundedness 单独定义和报告，不偷换 |
| hard verifier 的地位 | 独立认证条件，不作为整条研究路线的默认正确性假设 |
| 记忆单位 | 带原文 witness 的小型事实／关系绑定，而非无语义 ID 目录 |
| 活动上下文 | 固定角色、独立 token 预算、最新 read 至少完整展示一次、可恢复淘汰 |
| 训练／推理接口 | 同一 renderer；保存真实请求，不用未来 state 重建过去样本 |
| 共享模型审核 | 纳入角色条件策略；或显式冻结为阶段性环境，二选一 |
| 归因的理论表述 | 可追溯的贡献代理，不称为已证明的因果 credit |
| 学习主线 | 普通 outcome-based GRPO／RLOO 参照；新加权仅作明确有偏的分支 |
| 旧结果与代码 | 继续保留；不把新协议的结论回填成旧实验已证明的事实 |

最值得形成的研究主张是：

> **在有界上下文中维持可恢复的证据—事实绑定，使搜索、纠错与训练都基于同一套实际曝光状态；在不隐藏审核和记忆决策的前提下，研究 provenance 对效率与样本利用的额外价值。**

这比“增加一个更严格 verifier”更稳健，也比“把所有非最终引用动作的梯度清零”更有理论自洽性。能保证的接口性质写成硬规范；依赖模型语义能力的部分保留为清晰假设；有偏归因与新监督来源明确标记。

## 9. 证据与审阅边界

本报告基于上述固定 commit 的静态代码、可访问的原始论文正文／摘要及独立数学推导。Harness-1 的架构图页已通过 PDF 截图核对；没有将其 63 页全部逐页审核。STAMP 的方法与有界调制部分、ECHO 的正信用／上下文接口是重点对照。CAFE、Iris、AnySearch 与 Fact Utility 的部分全文请求不可访问，故只将原始摘要中的机制作为近期研究信号，不引用未核对的消融细节。

未运行新的 BC+、4B、训练或 benchmark 实验；未修改仓库。没有将静态缺口直接报告为已测量的性能损失，也没有把任何近邻论文的结果作为 ESR 未来成绩保证。
