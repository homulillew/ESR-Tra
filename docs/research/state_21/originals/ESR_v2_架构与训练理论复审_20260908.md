# ESR 的理论与架构复审：让证据状态、上下文和学习目标一致

**审查日期：2026-09-08**  
**对象：Agent Search / BC+ / 最终 4B 系统**  
**代码基线：`6ee9c4a264cd80a50d8a15511c8ed80b39c763b6`**  
**性质：设计审查与研究综合；未修改仓库，未启动模型推理或训练实验。**

## 核心结论

保留 v2 的不可变证据、单一工具契约、审核幂等、错误分类和追加式日志。下一次设计修订不应继续增加“如何让 verifier 放行”的规则，而应完成三项工作：

1. 将“必要条件＋引用 ID”补成真正可用的、包含关系事实与反证的紧凑研究状态。
2. 将“缩短近期历史”补成有界的上下文编译器，明确区分归档、工具返回、模型实际接收和状态吸收。
3. 将 provenance 定位为依赖线索和局部测量的索引，而不是未经验证的因果奖励；主训练先保持最终结果目标与真实条件分布一致。

**推荐定位：ESR 是一个可恢复、保留证据依赖的有限上下文研究系统；它可支持更可靠的局部信用估计，但不会因保存了来源关系就自动获得正确的因果归因。**

“理论上有效”应拆成可证明的协议性质、在明确假设下成立的估计性质，以及仍需经验检验的能力改善。不能把前两者替代第三者。当前 v2 自己也明确限定了机械保证与语义能力的边界。[Harness v2 设计规范](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/docs/harness/DESIGN.md)

### 1.1 已经正确的基础，不应推倒重来

v2 将不可变原文／实际视图与模型判断分开；`read_evidence` 重放已存视图；工具 schema 与参数校验共用定义；审核使用独立上下文和精确输入缓存；错误不伪装为 gap；hard/soft/off 保留真实标签。它们为可审计的前向系统建立了正确基础。[Harness v2 设计规范](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/docs/harness/DESIGN.md) [audit.py：审核包与协议检查](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/audit.py) [protocol.py：状态与工具 schema](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/protocol.py)

问题不是“重构完全错误”，而是当前底座还不等于一个信息充分、预算闭合、可直接用于 RL 的完整方案。

### 1.2 六个仍未闭合的设计接口

| 接口 | 当前代码事实 | 风险／设计含义 |
|---|---|---|
| 工作记忆 | Claim 只有 requirement 与 observation IDs | 没有显式保存已提取的实体绑定、年份和关系；依赖模型重读重建 |
| 上下文有界性 | 全量 observation directory 始终渲染，只缩 recent_actions | 目录随轨迹增长；state＋pending 放不下就终止，尚无完整容量分配 |
| 实际可见性 | 已引用观察的 read 不重新 pending；recent 可缩到 0 | 工具成功返回后，下一次模型请求仍可能不包含刚重读的文本 |
| 审核完整性 | 只送当前 claim 引用的观察 | 被 dismiss 的已知反证可能不进审核包；对候选的审核受引用选择影响 |
| 修复事件作用域 | resolved 比较 claim ID、requirement 和前后审核状态 | 换候选但保留泛化条件，也可能被计作同一 requirement 的修复 |
| 学习接口 | 新前向是独立包；历史接入仍是成功资格＋positive-only mask | 新状态契约没有自动转换成新训练语义，不能直接拼接 |

前五项来自当前环境与 runner，第六项来自历史 ECHO 接入。它们是静态分析得到的机制风险，不是本轮实测的新 bad-case 发生率。[engine.py：状态、观察、审核及上下文](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/engine.py) [runner.py：实际模型输入构造](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/runner.py) [历史 ECHO/verl 优势接入](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_grpo/integrations/echo.py)

## 2. Harness：从“管理证据 ID”到“管理可修正的研究状态”

### 2.1 Requirement 与 Finding 必须分开

“要找到事件 E 两年前的冠军”是一条要求；“A 在 2010 年获胜，B 在同一事件 2008 年获胜，所以题目目标为 B”才是已获得的研究信息。前者不能替代后者。

当前 schema 没有独立的 finding/binding 字段；它不是不能让模型推理，而是要求模型在证据离开近期上下文后，重新通过 ID 找回原文、重做关系连接。全量目录又只有 docid、偏移和 hash，没有语义导航信息。[protocol.py：状态与工具 schema](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/protocol.py) [engine.py：状态、观察、审核及上下文](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/engine.py)

建议仅增加一个有引用的简短 finding/binding，不恢复长篇滚动总结，不构建全量知识图谱：

```text
ResearchState
  target
  candidate: {value, revision}
  checks:
    - claim_id
      requirement
      finding                 # 已提取关系或当前推断，短文本
      supporting_spans
      counterevidence_spans
  active_gap_id
  budget                      # harness 管理，不由模型填写
```

需要多跳绑定时，在 finding 中明确实体、事件与年份对应；复杂任务可共用小型 bindings 表，但不强制把每个句子转成三元组。Finding 是模型写入的解释，不是原文真理；引用和审核标签分别保存。

### 2.2 逐条件核验必须保留共同实体绑定

下面两个命题不同：

$$
\bigwedge_j\exists x_j\;\phi_j(x_j)
\quad\not\Rightarrow\quad
\exists x\;\bigwedge_j\phi_j(x).
$$

每个条件都找到一个符合的人，不等于找到同一个符合所有条件的人。这是多跳检索里“每段证据都对，最后答案错了”的基本机制。

因此，atomic audit 不是把全题拆成互不相干的判断。它应执行“局部事实支持＋共享变量一致性＋目标关系位置”的核验。当前 target 检查已覆盖一部分目标绑定，但状态仍应显式保留中间关系，减少每次审核重新猜测的负担。[audit.py：审核包与协议检查](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/audit.py)

AREX 的可借鉴之处正是把未解决条件变成下一轮具体研究目标，并保留已获得的关系信息；不必复制它的双层循环、独立重启逻辑和完整多阶段训练。[AREX: Towards a Recursively Self-Improving Agent for Deep Research](https://arxiv.org/html/2607.21461v1)

### 2.3 支持和反证都应能保留，但不要求审核整份档案

当前 reviewer 只看到 actor 最终选择引用的材料。存在一个结构性风险：actor 读到反证后将其 dismiss，再用少量支持材料得到审核通过。这里不需要恶意策略，普通确认偏差就可能产生同样结果。[engine.py：状态、观察、审核及上下文](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/engine.py) [audit.py：审核包与协议检查](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/audit.py)

建议对当前候选保留有限的 contradiction certificate：冲突点、原始片段、候选版本。dismiss 的含义是“不继续占用活动上下文”，而不是“证据被证明无效”。不要求保存所有失败猜测；只保留能阻止当前候选重复犯错、或解释候选转换的少量记录。

对尚未被模型识别为冲突的材料，harness 无法自动知道它是反证。这个改动保证的是“不轻易丢掉已识别冲突”，不是“程序自动发现全部反证”。

### 2.4 Candidate revision 与 evidence repair 不混记

建议以三个作用域记录审核与修复：

```text
requirement_revision
candidate / binding_revision
evidence_packet_hash
```

同一候选补齐证据属于 evidence repair；由 A 换成 B 后满足同一泛化条件属于 candidate revision。两者都可能有价值，但不是同一个因果事件。当前 resolved 逻辑没有比较 candidate，仅稳定 claim ID 还不足以区分二者。[engine.py：状态、观察、审核及上下文](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/engine.py)

审核缓存已经包含答案，因此并不存在“换答案还错误复用原 audit”的同类问题；本条针对的是修复事件标签和后续训练解释，不能混淆成缓存 bug。

### 2.5 停滞应该触发重新思考，不应直接产生 reward

原文区间新颖性比“query 字符串变化”更可靠，v2 已正确将它命名为 raw-text novelty。但当前 stagnant counter 在没有 new_chars 的任何动作后都会增长，包含成功的状态更新和审核。[engine.py：状态、观察、审核及上下文](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/engine.py)

因此需要同时看“新观察”“候选／关系事实变化”“未解决问题是否变化”。这三者仍只是停滞诊断，不是可靠的语义信息增益。连续读新网页可以毫无帮助；只依据旧证据完成正确的年份推算却可能是决定性进展。

不奖励新页面数量、不奖励 gap 文字减少，也不因为重复若干次就强制通过。

## 3. 上下文管理：真正的问题是有限工作记忆的内容与边界

### 3.1 三层数据不能再混在同一个概念里

建议区分：

| 层 | 作用 | 大小与可信度 |
|---|---|---|
| Evidence archive | 保存全部原文、已产生视图和审计历史 | 外部存储，可增长；原文是观察，不是结论 |
| Working state | 当前候选、关系事实、必要条件、冲突和恢复指针 | 严格受预算限制；模型写入部分均可修订 |
| Decision snapshot | 这一轮实际送入模型的 messages、token IDs、视图区间和版本 | 不可变；训练和复盘以它为准 |

Decision snapshot 不应再成为新的一套语义状态机，它是上下文编译器的输出与采样记录。

### 3.2 “已归档”“工具已返回”“模型已接收”“已吸收”是四个不同状态

当前 `read_evidence(o1)` 在 o1 已被引用时不会创建 pending；它的文本仅可能出现在 recent_actions。`messages_for` 为适应长度可以把 recent_limit 降至 0。因此存在一条可由代码推出的路径：工具重读成功，但下一次模型输入没有这段刚重读的文本。[engine.py：状态、观察、审核及上下文](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/engine.py) [runner.py：实际模型输入构造](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/runner.py)

这不是原文变异，而是 exposure contract 缺失。建议 latest tool observation 至少 pin 到下一次策略请求；记录它实际进入了哪个 DecisionSnapshot。下一次请求完成或产生明确的接收记录后，才允许按工作记忆规则移出。

当前已记录原始请求，能够帮助事后排查，但还没有把这种暴露关系变成显式不变量。[client.py：token 预算及模型请求](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/client.py)

### 3.3 上下文编译应按职责和 token 预算，而不是只按近期窗口

推荐形式：

$$
C_t = Q \oplus Rules \oplus S_t^{compact} \oplus E_t^{working}
      \oplus O_t^{latest} \oplus H_t^{short} \oplus B_t.
$$

其中 Q 和 rules 是固定前缀；工作证据包含短引用与必要反证；latest observation 有一次明确的可见性保证；history 只保留少量决策摘要，不重复包含全部工具响应。

当前 pending observation 包含 text 和 raw_parts，而近期工具结果还会再次包含同一 observation，存在无意义的序列化重复；全目录同样无界增长。存储对象可以冗余，模型渲染不需要照搬存储对象。[engine.py：状态、观察、审核及上下文](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/engine.py) [views.py：实际证据视图](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/views.py)

推荐把上限写成可检查的分配：

$$
B_{fixed}+B_{state}+B_{evidence}+B_{latest}+B_{history}+B_{output}
\le B_{context}.
$$

这些是可配置的上限，不是声称某组数字普遍最优。若题目本身或最小必须状态超出配置，应明确失败或换更合适配置，不能把关键条件静默删掉。

### 3.4 先 admission，再冻结 view，再记录暴露

检索观察不应先生成一个最终放不下的“大包”，再让 runner 因 pending 不可裁剪而终止。建议先根据可用 buffer 选择有界的原文窗口，形成不可变 view，再进入待接收队列。更多内容通过 cursor/offset 获取。

部分窗口可以合法，但必须有自己的 span、hash 和 continuation 标记。不能在 view 已被定义为“模型看过的全文”之后偷偷截断。审核使用这些已暴露的视图；最终审核包过大时，应选择必要原始 spans 或明确分批，而不是悄悄漏掉证据。

### 3.5 归档目录应可导航且有界

原文永久存储，不意味着把所有 observation ID 和 hash 永远放在 prompt 里。保留与当前条件有关的少量语义目录项：标题／短索引、候选关联、待查条件和 view ID；其余通过分页或已有 read 接口的轻量查找恢复。

这里的索引摘要必须标为导航，不成为审核的原始证据。原则来自 ECHO 的 source-indexed memory；我们借鉴来源保留，不直接照搬它的 final-trace 正信用。[ECHO: Prune to Act, Trace to Learn with Selective Turn Memory in Agentic RL](https://arxiv.org/html/2606.31650v2)

### 3.6 Budget 也是研究状态

当前 actor context 主要显示剩余 action，而 client 另管 policy＋audit 的 completion budget。模型看不到真实剩余生成预算，可能在预算将尽时启动昂贵审核，最后没有足够空间关闭轨迹。[engine.py：状态、观察、审核及上下文](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/engine.py) [client.py：token 预算及模型请求](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/client.py)

建议暴露剩余 action、completion 预算与终止保留量。prefill、生成、审核、检索分别记成本；未知 usage 不假装精确。在传输超时后，服务端可能已经生成并消耗资源，后续重试应有悲观预算预留或明确的实际成本未知标记，不能称为严格真实计算预算保证。

### 3.7 上下文信任边界不可随压缩提升

原始用户任务、工具返回的不可信网页、actor 的推断和 auditor 的诊断，应在渲染中保持来源身份。当前 runner 把所有环境状态序列化到单个 user message，虽然 system 已提醒工具内容不可信，但信息来源仍值得结构化标记。[runner.py：实际模型输入构造](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/runner.py)

不要在压缩时把网页内的指令转写成新的 system 要求，也不要把旧审核 rationale 变成无版本的当前事实。来源标签不能解决全部提示注入，但能使信任边界可检查。

## 4. 审核与终止：不要把高门禁覆盖率误认成正确目标

### 4.1 同模型新上下文不是独立裁判

fresh context 减少历史锚定，不能消除同模型共享的实体知识缺陷、否定理解错误和推理偏好。建议保留独立审核输入，但不赋予它“唯一真理”的语义地位。

若十个必要判断各自在充分证据上有 95% 通过率，并假设这些误拒相互独立，则全部通过概率是：

$$0.95^{10}\approx 0.599.$$

这是数学示例，不是对你们 verifier 的实测。它说明增加 all-pass 条目会组合放大误拒；相关误差时不能直接用乘积，但同样不能只看单条准确率。

### 4.2 hard 与 soft 服务不同效用目标

在固定预算、未作答计错的 benchmark 中，核心目标是最终作答正确率；在风险敏感的应用中，目标可能是错误提交率受约束下的最大覆盖率。它们不应被一个默认门禁混为一谈。

建议：机械合法性始终 hard；语义审核在研究策略中作为可行动的诊断；严格证据认证保留为独立输出／部署 profile。hard/soft/off 的结果不能混报。v2 已经有模式分离，但 soft 仍要求有效审核，因此格式或服务失败仍可能阻塞该模式的结束，需要在设计中明确它是资源故障还是必要认证前提。[Harness v2 设计规范](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/docs/harness/DESIGN.md) [engine.py：状态、观察、审核及上下文](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/engine.py)

### 4.3 审核反馈应该回答“下一步能做什么”

target/coverage 当前只有 status 和 reason；逐 claim 才有原文 quote。建议把缺失条件尽量映射回原问题位置或稳定 requirement，让 actor 知道是目标关系错、缺桥接事实、单位口径不清还是明确冲突。[audit.py：审核包与协议检查](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/audit.py) [protocol.py：状态与工具 schema](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/protocol.py)

不是增加更多评分，而是提高反馈可操作性。近期 Polished but Unresolved 将约束清晰度与动作映射列为缓解过早结束的因素；可借这点，不必引入其 hidden-state probe 和激活干预组件。[Polished but Unresolved: Identifying Late-Stage Pressure States in Long-Horizon Tool-Use Agents](https://arxiv.org/abs/2609.00823)

### 4.4 终止是有限预算决策，不是“新证据越多越好”

概念上可用以下有限预算价值式组织逻辑：

$$
V(s,b)=\max\{U_{answer}(s),U_{abstain}(s),
  \max_{a\in research,\;cost(a)\le b}\mathbb E[V(s',b-cost(a))]\}.
$$

这里使用固定预算约束；若再加入每步成本惩罚，就是另一个显式效用目标，而不是宣称不改变原始奖励。审核本身也应消耗预算并能带来信息价值，不能无条件无限重复。

harness 不需要精确求解这个 Bellman 方程；它只需要给策略足够的信息，使“继续搜索、重读、改候选、结束”成为可学习的选择。

### 5.1 三类结果不能混为一个“已证明提升”

ECHO、TRACE 和 AREX 与搜索任务直接相关；FACTOR 与部分信用审计主要在交互式环境中验证。ContextPilot、CBPO、RTPO 等新作的摘要提供了值得追踪的机制线索，但不能将未核对的具体定理、实现和模型规模视作你们 4B/BC+ 的直接证据。

Credit Without Ground Truth 在其 ALFWorld 执行重放设置里发现，常用步骤评分与局部结果贡献不能简单等同，并强调训练剂量混杂。它是重要的反证性研究，但单个环境、有限策略和抽样精度不能证明“所有 process credit 无效”。对 ESR 最直接的启示是：有效样本量和随机同密度控制必须与信用内容分开理解。[Credit Without Ground Truth: Auditing Step-Level Credit Assignment in LLM Agents Against Executed Replay](https://arxiv.org/abs/2608.19760)

### 5.2 优化器稳定性不应与 ESR 机制一起改变

GSPO 采用序列层面的 likelihood ratio 与 clipping，SAPO 采用平滑门控处理偏离采样策略的更新；它们是优化器层的工作，不能修复错误的历史上下文或审核输入。Dr GRPO 提醒归一化与长度／难度权重耦合。[Group Sequence Policy Optimization](https://arxiv.org/abs/2507.18071) [Soft Adaptive Policy Optimization](https://arxiv.org/abs/2511.20347) [Understanding R1-Zero-Like Training: A Critical Perspective](https://arxiv.org/abs/2503.20783)

因此当前理论设计只规定 ratio 的分母来自真实 behavior policy、上下文一致、loss reduction 明确。暂不把“改 memory＋改 verifier＋改信用＋改优化器”打包成一次新方案。Search-R1 的工具观察屏蔽与结果监督仍是应保持清楚的基础。[Search-R1: Training LLMs to Reason and Leverage Search Engines with Reinforcement Learning](https://arxiv.org/abs/2503.09516)

## 6. 训练归因：先纠正两项理论误解

### 6.1 失败轨迹中有正确动作，不意味着普通策略梯度理论错误

对固定环境与固定上下文编译规则，令每轮 actor 的完整生成动作包含其推理与工具请求。最基本的 on-policy score-function 形式为：

$$
\nabla J(\theta)
=\mathbb E\left[\sum_t (R-b_t)\nabla_\theta\log\pi_\theta(a_t\mid C_t)\right],
$$

其中 baseline 必须满足相应的条件独立性，不能直接依赖被打分的当前动作。

单条失败轨迹的负信号可能作用到局部正确动作，这是方差和局部价值估计的问题；不能据此推导“必须删除所有负优势才合理”。正确性与贡献本身也不同：一步正确动作可能冗余，一步看似无效的探索可能排除了关键候选。

这里的无偏讨论针对基础 score-function 估计，不自动扩展成带组内标准差、clipping、异步采样、长度归一化的 GRPO 整套算法定理。实际 GRPO 框架可以保留，但数学陈述要注明适用边界。

### 6.2 对先前 bounded provenance weighting 的修正

当前研究计划已明确写明该加权是有偏启发式，而不是 GRPO 的无偏等价；这个免责声明应保留，并进一步把它从推荐主算法降为可选假设。[当前 4B 训练方案：provenance 加权与 auditor 冻结](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/docs/research/ESR_GRPO_4B_EXPERIMENT_PLAN.md)

令：

$$w_t=\frac{1+\lambda m_t}{1+\lambda\bar m},\qquad\widetilde A_t=w_tA.$$

平均权重为一并不保持梯度：

$$\sum_t w_tA\nabla\log\pi(a_t\mid C_t)
\ne\sum_t A\nabla\log\pi(a_t\mid C_t)$$

通常成立。

一个纯数学反例：两步对同一参数的 score derivative 分别为 1.5 和 −2，A=1。原始样本梯度为 −0.5。若 m=(1,0)、λ=1，则 w=(4/3,2/3)，加权样本梯度为 2/3，方向相反。该反例不预测实际训练表现；它否定的是“均值守恒足以保证梯度方向守恒”。

FACTOR 原文同样明确：其 action-mean 守恒针对 behavior policy 点、clipping 前的标量 surrogate 系数，不保证梯度方向或范数。[FACTOR / How Much, Then Where: Credit-Conserving Action-to-Token Allocation for Multi-Turn Agent Reinforcement Learning](https://arxiv.org/html/2608.07118v1)

### 6.3 更完整的 provenance 仍然不等于因果贡献

最终引用 mask 会漏掉至少两类有用动作：找到桥接实体／别名的导航页，以及用于排除错误候选但没有进入最终支持集的反证。反过来，把一份无关材料挂入最终 citation list，并不能证明获取它的动作有贡献。

ECHO 自己将方法描述为 final-trace approximation；不能因为 ESR 将 turn 索引细化为 claim–evidence 索引，就宣称自动消除了这种近似。[ECHO: Prune to Act, Trace to Learn with Selective Turn Memory in Agentic RL](https://arxiv.org/html/2606.31650v2)

最合理的用途顺序是：provenance 用于恢复、诊断、挑选需要进一步测量的位置；只有在测量或有额外可靠假设后，才进入信用估计。

## 7. 更干净的训练接口，以及一个可选的局部信用方向

### 7.1 精确历史上下文是先决条件

每次采样记录：

```text
DecisionSnapshot
  rollout_id / decision_id / role
  actual prompt token IDs
  generated token IDs, including reasoning when present
  behavior logprobs and behavior policy revision
  compiler / tokenizer / schema revisions
  actually exposed observation IDs and ranges
  policy-loss mask
```

不得用最终 ResearchState 替换早期决策输入；不得把最终证据注入前面尚未观察到它的 turn；不能只记录解析后的工具 JSON 再重构整条训练序列。每个自产 token 在其原生成位置计算一次损失，后来作为 prompt 的重放不重复训练。工具观察与机械生成文本不是 actor 生成标签。

v2 当前完整请求日志便于审计，但还没有这套精确采样协议；历史训练接入也没有因新包存在而自动兼容。[client.py：token 预算及模型请求](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/client.py) [runner.py：实际模型输入构造](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_harness/runner.py) [历史 ECHO/verl 优势接入](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_grpo/integrations/echo.py)

RTPO 的近期摘要将 rollout/training context mismatch 与策略漂移列为多轮不稳定的共同来源。我们借它识别问题的角度，不以尚未复核的递归最优性声明作为自己的保证。[RTPO: Reverse-Turn Policy Optimization for Stabilizing Agentic RL Training](https://arxiv.org/abs/2608.18682)

### 7.2 Auditor 的训练身份必须明确

当前计划提出先冻结 accepted/post-SFT 的 4B auditor，这是正确的归因隔离。actor 训练时 auditor 与检索环境相对固定，便于判断是哪一部分策略发生改变。[当前 4B 训练方案：provenance 加权与 auditor 冻结](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/docs/research/ESR_GRPO_4B_EXPERIMENT_PLAN.md)

同一模型家族、两个 4B checkpoint 仍需分别报告调用与资源；不能称为只有一个服务开销。未来若恢复共享权重，则轨迹分布包含两种生成：

$$p_\theta(\tau)\propto
\prod_t\pi_\theta(a_t\mid C_t^{research})
\prod_k\pi_\theta(v_k\mid C_k^{audit}).$$

忽略审核生成的 score 项却同时更新相同权重，不等于优化完整联合系统的精确策略梯度。可以选择这种工程近似，但必须标明。最终 benchmark judge 在两种方案中均独立于在线 auditor。

### 7.3 最简主线：普通 signed outcome 学习

主线只规定最终正确性奖励和真实条件分布；正常任务预算耗尽而没有答案计失败；服务故障、数据损坏等按固定机制隔离，不按答案好坏选择性删除。不要额外用 audit pass、gap 数量和引用数量乘一次训练资格。

历史代码排除 overlong、对成功做 eligibility gate、只保留正优势的逻辑属于旧训练定义，必须作为旧算法阅读，而不是当作新 forward contract 的自然结论。[历史 ECHO/verl 优势接入](https://github.com/homulillew/ESR-Tra/blob/6ee9c4a264cd80a50d8a15511c8ed80b39c763b6/src/esr_grpo/integrations/echo.py)

为了理论描述清楚，可用独立同题 rollout 的 leave-one-out baseline 作为参照：

$$b_i=\frac1{G-1}\sum_{j\ne i}R_j,\qquad A_i=R_i-b_i.$$

在同题 rollout 随机性条件独立等前提下，它不使用当前样本自己的动作或奖励来估计其 baseline。若加入组内标准差或 clipping，则需另外讨论这些近似，而不是把全部包装成无偏。

### 7.4 真要增加一项信用机制，优先考虑“独立续跑 baseline”

**这是本次提出的设计方向，不是现有实现，也不是已经验证优于 GRPO 的结论。**

让 ESR state 选择少量值得测量的决策前缀，例如候选切换后、关键证据加入后、重要 memory edit 前。选择必须只使用动作前可见信息，而不是最终成功答案反推。

从该前缀恢复同样的外部档案、工作状态、上下文编译结果、auditor 配置和剩余预算，用固定 behavior policy 独立采样 K 条后续完整轨迹：

$$\hat b_t=\frac1K\sum_{k=1}^K R(\tau_t^{(k)}).$$

它们应从“当前动作尚未选择”的位置重新采样，不能强制“必须换成与原动作不同的动作”。后者是另一个用于诊断的反事实对照分布，不再自动是独立 baseline。

把局部信用写为：

$$\hat A_t=R_{factual}-\operatorname{stopgrad}(\hat b_t).$$

若 \(\hat b_t\) 与 factual 当前动作在历史条件下独立，则：

$$
\mathbb E[\hat b_t\nabla\log\pi(a_t\mid C_t)\mid H_t]=0.
$$

未选中测量的步骤仍使用普通 baseline；不将其梯度置零。这样新增的是更局部的期望回报参照，而不是未来依赖的梯度闸门。

条件和代价必须写清：需要真实可恢复的执行状态、独立采样、固定版本和预算；有限 K 会增加估计噪声及成本；\(V\)-baseline 不自动等于方差最优 baseline；以上无偏性质对应 on-policy unclipped score-function，并非整个 PPO/GRPO 收敛保证。

这一路线与 CBPO 的 exact-prefix 局部对照、ContextPilot 的关键编辑点分支具有相邻思想，但此处的 baseline 独立性推导是自己的设计限定，不声称两篇论文都实现了同一估计器。[Contrastive Branch Policy Optimization](https://arxiv.org/abs/2608.24300) [ContextPilot: Teaching Agents for Proactive Context Management via Fine-grained RL](https://arxiv.org/abs/2608.28476)

它比“最终引用的动作都值得奖励”更接近可解释的信用，但不是免费的改进。初始 ESR 核心不必启用分支，只保留将来正确支持它的 snapshot 与恢复边界。

## 8. 势函数奖励整形：一个有用的定理，以及它没有承诺的东西

定义：

$$r'_t=r_t+\eta[\gamma\Phi(X_{t+1})-\Phi(X_t)].$$

对于固定有界势函数、适当的状态／历史增广与终止边界，势函数整形可以保持原任务的策略排序。经典依据是 Ng、Harada、Russell 的奖励变换定理。[Ng, Harada & Russell — Policy Invariance Under Reward Transformations](https://people.eecs.berkeley.edu/~russell/papers/icml99-shaping.pdf)

对有限轨迹直接展开：

$$\sum_{t=0}^{T-1}\gamma^t r'_t
=\sum_{t=0}^{T-1}\gamma^t r_t-\eta\Phi(X_0)+\eta\gamma^T\Phi(X_T).$$

若所有真实终态，包括定义为任务终态的预算耗尽，都令 \(\Phi(X_T)=0\)，同一个初始问题下只差一个与动作无关的常数。预算应纳入状态，以正确表达有限 horizon；外部意外截断则不能不加说明地当作已终止。

**但若最后仍将整条 shaped return 求和后做普通组优势，该常数会抵消，没有凭空产生新的 GRPO 学习信号。** 若想改变时间归因，就要采用 return-to-go、局部 baseline 或价值估计，而不是把每个势差未经论证地直接广播给该动作的 token。

这也是理解 TRACE 的边界：其一阶 TD 差分有望远镜求和性质，但参考模型的 gold-answer 可预测性不是环境成功价值；终点 proxy 不恒定，而且完整实现还混合时间信用和 outcome advantage。不能将“差分能求和”替换成“最终目标与最优策略必然不变”。[TRACE: Turn-level Reward Assignment via Credit Estimation for Long-Horizon Agents](https://arxiv.org/html/2607.13988v1)

因此本轮不建议新增 coverage potential 或 likelihood reward。它们可以是未来研究对象，不能作为填补当前前向缺口的捷径。

## 9. 4B 上保持简洁的最终设计取舍

| 保留 | 补齐 | 暂缓／不作为理论主张 |
|---|---|---|
| 不可变文档和视图 | 逐调用实际 exposure 记录 | 全局知识图谱 |
| 六个清晰工具和单一 schema | 少量有来源的 finding/binding、必要反证 | 多 agent controller、复杂重启树 |
| 审核新上下文、精确缓存 | candidate-scope 的诊断与修复标签 | 同模型审核等于独立正确裁判 |
| 确定性上下文构造 | 预算分区、有限目录、latest-result pinning | 保存档案等于活动状态信息充分 |
| actor 与 auditor 身份分离 | behavior context/token/logprob 一致性 | final-trace 等于因果贡献 |
| 最终结果奖励 | 将 provenance 用作恢复和测量索引 | positive-only hard mask 默认优于 signed PG |

工程上首先是修改现有模块的责任边界，而不是再起一套 parallel harness：protocol 补充最小状态；engine 区分候选与证据修复；runner 成为有界 context compiler；client／ledger 记录准确采样和暴露边界。训练适配仍独立，不能悄悄并入推理状态机。

### 9.1 本轮应固定的六句话

**观察是来源，不是结论。**  
**Finding 是带来源的可修订解释，不是第二份原文。**  
**Audit 是带版本的诊断，不是不可置疑的事实。**  
**Dismiss 是移出工作上下文，不是反证消失。**  
**Provenance 是依赖线索，不是因果贡献标签。**  
**Context snapshot 是训练条件，不是事后可任意重建的展示格式。**

### 9.2 更适合论文与后续实现的主张

与其主张“前向通过完美 verifier，反向准确奖励真正有用动作”，更稳妥的研究主张是：

> 在有限上下文预算下，以来源保留的关系状态维持长程研究进展；通过明确的审核、暴露和采样边界，避免机械上下文失真与训练条件错配，并为基于最终结果的局部价值／信用测量提供可恢复前缀。

这个主张可以拆成可证明的来源／缓存／容量不变量，在条件独立性下成立的估计性质，以及需要真实 4B 验证的语义和性能假设。它不需要把每篇论文的模块叠起来，也不依赖先拥有一个永远正确的 verifier。

## 10. 限制与证据等级

本报告没有重新执行模型推理、BC+ 评测或训练；没有修改远程仓库。代码问题均以固定提交为依据，静态风险不等于实测发生频率。

检索围绕：来源可恢复的上下文管理、约束修复与停止、步骤信用及其反证、真实训练上下文、奖励整形边界。停止继续广泛发现的原因是这些决策家族已经有原始支持或明确限制，新增更多相近方法不大可能改变本报告的架构取舍。
