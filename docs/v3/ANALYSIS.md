# ESR v3 方案分析：从 bad case 到低编号负担

## 1. 对象与证据边界

本轮从用户指定的 `main@6ee9c4a264cd80a50d8a15511c8ed80b39c763b6` 新建分支，实现独立的 `esr_harness_v3`。这个 main 不是此前分析的研究分支 `c6dec9c`。不将新协议写进旧包，不重解释旧 SQLite，不改训练 reward/router，不改历史成绩。

直接规格来源为会话文件《ESR_v3_低编号负担完整方案.md》与《ESR_编号问题与论文接口对照.md》。历史依据是 v1 `ESR-GRPO-Code-L@253beb4` 和 v2 `ESR-Tra@c6dec9c` 的报告；它们是历史作者记录，不是本次重算的私有轨迹。论文只作为已有设计的有限来源，本轮不重新作论文性能主张。[1–6]

本次代码实现前向执行与真实事件记录。离线测试验证契约，不代表 4B、32B、强 API 或 BC+ 的准确率/成本改善。真实模型、付费接口、完整 BC+ 语料和 GRPO 优化器没有在本轮运行。

## 2. 编号失败不能都归因于模型

| 类别 | 依据或反例 | 应改变的部分 | 不能推导的结论 |
|---|---|---|---|
| 合法 c0 被拒 | v2 更正：实际 schema 的共享字典别名污染；442/1001 是受影响导出请求数 | schema 与执行器共用契约，每次导出独立对象 | 不是 442 次模型编号错误 |
| ID 存在却不能使用 | q120 登记覆盖、q170 回读、q790 pending/focus | 交付与采用分离；恢复与终止不要求无关清账 | 不保证原来的模型因此答对 |
| 合法 ID 错绑内容 | auditor 将真实引文归给另一观察 | 内容与句柄相邻，局部来源选择，独立测错绑 | enum 合法不等于来源正确 |
| 新 ID 尚未收到就猜测使用 | 旧 add/update 语义及同轮新观察引用反例 | add 禁止自填 ID；回执返回 ID 与内容；引用绑定决策快照 | 代码可构造风险不等于已知自然频率 |
| 反馈正确但参数不变 | 引号合成局的连续 noop | 对齐具体问题与目标字段效果 | changed 不等于语义修复 |

重点不在把 c1 改成另一个名字，而在减少模型必须执行的身份连接。语义选择仍由模型完成；程序不能用模糊匹配或自动纠号替它选择证据。

## 3. 哪些能力继承，哪些是本次变更

原文档案、局部 delta、审核隔离、noop、精确日志以及有序工具执行在旧方案中已有基础，不能算 v3 首创。此次实现的低编号前台与研究机制为：

| 本次设计 | 对模型减少什么 | 程序承担什么 |
|---|---|---|
| add / revise 分开 | 创建时不猜编号；修改才选对象 | 分配 ID、保留不可变版本、返回内容映射 |
| 统一 refs | 不重复分流 observation_ids 与 based_on；不抄全部祖先来源 | 按类型保存直接原文与前提边，展开时保留继承来源 |
| 冻结 this | 单原文局部使用不用抄随机 o 编号 | 明确映射、整批阅读判定、实际呈现、请求快照绑定 |
| 内容邻接 | 不在编号表与正文之间远距离配对 | 卡片组织、来源窗口与段落索引 |
| 可恢复历史 | 未写 finding 的搜索线索仍有入口 | 当前 episode 内的观察、搜索、备注定位 |
| 版本化局部修订 | 不重做所有独立事实 | 已声明依赖失效、当前研究段重建 |
| 直接审核/提交答案 | 不为核对或结束先保存同一答案 | 准确答案包、审核对象匹配、明确终态 |

统一 refs 可能把一部分类型错误变成合法但错绑；this 也可能引入指代误用。二者是需要消融的候选，不是必然优于 c/o 的结论。`enable_this=False` 是明确回退；不通过自动替换选择器掩盖失败。

## 4. 论文思想如何被限制性吸收

ECHO 官方配置将局部记录绑定最近工具结果，历史选择才要求从 `Valid turns` 输出 `turn_N`。本实现只借局部归属与跨历史选择的分离，不要求每轮总结，也不将回合归属当逐 claim 支持证明。[4]

AgentOccam 将对象类型、编号、名称放在一起；本实现借内容邻接，不借网页元素随页面变化的身份语义。ContextPilot 有整数 chunk ID、scan 和精确匹配的 memory key；本实现借明示候选与自然局部操作，不复制记忆工具族。[5–6]

此前阅读的 PlanFence / RD-Forget 启发依赖范围与存档/当前使用分离；CAFE 启发后续失败前缀恢复训练；VICT / Coverage 启发来源与因果覆盖分开。它们没有被逐篇变成新的在线组件。论文清单的概括不是对 ESR 新接口的实证。[7]

## 5. 最小研究闭环

`Archive` 保存真实材料和事件；`State` 表达当前理解；`Context` 组织下一次决策。三个职责属于同一个 episode，不是三个模型维护的知识库。

模型只选择搜索方向、来源、解释和终止。程序只保证可确定的身份、曝光、版本、事务与成本。支持与反对仍是带范围的语义意见。

正常研究保留近期交互，只有容量压力或明确替换当前解释时重建研究段。新旧事实可以并存；晚读到的材料不自动更真。导航来源不是推理依赖，旧候选被排除不删除沿该路线找到的原文。

## 6. 仍然不能由 harness 保证的事情

模型可能找不到关键材料、未识别反证、误读年份、漏写依赖、未调用审核或继续 noop。原题保留不等于完整覆盖；引用合法不等于蕴含；记录依赖不等于因果识别。取消 blocker 只保证合理动作可执行。

4B 的协议学习与恢复能力仍需训练。恢复数据应保留策略自己的失败前缀、真实可用证据、简短反馈和有效续程，也要有错误审核、无需记忆和短路径的反向样例。不得回填测试题答案后称为自然研究。

## 7. 研究与工程的验收分开

首先检查确定性契约：猜号、this 多页禁用与快照、未交付引用、局部失效、原子回滚、审 A 交 B、缺/空审核、预算、原生回执、只读回放。

固定前缀再比较内容邻接、refs 和 this；使用一致双射改名与列表重排，保持全部来源约束。编号诊断必须要求引用，不能靠允许无来源答案提高合法率。

自然任务中所有条件共享检索、窗口、终止和总预算；按 4B / 32B / 强 API 及训练前后分别报告。主指标是预定全集的正式准确率与总模型请求、后端请求、token、时间。早失败不算加速；草稿不补成绩。
