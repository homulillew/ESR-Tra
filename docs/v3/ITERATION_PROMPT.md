# ESR v3 后续调试、测试与迭代闭环 Prompt

将下文作为后续编程/研究 agent 的任务提示。它面向代码工作会话，不进入被测 policy 或 auditor 的系统提示，不把开发诊断、测试答案或本文件注入研究模型。

---

## 你的任务与范围

你接手 `homulillew/ESR-Tra` 的独立 ESR v3 分支。先读取 `docs/v3/ANALYSIS.md`、`DESIGN.md`、`VALIDATION.md` 和 `src/esr_harness_v3`、`tests/harness_v3`。核对当前分支与 HEAD，不假定当前版本等于某次对话里的提交。旧 `esr_harness` 与 `esr_grpo` 是兼容/历史入口，不静默迁移。

目标是提高正式正确完成、减少模型维护负担与总调用成本。不得用更少提交、更早失败、更多 supported、更高 schema 合法率、草稿命中 gold 或删掉失败局来代替这个目标。

按 **定位失败 → 建立反例 → 一个最小机制 → 冻结契约 → 验证 → 决定保留/回退** 工作。不要看到一篇新论文就添加一个新 agent。每次改动必须能指出真实失败或明确合成反例。

## 不能破坏的默认语义

模型侧六工具名称保持稳定。add 新建不填 c ID；revise 明选已有项；refs 中的 o 是原文，c 是版本化前提；this 仅指本次请求明确呈现并冻结的唯一原文。省略来源不表示使用 this，也不继承旧答案来源。

不要模糊纠号、c/o 同号互换、自动补引用、从自由思考里捞答案或把任意自然语言名称当唯一数据库键。source provenance、语义支持、当前可见和因果贡献必须分别记录。

不用全档案登记/清空 pending 来卡住研究。不要求每页写 finding 或每题审核；focus 不作执行许可。未采用材料仍保留，可恢复；已知冲突不能因删引用就消失。没识别出的反证是能力边界，不假装程序都知道。

真正的解释修订可以使已声明下游失效；独立事实和原文保留。审核意见不自动成为客观真相；未知不当作错误。要求变了而旧 finding 没重写时，旧解释不可冒充新要求的依据。

审核必须绑定准确答案包；审 A 不替 B 背书，局部通过不当整体通过，空/缺项审核不能自动通过。verify 是反馈边界；启动审核要给后续策略至少留一次反应预算。目标字段没改就是没改，不能因全局版本增加就算修复。

## 阶段 0：只读盘点与实验登记

先执行 `git status --short`、`git rev-parse HEAD`，读取当前改动。不要覆盖现有未提交内容，不强推、不重置旧实验。不直接向 main 提交；在已授权开发分支或新工作分支修改。

记录一个实验 manifest，至少含：基线提交、候选提交或补丁摘要、协议与 prompt 哈希、模型请求名与实际返回标识、tokenizer/模板、检索索引指纹、schema 哈希、题目 ID 与 split、重复次数、采样设置、所有预算与停止规则、待检验假设、主要指标及保留/回退规则。

**缺少用户明确的付费/远程执行授权、总请求上限或有效凭证时，只做离线阶段。** 不探测可用密钥、不从历史脚本复制秘密、不自动切换到其他收费模型。凭证仅从明确环境变量读取，不打印。

## 阶段 1：机械契约验收

安装项目后，先运行：

```bash
python -m pip install -e '.[test]'
python -m pytest tests/harness_v3 -q
python scripts/validate_v3.py --output /private/validation/new-run
python -m pytest tests/harness_v2 tests/harness_v3 -q
```

最后一条是旧兼容+新协议联合回归，必须区分实际执行与环境缺失，不能把仅 v3 的通过数写成全仓通过。无网络离线机可使用现有环境，不擅自下载大模型。

出现失败，保存第一次失败输出、最小输入、真实参数和状态前后差异。先判定：测试本身错误、旧环境问题、代码 bug、契约不完整，还是模型行为问题。只修协议或代码能确定的问题，不通过弱化来源规则让断言通过。

关键回归必须覆盖：

| 场景 | 必须成立 |
|---|---|
| 合法 c0 曾被 schema 污染拒绝的历史 | 新 schema 对象不交叉污染；旧污染数据不用于模型能力统计 |
| add 里猜 c 编号 | 明确拒绝，不隐式变成 revise |
| 多页或失败阅读 | 不从最后一个结果/裁剪结果推断 this |
| 同响应先读新页再使用 this | 仍绑定生成该决定时的原文 |
| pure repair 重呈现旧原文 | this 可以按新请求再次明确绑定，不靠运行时 latest |
| c/o/ref 合法但语义错绑 | 不能被形式通过掩盖，需要后续语义测试 |
| 新观察、新 claim、新 cursor 未交付 | 不允许猜测使用 |
| 同事务修改两个已有节点 | 依赖提案版本，失败全回滚 |
| 来源新增、移除、A-B-A、退休重建 | 不回填过去来源，不倒退解释版本，不复用退休 ID |
| 旧前提变化 | 下游旧解释退出，独立事实保留 |
| 回读未登记材料、focus=null | 路径可达，不重建清账门槛 |
| 历史查询 | 能定位旧搜索/备注，类型不晋升为原文 |
| 审 A 交 B、换引号、clear draft | 不继承错误审核，不洗掉历史意见 |
| 审核缺项/跨 claim 引文/格式失败 | 有界失败，不生成虚假事实 gap |
| correct feedback 后只改 focus | 明确 answer 未变，不算修复 |
| 审核用尽预算 | 启动前保留反应，不自动扩额度 |
| 原生多调用 | 每项有回执，不静默截断、不悬空配对 |
| SQLite/进程中断 | 哈希和 head 检查，只读回放，不重复未知完成的外部动作 |
| RL 导出缺 tokens/logprobs/spans | rl_ready=false 或 require-rl 拒绝，不重 tokenize 猜造 |

保持正反对照：合法幂等更新不能全部禁止；旧事实可能仍成立；审核也可能错误；简单题可能无需任何状态操作。

## 阶段 2：本地协议往返与部署接口校验

先跑本地 HTTP fixture，核对 policy 原生 tool_calls 与 tool 回执、检索 /retrieve 与 /get_doc、全部请求计数、实际 provider 参数和秘密不进入日志。

真实服务联通只有在授权后执行，使用合成问题、不含 benchmark gold。先核对 tokenizer 的 chat template、函数 schema 是否被接受、模型是否返回原生调用、max_tokens 的含义及上下文计数单位。byte_counter 不是 token，不得用离线字节预算冒充服务端上下文窗口。

服务端若是 Lanz/Anthropic 而非 OpenAI-compatible，不给完整系统增加自由文本自动修理器。新增一个独立适配器，保留所有内容块和原始调用 ID，再用共同协议测试。不得只提取第一个 JSON/第一个工具。

任何未知 usage 继续占请求额度；固定且有界地处理服务失败。不得在配额错误后换账号、换模型或循环重试。

## 阶段 3：固定真实前缀的机制实验

读取被冻结的失败前缀，保留策略当时实际收到的原文和反馈，不注入原本未交付的全文、预选正确文档或 gold。人工构造/教师补充的前缀必须单独标为机制上界，不能计自然成绩。

逐个比较，其他条件固定：

1. 原编号展示与内容邻接。
2. 旧字段分流与 add/revise+refs。
3. this 开/关；单源、多源、重复页、阅读失败分别报告。
4. 当前状态卡与状态+近期过程。
5. stale 标签与实际局部退出/修订边界。
6. 分散反馈与问题+目标字段变化并置。

一次不要替换所有因素。每个前缀预先固定样本数，不采样直到成功，不只重跑失败臂。使用一致双射重命名和列表重排，所有 schema、回执、预期引用同步更改，防止人为制造 ID bug。

记录：选择正确对象的比例、合法但错绑、未发布/未交付使用率、可用候选数、引用距离、必要引用次数、恢复请求、目标字段实际改变、最终正确完成。正确审核救回与错误审核误伤分开；更服从不代表更好。

## 阶段 4：自然任务配对

先冻结共同的检索、正文窗口、来源要求、提交契约、预算和独立 judge。首轮比较修好共同接口的基线与 v3；再逐项增加机制。不能一臂 hard 一臂可直接提交，却将差别全记成上下文收益。

4B、32B、强 API 分开，零样本与 SFT 后分开。网关返回模型变化时重新建立对应对照，不跨路由拼结果。开发集和封存确认集隔离；确认集不参与规则设计，不被论文或文档中的预选答案污染。

总成本计算 policy、auditor、格式修复、传输、后端检索、输入输出 token、缓存与完整耗时。模型请求、工具动作、后端请求、观察依赖串行轮数分别报告。

主要判据是正式答案准确率与总成本的配对结果。少提交、更早失败、草稿正确、更多 supported、检索少，都不能单独证明改善。服务错误留在原分母，同时提供清楚的基础设施分项；不以成功重跑替换失败。

预算不足以完成预定全队列时，停止并报告完成前缀与未执行清单，不挑有利结果，不擅自改重复次数。连续两项无可信净收益，停止新增在线机制，先复核失败分类。

## 阶段 5：恢复训练和 GRPO 接口

只有机械契约稳定后，构造策略自己的真实失败前缀、可用证据、简短反馈和有效续程。不要只用理想成功轨迹。保留无需记忆/无需审核、错误审核不采纳、格式局部修改、相似来源消歧等反向样例。

在真实采样端保存 token_ids、old_logprobs、精确 action_spans 与 tokenizer_identity，记录每次实际请求的 this 和 claim 快照。检查导出 `rl_ready`，禁止 decode 再 tokenize 猜对齐。

先验证均匀 GRPO，再比较有界来源调制与等稀疏度/等总权重随机定位。positive-only、优势归一化与定位机制分开消融。没进入最终 refs 的桥接搜索不自动归零；程序重曝光不算模型 read，后台失效不算模型修复。

不以 auditor supported 比例、changed 次数、新文档数作主要任务奖励。全失败组的冷启动、全成功二值组的效率排序问题分别解决，不宣称来源图自动提供信号。

## 每轮必须交付的结案记录

在 `docs/v3/iterations/<独立实验编号>.md` 写明：问题、证据、最小改动、代码位置、冻结条件、第一次失败与修复、实际测试命令和结果、全部成本、正反对照、未执行范围、keep/revert/inconclusive 决定、下一项最小可证伪假设。

同时保存机器可读 manifest、结果表、日志哈希。真实题目、provider 原始响应、凭证与完整付费轨迹默认留在 private runs，不推公共仓库。只提交代码、合成测试和脱敏统计；推送前核对 `git diff --check`、秘密扫描和旧文件是否被意外修改。

最终报告准确区分：代码已实现、机械测试通过、真实接口通过、模型行为改善、自然任务改善、训练完成。不得将任意一层代替下一层。不能承诺会在后台继续工作；在当前会话交付已完成结果与明确边界。
