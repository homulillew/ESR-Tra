# Retry20 v2 Bad Case 分类报告（harness vs 能力层）

日期：2026-09-02
原则（用户确认）：**每一类 bad_case 判「harness 可解」还是「模型能力需训练(SFT/RL)」，并给理由。**
分类判据：
- **harness**：模型行为结构卡死（search→不open/open后拿错ID/verify后换词重搜/非法死循环/服务瞬时故障无重试）——给对引导或断环就能拉出循环，不换模型、不动验证侧精度。
- **能力层**：harness 引导到位、信息充分，模型仍选错实体/答错/不收敛（如 311/776）。
- **仲裁**：看轨迹尾部每步——「被 harness 拒绝/误导了吗」→harness；「信息放开后模型选错」→能力。

## 分类细析（逐类原因 + 处置）

### A 类：harness 可优化 —— `evidence_directory coverage` 硬规则（120 实证）
- 现象：模型 open 新文档 e2 后，只想补一个 finding，但 `update_state` 要求一次覆盖全部已开文档，缺 e2 → 「coverage failed; missing=[e2]」。模型反复撞这条还 read 已登记证据、非法 open，空转。
- **判定为 harness**：这是**确定性环境规则的不透明/不友好**，不是模型智力问题。换一个更宽容的接受策略（允许增量登记已开文档，或把「已打开未登记」标成 pending 而非硬拒）就能解。
- **候选 Fix 7**：放松 coverage——允许 update_state 只登记本次新增的 evidence，已登记的可省略；或 reject 文案像 stale-break 一样点名「你还有待登记的 e2 必须写进 evidence_findings」。

### B 类：能力层 —— verify 通过却不 submit / 打满轮次不收敛（416/533）
- 现象：416 三次 verify 全 supported，但模型从没调 submit_answer；533 打满 30 轮。
- **判定为能力层**（理由）：harness 的断环、去重、服务重试都到位了，模型在信息/门控全部放行的前提下**没有做出「收尾提交」的决策**——这是策略/收敛能力，换 harness 引导救不回最终那一步。属 RL 的 credit-assignment 或 SFT 的输出策略先验问题。
- 处置：留给实验2 RL（20号已列为 RL credit assignment 正题），或需加 submit 诱导（但那有精度风险，不如先保持 verify 严格）。

## 结论（v2 全部跑完）

- **转换率 1/19 = 5.3%，两轮持平，但提交集不重合**（r1={266}, r2={661}）。266 的 win 在 r2 未复现，这在统计上是极强的「提交是随机收敛事件」证据。
- **harness 修复非无效，但属「抬升覆盖/加快收尾」而非「稳定翻盘」**：r2 多数坏例轮数下降（186/324/384/530/633/666）、661 靠 fix6b 断环从 30→27 提交。**这些是 harness 实打实的收益**，但没有把它变成「能让大部分坏例提交」的确定性开关。
- **剩余主导失败明确指向能力层**：verify 通过却不下 submit（416/661 r1）、打满 30 轮不收敛（很多条）。harness 已把能做的结构性断环都做了，**「最终收敛/提交决策」是模型能力，需 RL（credit assignment 让 verify 通过→submit 被奖励正强化）或 SFT（输出策略：verify supported 后应立即 submit）**。
- **对「冷SFT」的判断**：用户此前的评估方向正确——模型需要学会**流程纪律**（如何 open→update→verify→submit 正确衔接、如何在同一 update 里登记全部已开文档、如何 verify 通过就收尾）。这些在 harness 里能被刻成 guidance（如 fix6b），但模型**不稳定的执行**恰恰说明：单靠 harness 文案不够，需要 SFT 把这些动作顺序固化成先验权。下一轮应转向 RL（实验2，task 7-9）或用 fix6b/flow 的数据做冷 SFT 冷启动。

## 遗留可做的 harness（Fix7，非阻塞）

relax `evidence_directory coverage`（120 实证）：允许增量登记已开文档 / 文案点名待登记 ID。它能去掉一个确定的拒因、让坏例更快到 verify，但**不会让「已经不 submit」的坏例 submit**。优先级放 RL/SFT 之后。
