# STRIDE a3：12 道指定难题的自然运行、评估与轨迹分析

本批按用户指定顺序，对 q770、q778、q772、q774、q769、q775、q786、q776、q771、q788、q793、q794 各运行一次。6 题正式提交，6 次事后语义 judge 全部判对；4 题耗尽模型调用预算，2 题合法弃答，整体得分为 **6/12（50%）**。题目难度来自用户指定，不能据此把本批解释为随机抽样的难题准确率。这些题已用于开发分析，不再属于未接触的测试题。

## 1. 实验身份与运行约束

执行代码固定为发布提交 `5d7752be94a9d40aa757383d8899504bc0f81e81`。运行前核对 14 个 STRIDE 核心源文件与 Git 提交及计划中的 SHA-256；运行结束后再次核对。新增脚本负责预算登记、原始 HTTP 捕获、顺序执行、离线审计和发布，不修改核心策略、工具 schema、搜索排序或提示词。

生产检索采用 CPU SQLite FTS5（Full-Text Search 5，SQLite 全文检索模块）与 BM25 排序，索引含 100,195 个文档，分词器为 `porter unicode61`，查询词使用 OR。索引以只读方式访问；没有在线搜索、GPU 检索或重建索引。索引指纹来自元数据与索引标识，不能解释为本次重新计算完整语料字节哈希。详见 [运行前代码与索引核对](../cohort/source-index-checks.json)。

请求模型为 `EB-GLM-5.2`，实际响应标识为 `glm-5.2`，温度为 0。服务部署地址在公开包中脱敏。每题均为新建 episode，问题全文直接来自 question-only 文件，无题目专用提示、人工候选、旧题轨迹或标准答案注入。运行中没有 judge、审阅模型调用或人工干预；每个真实 HTTP 尝试先扣全局额度，自动重试为 0。

用户授权提高难题预算后，在首个真实调用前将五个上限加倍，其余配置保持一致：

| 配置 | 本批上限 |
| --- | ---: |
| 模型调用 | 64 |
| 动作 | 200 |
| 后端调用 | 120 |
| 累计输出 token | 48,000 |
| 每题时间 | 1,800 秒 |

单次输出仍为 4,096 token，每批最多 4 个工具调用，每次 search 最多 3 个查询。上下文上限 96,000、响应预留 4,096 使用 ByteCounter 计算 **UTF-8 字节**，不能当作模型 token 上下文长度。rolling 模式、最近 4 组、3 个证据窗口的 shelf、notes、recall、FINAL 保留机制等保持开启。`compiled_query_cache=false` 与运行中确实命中的原始查询精确缓存是两层不同机制。

初步选题文件中的 384 次 policy 预算，在发请求前由 [正式预算计划](../cohort/budget-plan.json) 改为 768 次 policy 加 12 次预留 judge，原文件保留用于审计。首题开始时全局已用 62 次，剩余 938 次，能够覆盖 780 次最坏情况。完整冻结配置见 [逐题计划](../cohort/plans/q770.plan.json)，所有题采用相同配置。

## 4. judge 判对与证据审阅的区别

q788 是本批最明确的差异。judge 的理由称所有条件解释准确，但它没有读取被引用的证据，因此这段理由不能代替来源核验。原始长答案把“医院 1953 年迁入建筑、1956 年扩建”当作“医院在 1930 年后创办”，与 e2 中 1927 年前已存在的记载冲突。此外，23,000 平方米约为 247,570 平方英尺，不等于超过 400,000 平方英尺；模型并列引用另一个来源的 430,000 平方英尺而未解决冲突。Wikimapia 的附近距离也不能直接证明实际步行路线。保留原始 judge 对的标签，同时将解释标为证据审阅不通过；没有为了让两者一致而重判或改写提交。详见 [原始 judge 第 6 次结果](../judge/006.judgment.json) 与 [q788 证据逐项核对](../q788/EVIDENCE_AUDIT.md)。

q786 的正式答案只有姓名，judge 判对不代表运行正文中的生日描述或全部身份条件已经证明。R7 原文出生日期是 1956 年 9 月 28 日，结束前正文却说 9 月 4 日。早期出生证据未列入最终 refs，后来的引文还存在时间截止限制。q776 的题名由二手讣告准确引用，符合标准答案，但“已读官方期刊记录”这一要求仍未完成。这些情况应保留为答案正确但证据链不完整的开发案例。

q772、q769、q771 对所问核心事实的证据较直接，但逐条证据报告仍明确标出未核实的外围条件；不能把名称或职位正确扩展成每一个背景条件都已验证。

## 6. 可见性、工具完整性与机制边界

12 题的请求问题全文、HTTP 与 archive 的请求/响应 JSON 对应关系、native tool-call ID 顺序、动作参数与结果、下一轮实际工具回包、保存的原文证据窗口和 find 偏移均通过离线核对。没有观测到 HTTP 重试、漏记实际调用、工具结果被替换或伪造 eN 的问题。详见 [逐题机器核对](TRACE_VALIDATION.json) 及每题 INTEGRITY_CHECKS、SUPPLEMENTAL_CHECKS、TOOL_EXECUTION_LINKS 和 EVIDENCE_LIFECYCLE。

所有题均未主动调用 notes 或 recall，必须标记为 **NOT_EXERCISED**，不能评价其修复能力。find 仅在 q770 发生两次，均为大小写敏感匹配，没有测试 ignore-case 分支。shelf 恢复只在 q770、q786、q793 发生，容量驱逐次数均为 0；不能根据本批判断容量驱逐策略。

q770 的 e3 前一人物语境在 R12 后离开请求，而 e4 候选片段长期恢复；q793 的 R33 排除候选正文在 R34–37 可见、R38 起不可见，同一轮候选又出现，但包含 2025 年的原文 e1/e2 与题目截止条件仍可见。这支持“保存原始证据与保存当前结论、排除理由是不同问题”的机制假设，尚不能证明压缩导致错误，需要控制变量验证。q788 没有上下文压缩，仍发生明显证据矛盾；q778 的 e1 与错误回包一直可见，仍重复提交数值。这两个案例说明可见性不足不能统一解释全部失败。

## 7. 离线审计修正与验证记录

发现并修正了一处既有离线统计错误：q788 的非法 search 把 `queries` 传成字符串，旧报告用 `len()` 将其 165 个字符算成 165 条查询，得到 declared 177。按 schema 只统计合法数组后，正确 declared 为 **12**，另记 1 次非法参数形状；实际执行查询原本就是 12。旧报告完整保留为 `.before-query-count-correction.json`，新增 QUERY_ARGUMENTS_AUDIT 记录修正依据。没有改动 HTTP、episode、额度、线上实现或原模型答案。q793/q794 同样检查参数形状，均不需要修正。

离线测试为核心与采集/队列共 242 项通过、judge 4 项通过、统计修正 2 项通过，共 **248 项**。smoke、replay、diagnose、CPU 合成检索检查全部成功。judge 测试最初因 Windows 默认临时目录权限产生 4 项 setup error，改用工作区独立临时目录后通过；没有修改产品代码或产生真实模型调用。公开包保留原失败日志、成功结果及解释。q778 的数字/字符串 finish 差别另有离线重现记录。

## 8. 单一后续实验建议（未执行）

优先验证一项机制：**只增加由轨迹计算的查询重复反馈**。在模型已有控制反馈中列出本次查询此前出现次数及上一次新增文档/证据的轮次，保持工具 schema、检索、候选生成、动作权限和核心预算不变；不自动改写查询、禁止重复调用或给出标准答案。它针对 q770、q774、q775、q786、q793、q794 的长循环，不预先声称能解决 q778 的类型错误或 q788 的关系误读。

可在另行登记后，将 q770、q774 作为循环开发案例，各跑原始/反馈两个条件，每条件最多 64 次；q771、q772 作为短成功负对照，每条件最多 16 次，共最多 320 次 policy，加 8 次 judge 为 328 次，低于当前剩余 449 次。只改一个反馈机制，同题两条件采用相同预算；记录正式正确率、首次新增证据轮次、重复查询率、无新增证据的最长连续轮数、输入字节与 token、是否出现读原文动作，以及原有短成功是否退化。样本量很小且已暴露，结论限于开发机制验证。本批没有执行、预占或付费试跑这个建议。

## 9. 公开包的完整性与阅读顺序

先读本报告和 [逐题评分](cases.json)，再进入每题 INTERACTION_ANALYSIS 与 EVIDENCE_AUDIT，需要核验时打开 ROUND_ANALYSIS 或 rounds 中的某轮。每轮链接对应原始 HTTP 请求与响应；documents/evidence 目录提供与 archive 完全相同的 UTF-8 文本。大型 FULL_INTERACTION 文件仍完整保留，逐轮视图方便网页和 GPT 分段读取，不替代原始数据。

公开 archive 只脱敏模型部署元数据，并重算事件哈希链；内容寻址对象、模型消息、工具结果、文档和证据原文均保持相同。原始与公开 head 的映射见 [ARCHIVE_HEAD_MAP](../ARCHIVE_HEAD_MAP.json)。外部 judge 标签绑定公开 head，原始 head 保留在映射表。所有 HTTP `.body` 保持逐字节一致。SOURCE_FILE_HASHES 记录私有封存来源，PUBLICATION_FILES 记录文件变换；根 MANIFEST 记录最终公开文件字节，重验公开包应使用根 MANIFEST，不能直接将脱敏后的文件与私有来源哈希比较。

逐题报告在 gold/judge 前封存，其中 formal_correct 为 null 和“待 judge”是当时真实状态；最终外部评分集中放在 evaluation 与 judge，避免倒改历史。公开包不包含凭据、全量 gold/语料、生产索引、虚拟环境或其他会话的预算数据库。
