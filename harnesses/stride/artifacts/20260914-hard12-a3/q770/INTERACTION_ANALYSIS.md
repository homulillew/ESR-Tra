# q770：候选人物错接后持续重复检索，64 轮未提交

本题要求用研究组成立时间、合编书籍、会议、文章和博士研究对象等线索识别人名。自然运行使用 64 次模型请求，以 `model_budget` 结束，正式答案为空。模型散文中的 Rod Mengham 只是候选，不能替换为正式提交。所有题目的自然运行结束后，独立评估文件才会记录标准答案；本报告写作时没有读取标准答案。

## 1. 执行身份和预算

核心源码逐字节匹配 release `5d7752be94a9d40aa757383d8899504bc0f81e81`，包版本 `0.1.0a3`，协议 `stride-search-3`。请求模型 `EB-GLM-5.2`，所有实际返回均为 `glm-5.2`，temperature=0。一次自然运行，无重试、提示词修订、候选注入或基准答案输入。完整 Config、源码哈希及环境身份见 [manifest.json](manifest.json)。

本批每题上限为 64 次模型调用、200 个动作、120 次后端调用、48,000 输出 token、1,800 秒。上下文为 96,000 UTF-8 字节，响应预留为 4,096 字节，单次模型输出参数为 4,096 token。CPU SQLite FTS5 使用既有生产索引，OR 提词和 BM25 排序保持不变；compiled_query_cache=False。精确原始查询缓存仍是正常运行机制，与关闭的编译查询缓存不同。

## 2. 逐轮推演

| 轮次 | 实际动作及变化 | 审阅结论 |
|---|---|---|
| 1 | 三条宽查询返回 Cambridge 教师介绍 d10、2019 年会议汇总 d7 等 | 有候选导航，没有可引用原文 |
| 2 | read d10、d7，得到各自开头 e1、e2 | ref 合法；d10 开头没有命中召集人段落，属于同页选错范围 |
| 3–4 | find convenor 得到位置 9308，read 9200:9800 生成 e3 | 偏移正确；窗口从人物介绍中间开始，没有人物姓名 |
| 5 | 为寻找姓名向后读 9800:10600，得到下一位教师 Rod Mengham 的介绍 e4 | 窗口跨人物边界；向前补读才能核实前一段主体，但模型没有这样做 |
| 6 | 模型说已找到 Rod Mengham 是该 symposium convenor，围绕其姓名检索 | 把前一人物的职务接到后一人物；这是模型的语义归属错误 |
| 7–9 | read d15 开头，find ROD MENGHAM，再 read 对应段落生成 e6 | 导航成功，e6 证实部分职业和著述信息，没有补齐本题六组条件 |

| 13–16 | 同一组六条查询重复四轮 | 缓存命中与此前收到的导航标记已经在实际工具回执中出现 |
| 17–63 | 固定六条查询持续重复，不再阅读或更换候选 | 没有形成新的证据窗口；重复模型调用继续消耗额度 |
| 64 | 收到 FINAL 请求后仍提出两次 search | 两个动作按合同返回 `final_only`，executed=false；未调用 finish，最后以 model_budget 结束 |

每一轮的模型原话、实际参数、查询集合比较、原文可见性均逐轮保存在 [ROUND_ANALYSIS.md](ROUND_ANALYSIS.md)。该文件保留全部 64 轮，表中的合并只用于解释相同阶段。

## 3. 工具执行与终止

120 个原生工具调用均有对应的动作执行记录，118 个真正执行；最后两个 search 被 FINAL 合同拒绝。动作类别计数包含被拒绝的调用：search 112、read 6、find 2。330 条查询真正进入 query_execution，模型声明的 336 条中最后 6 条未执行。不能把最后这 6 条算成 CPU 检索，也不能把合同拒绝解释为工具丢失。

原生调用 ID、顺序、名称、参数、工具结果和下一实际请求回执的核对见 [TOOL_INTEGRITY.csv](TOOL_INTEGRITY.csv)、[POSTHOC_CHECKS.json](POSTHOC_CHECKS.json) 和 [SUPPLEMENTAL_CHECKS.json](SUPPLEMENTAL_CHECKS.json)。本局没有 result_withheld。第 64 轮确实发出 FINAL 请求；最后的拒绝回执留在归档中，因为额度耗尽没有下一次请求，不能声称模型已看到该回执。

## 4. CPU 查询和重复

330 次 query_execution 中 297 次命中精确查询缓存；实际执行 33 次 CPU search，加 3 次 get_document，共 36 次后端调用。编译等价键重复 297 次，结果集合与此前完全相同的查询有 309 次。原始查询中没有引号、site: 或大写 AND/OR。

第 17–63 轮固定六条查询，重复不仅体现在字符串和编译结果，还伴随零新增原文和同一候选持续不变。仍不能据此证明索引没有答案：本局没有系统穷举语料，检索失败可能来自候选偏离和检索词选择。全部原始查询、实际 OR 表达式、top_k、结果文档和缓存状态见 [QUERY_EXECUTION.csv](QUERY_EXECUTION.csv)。

## 5. 原文连续性和 shelf

e1、e2 在第 3 轮首次送达，e3 在第 5 轮，e4 在第 6 轮，e5 在第 8 轮，e6 在第 10 轮；都取得了 delivery_ack。e1–e3 在第 13 轮退出实际输入。e4 从第 13 轮由 shelf 持续恢复，e5 也从第 13 轮恢复，e6 从第 15 轮恢复；最后仍可见 e4、e5、e6。

50 次请求发生压缩，52 次请求恢复 shelf，共恢复 154 个窗口，容量驱逐为 0。直接加入 shelf 的序列化请求增量累计 368,024 字节。该数值是实际序列化差值，不是 provider token，也不是消融实验测得的成本。

shelf 确实保持了候选人物原文，但 e5 是颁奖新闻的通用开头，对本题未解决条件没有帮助。最初召集人段落 e3 已退出；候选姓名段落 e4 则持续可见。可观察到这种不对称保留与错误候选持续出现，尚不能证明 shelf 导致锚定，因为没有对照运行。

## 6. 错页、错范围和人物归属

本局关键错误不是非法 ID。d10 是真实返回并成功打开的页面，find 和 read 的偏移都准确。e3 对应的人物姓名位于更早的段落，模型向后读到了下一位人物，并在第 6 轮将其当作前一段的主体。

只读复核已保存的 d10 快照 8400:10000 后，可以明确看到前一段标题是 **DR LEO MELLOR**，下一段标题才是 **DR ROD MENGHAM**。这一邻接内容另存为 `POSTHOC_EXPANDED_EVIDENCE.json`，标记为 `posthoc_expanded_evidence`，没有输入 policy，也没有回填为正式依据。该复核确认了人物错接，不用于确定本题标准答案。

## 7. notes、recall、find

notes 与 recall 均为 NOT_EXERCISED；因此未检验 recall_navigation 或 centered_recall。两次 find 分别定位 convenor 和 ROD MENGHAM，默认大小写敏感，匹配位置均与保存快照一致；ignore_case 扩展没有触发。

## 8. 正式引用审阅

本局没有 finish，也没有正式 refs，正式断言审阅为 NOT_APPLICABLE。不能把散文里的 e4/e6 视为正式引用。候选推演审阅与正式判分严格区分，具体断言见 [EVIDENCE_AUDIT.md](EVIDENCE_AUDIT.md)。

## 9. 成本

自然运行 318.405 秒；64 次 HTTP 耗时合计 281.199 秒，CPU 后端耗时 29.222 秒。实际请求正文共 4,865,091 字节。provider 报告输入 1,212,229 token、输出 11,744 token、缓存读取 1,004,288 token；缓存读取包含在输入中，不重复相加。缓存写入字段缺失，归一化后为 unknown，不能把原报告空和的 0 当作已知值。没有价格依据，货币成本为 unknown。

## 10. 描述性对照

本题在第 32 轮之后仍有 32 次请求机会，但没有新增原文或正式提交。只能说明该轨迹中的额外预算没有使策略跳出重复；不能代替 32/64 预算对照，也不能推断其他难题增加预算都无效。与此前 q26、q72、q661 的题目内容不同，不作准确率因果比较。

## 11. 问题分类

- 已核验代码 bug：本局未发现；动作拒绝、缓存和原文保留均有可解释的合同记录。
- 按设计执行但成本可能不合算：重复缓存查询仍反复消耗模型调用；shelf 持续保留低相关窗口。
- 模型选择或解释错误：人物段落错接、长期固定候选、收到 FINAL 控制仍调用 search。
- 后端或语料不足：未建立；本局查询没有找到所需材料不能证明材料不存在。
- 尚无因果证据：shelf 是否加重候选锚定、低温是否造成重复，需要独立实验。
