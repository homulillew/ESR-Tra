# q775：不断说要看页面，实际只搜索，64 轮未提交

本题要求由两本书的出版/获奖关系和两位作者的成长城市、出生城市识别城市。64 次模型请求后以 `model_budget` 结束，正式答案为空。全程没有 read。模型口头多次说要直接查看 Wikipedia 页面，原生动作始终是 search。此报告在读取标准答案前写成。

## 1. 执行身份与预算

核心 release `5d7752be94a9d40aa757383d8899504bc0f81e81`、包 `0.1.0a3`、协议 `stride-search-3`；EB-GLM-5.2/glm-5.2、temperature=0。只读 CPU SQLite FTS5 生产索引，OR/BM25 不变，compiled_query_cache=False。完整 Config 见 manifest.json。上限为 64 模型调用、200 动作、120 后端调用、48,000 输出 token、1,800 秒；上下文 96,000 字节、响应预留 4,096 字节、单次输出 4,096 token。一次自然运行，无提示修订或重跑。

## 3. 工具落地

128 个原生调用、126 个执行动作，全部为 search；最后 2 个拒绝执行。声明 383 条查询，377 条进入 query_execution，最后 6 条未执行。没有工具丢失或参数自动修改，没有 result_withheld。原生 ID、顺序、参数和下一请求回执的对应均可核对，最后拒绝回执因为没有后续请求而未送达。第 64 轮确实收到 FINAL 控制。

## 4. CPU 查询与导航

377 条执行记录中 317 条精确缓存命中，真正 CPU search=60；预算上限是 120，所以结束原因不是后端预算耗尽。编译等价重复 317 次，结果集合重复 322 次。总共出现 126 个不同 dN，没有任何一个转成原文。

例如第 11 轮 `International Booker Prize Wikipedia` 实际编译为四个词 OR，返回 d12 的 **Booker Prize** 页面及其他作者条目，并非被模型实际打开的 International Booker 页面。`David Diop born Paris Wikipedia` 的结果还包括 Lupin、非洲足球、电影和历史条目，说明这些普通词项会把不同实体带入结果。d98/d99 等新闻导航确实出现 David Diop 的获奖线索，但模型没有 read。不能将导航噪声直接归为“语料无答案”，也不能把散文的“看实际页面”计作阅读。

未使用引号、site: 或大写布尔操作符。检索完整列表见 QUERY_EXECUTION.csv。
