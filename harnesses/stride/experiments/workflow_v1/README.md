# Workflow v1 有限在线验收

本实验验证正式 CLI 中的 `gap-workflow-v1`。远程基底为 `266772cebd296c4f9a7cb861c562f639ed3b0190`，包版本为 `0.1.0a3`，答案合同显式设置为 `string-integer-v1`。唯一产品修正是恢复 CLI 的 token 预留检查和 cohort 基础设施失败退出码；本轮不调整工作流提示、检索或重复检测算法。

运行顺序固定为 q775 legacy、q775 full、q774 full、q774 legacy（每槽最多 16 次策略请求），随后 q771 full、q778 full（每槽最多 4 次）。每槽为空 episode，正式 `Harness.run` 自然执行。`legacy` 和 `full` 使用 `WorkflowConfig.profile`，同题两臂其他配置完全一致。`PLAN.json` 记录所有 Config 字段、模型和 CPU 索引身份、原题哈希、源码哈希及验收记录哈希。

每槽使用新的真实单调时钟，时间上限 600 秒。HTTP 超时取 180 秒与本槽剩余时间的较小值；CPU 后端沿用只读索引及原查询超时。上下文容量 96000、输出预留 4096 的单位均为 UTF-8 字节，单请求输出上限 4096 的单位为模型 token。时间在动作边界检查，已开始的后端操作可能稍晚结束。

策略最多 72 次，所有策略完成并封存后，仅对 submitted 的完整原答案调用项目 judge，最多 6 次。judge 使用同一部署的独立后处理请求，不进入策略循环。共享持久总账总上限 80 次，每次发送前原子占账，失败与未知状态同样占额；计划最多 78 次，余下两次不用于重试。任务预算耗尽继续下一槽，基础设施、身份、完整性或预算异常停止队列。标准答案文件只在策略封存后读取。

本地 transport fixture 验证正式 CLI、原始 HTTP 捕获、SQLite 回放、文本导出、封存和占账边界，不代表模型效果。在线启动前提交实现、测试和计划；首次发送后保持源码与提示不变，不重跑失败槽。完整 HTTP、SQLite、逐轮事件、全部对象、证据窗口及原始回答均保存在新的私有 `runs/` 目录；公开报告仅发布必要摘要和哈希。旧轨迹、旧实验报告与正式 6/12 保持原样。

执行入口为 `validate_live.py prepare` 和 `validate_live.py run`。前者核对原始私有 manifest、已发布原题、索引并生成冻结计划；后者核对冻结源码和共享额度后自动执行两类请求。凭证由进程环境提供，路径由命令参数提供，报告不包含部署地址或凭证。
