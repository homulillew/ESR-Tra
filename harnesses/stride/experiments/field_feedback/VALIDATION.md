## 合法性与诊断

[接受集合比较](report/ACCEPTANCE_DIFF.json) 覆盖 1,134 个合成参数组合，新旧均接受 5 个、拒绝 1,129 个，差异为空。这个有限集合本身不构成对所有 JSON 的数学证明；实现层面还保持了原解析器、原 schema、原 jsonschema 校验、整数预检查和原执行检查，只在原本抛出校验错误时选择 message 格式。

新增测试覆盖：数字答案、合法字面字符串、refs 类型与元素类型、空白答案、缺失字段、额外字段、回答/弃答混合、合法弃答、未交付来源、严格解析错误、嵌套 oneOf/anyOf、无唯一相关分支、开放属性分支、多个合法分支重叠、超长实例和异常属性名。search.queries 的字符串错误定位到 `/queries`；它仅用于离线对照，没有重跑 q788。

新消息只含字段路径、规则、预期类型或约束以及实际类型。消息最多 420 字符、最多 3 条诊断，路径最多 64 字符，递归诊断还设有深度和节点上限。异常字段名按 JSON Pointer 转义后以 JSON 字符串呈现；过长字段仅展示明确标记的祖先指针，不回显答案值或任意长实例。多分支错误不会按“最少错误数”默认选择意图，也不会建议删除字段以通过校验。

两条 SCRIPTED 本地 HTTP 往返都实际执行了：检索合成记录 → 阅读 → 拒绝数字答案 → 脚本给出合法字符串 → 正式提交。错误回执保留其独立原生 ID，下一请求中的工具 message 与 control.feedback.message 相同，原 arguments 保持不变。脚本示例的答案字符、前后空白、引号和换行均未被引擎改写。该验证只证明接口可达，不是模型自主修复结果。

## 前缀与输入差分

R1–R4 真实记录通过离线配对重放，未重新检索，也未给重放模型后续响应。A 臂 79 个事件除重新测量的耗时外完全对应；R1–R4 和原 R5 serializer 字节一致。恢复后的 25 个文档、1 个证据窗口、6 个查询缓存项，以及全部交付/导航状态和计数都参与核验。

B 臂只在前缀最后一个参数错误上启用字段消息。首个续程请求差分仅为：

- `/messages/9/content` 内部 JSON 的 `/message`；
- `/messages/10/content` 内部控制 JSON 的 `/feedback/message`。

两处从旧根路径消息变为 `finish: pointer "/answer" expected type string; received type integer.`。原问题、模型原始 ID/arguments、所有历史消息和证据、工具 schema、预算、phase、温度和 tool_choice 均保持相同。测试另外确认：增加额外系统指令会使差分白名单失败；重放适配器不能拿历史后缀或未知检索结果代替新行动。

运行状态中的允许变化限于最后一个组的对应回执、该组的内容哈希和 feedback.message。其余状态字段逐一相同，公开 [前缀报告](report/PREFIX_REPLAY_CHECK.json) 保存字段哈希和剩余额度，原状态与准备好的 HTTP 正文只保存在新的本地目录。

## 精确阻塞与未执行项

总体前缀状态为 **BLOCKED_PREFIX_RECONSTRUCTION**：原采集器没有记录 R4 边界的单调时钟耗时，无法精确恢复原 1,800 秒时间余额。UTC 间隔 18.538888 秒不能代替原 clock 差值，最终终态耗时也不能用于反推此前每个未记录的引擎处理间隔。本轮没有用近似值解锁续程。
