# 保留工具调用与原文、删除历史散文：证据与单变量试验

检索日期：2026-09-15。实际检索并打开论文原文。未读取其他八题、gold或当前未封存轨迹；未调用GLM，未修改产品或跟踪文件。这里讨论历史输入投影，不改变模型正在生成的一次响应。

## 结论

已有一手干预证明：某些中间轮推理可以删除，错误旧推理也可能干扰后续证据判断。但没有找到“冻结API搜索Agent中无条件删除所有历史assistant散文、保留tool_calls与工具原文”普遍减少重复且提高准确率的直接实验证据。相反，全删推理存在明显负结果。因此可以做有界、确定性的中间历史散文删除试验，不能宣传成已经验证的脱困方法。

已封存响应内4096 token复读发生在一次生成内部。下一请求才应用的历史删除无法直接截断这次生成；若length按规则终止episode，就没有下一请求。它只能检验更早的历史散文是否增加后续复读倾向。不能把输出截断恢复、改采样参数和历史投影一起加入同一试验。

## 一手证据

### Agent-Omit：最接近的单轮删除后继续实验

[Agent-Omit: Training Efficient LLM Agents for Adaptive Thought and Observation Omission via Agentic Reinforcement Learning](https://arxiv.org/html/2602.04284v1)，2026-02-04。

§3.2固定已生成前缀，删除某轮thought或observation，再继续生成，对照准确率与总token。Qwen3-8B/WebShop中，删除中间推理可同时改善两者；删除最初或临近结束的推理会损害准确率，并可能产生更多推理来恢复丢失信息。此消融提供推理历史可以有选择省略的因果依据，尚非FTS搜索或GLM复现。

完整Agent-Omit采用监督微调与强化学习，训练时通过后续轨迹正确性识别可删除轮次。不能在部署时用gold挑删除位置，也不能把训练后的整体收益说成免训练固定规则收益。图3为曲线，本笔记不从图猜测精确百分点。

### SPARE：保留工具与证据、删推理的直接正负结果

[Buried in Textual Debt: Context Pruning with Visual Evidence Preservation for MLLM Agents](https://arxiv.org/html/2608.22963v1)，2026-08-24。

附录C.1固定问题、图像、tool_calls、动作、工具观测，只改保留推理。构造冲突子集上，定向SPARE使8B旧答案复制36.36→9.09，随机删一段仅降至27.27；自由回答准确率没有变化。这个小规模诊断支持“旧猜测可能干扰证据”，不证明一般搜索脱困。

表1全删推理：Qwen3-VL-30B平均准确率44.30→35.22；8B 54.27→50.12。定向SPARE在30B提高到49.19，8B仍降到53.47。附录B.2每次剪枝需生成摘要、两次forward replay，使用KL分数；还有微调摘要器变体。无需额外模型不等于无需额外推理成本，当前API/CPU harness不可直接复现分布级操作。

### Observation Masking不是删除assistant散文

[The Complexity Trap](https://arxiv.org/html/2508.21433v1)，2025-08-29：主要删除旧工具观测，保留动作及推理，与本提案方向相反。SWE-agent里遮蔽与LLM摘要表现接近且更省；摘要在部分模型上延长轨迹，加入critic未提高解题率；OpenHands小样本反而偏向摘要。它支持用简单确定规则作对照，但不支持“删推理保原文”的效果。

[Masking Stale Observations Helps Search Agents—Until It Doesn't](https://arxiv.org/html/2606.00408v1)，2026-05-29：直接覆盖BrowseComp-Plus和BM25，但仍保留推理、删除观测。表1中BM25/Qwen3.5-4B准确率23.6→29.9，同时每题工具调用增加48.8次；GAIA/GPT-OSS-120B准确率72.8→68.0。成本与准确率不保证同时改善。§5注意力分析显示推理获得较高注意力；这是相关性，不足以证明这些推理应删除或保留。

### 整体重建不是保留原文的历史投影

[DeepSeek-V3.2 §4.4](https://arxiv.org/html/2512.02556v1)，2025-12-01：128K上下文用量超过80%后比较摘要、删除75%历史、全部重置。摘要平均延长到364步，BrowseComp约60.2；全重置67.6且步数较少。该实验通过扩展可执行步数获得收益，不能推导固定16请求内只删除散文有利。

[IterResearch算法1](https://arxiv.org/html/2511.07327v1)，2025-11-10：原问题、持续报告、最近工具交互重建上下文，报告保留结论与计划但不是原始证据。免训练prompting有正结果，既有笔记已列；其报告生成及历史替换同时变化，无法隔离删除旧散文的贡献。

## 候选单变量：中间已完成轮次的散文投影

若后续决定试验，建议先采用以下唯一变动，而非摘要器：

1. 只处理已经完成、包含tool_calls并有完整结果组的assistant消息。
2. 保留episode最初一个完整动作组和最新一个完整动作组的assistant.content；对两者之间的完整组，将assistant.content设为null。tool_calls的ID、名字、arguments及所有工具消息逐字保留。
3. 不修改HTTP原始归档、证据窗口、原题、system、控制状态、notes、未提交响应修复文本、当前输出及finish结果。投影在实际请求构建时对副本进行，容量计量使用投影后的真实wire。
4. 不增加解释提示、不新增工具、模型请求、摘要或语义评分；不根据题号、答案、候选名或离线judge选择删除位置。

首轮采用保留首轮及最新轮，是受到Agent-Omit位置负结果启发的启发式，并非论文已证明的最优窗口。若初始错误锚定恰在首轮，保留它可能继续有害；必须把这点当作可能失败原因。也不要先同时试多个窗口再从同一开发题选最高值。

## 与LLM摘要的差异

| 维度 | 确定性散文投影 | LLM摘要重建 |
|---|---|---|
| 被改变的信息 | 指定历史assistant.content | 通常同时重写推理、动作描述与证据 |
| 工具原文 | 当前保留组内逐字不变 | 通常只剩摘要，需要另存原文 |
| 额外模型请求 | 0 | 独立摘要器通常至少1次/事件；同请求报告则增加输出 |
| 新错误来源 | 丢失排除理由、关系解释与计划 | 以上风险加错误概括、遗漏、把猜测写成事实 |
| 可直接检验 | 输入差异精确定位到字段 | 需同时审核摘要忠实度 |

## 如何验证而不混淆收益

- 先离线构造有多轮原文及错误结果的轨迹：验证投影幂等、原对象未改、工具ID配对不变、原文与引用范围不变、首轮/最新轮/FINAL处理按冻结规则，原始归档可回放。
- 在线比较同配置baseline与仅投影，保持总请求、后端、采样、答案合同一致。第一次请求应相同；进入至少三组历史后才产生差异。
- 同时记录答案正确率、弃答/预算/length终止、每响应重复片段比率、相同查询率、真正新读取窗口、模型请求、输入/输出/cache token和时延。重复片段统计仅用于后处理，不参与实时策略。
- 输入变短不等于账单更低：修改早期消息可能破坏前缀缓存，增加未缓存输入。输出变长、重新推理或新增工具调用也可能抵消节约。
- 原文完全保留仍可能丢失“这条来源为何排除候选”的唯一记录；工具arguments只能恢复查过什么，不能完整恢复为什么查、已经排除了什么。
- 如果当前上下文主要由工具结果占据，删除散文节省可能很小。若已读证据不足，投影也不会凭空提升召回。不能把更短输入或更少复读直接当成搜索质量提升。

这项实验改变后续上下文中的历史呈现；它不等价于要求模型不思考、降低推理预算，也不提供对响应内部无限复读的执行保证。
