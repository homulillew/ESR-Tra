# 词覆盖重排的相关研究与证据边界

核查日期：2026-09-16。本文只总结原论文，不使用实验题目、答案或判分记录。

待测规则使用同一 CPU 和 SQLite FTS5 索引：先以 OR/BM25 取得20个候选，再按查询中不同词在作为标题存储的 URL 及完整 snippet 中的精确词覆盖数重排，返回原 top_k。该规则不增加辅助模型或新索引，但改变了检索排序；同硬件、同索引和相同策略请求上限不代表检索算法或计算成本相同。

下列论文支持研究检索排序这一变量，**没有直接验证上述精确词覆盖规则，也没有证明它在最多16次策略请求的相同预算下提高答案准确率**。

## 三篇原论文

| 论文与版本 | 实际比较及结果 | 成本、负结果与适用边界 |
|---|---|---|
| [Revisiting Text Ranking in Deep Research](https://arxiv.org/html/2602.21456v1)，2026-02-25，§3.2.7、表7/8 | BrowseComp-Plus 中，gpt-oss-20b 的全文档 BM25 参数由 k1=0.9、b=0.4 改为 k1=3.8、b=0.87，准确率0.259→0.443，平均搜索32.22→28.66。BM25 加 monoT5、重排深度50时准确率0.689，平均搜索27.57。 | 最多100轮，并非16次总模型请求。monoT5 是额外3B模型。作者部分 BM25 调参使用全部评测查询，并明确警告没有独立验证集：存在评测集调参泄漏风险，不能将该增益视为无偏的独立泛化估计。更强推理重排也会误解关键词间关系。Pyserini 参数和神经评分不等价于 FTS5 词覆盖计数。 |

| [When More Reformulations Hurt: Avoiding Drift using Ranker Feedback](https://arxiv.org/html/2605.00560v1)，2026-05-01，§4.3/5.2 | ReformIR 用原查询作为重排判断基准，再根据排序反馈调整改写查询的权重；在固定候选预算下比较 TREC DL 检索指标。默认5种改写，每种独立检索最多100个候选。 | 包含改写 LLM、额外检索和 MonoT5 评分。GenQR 的改写数从3增至50时效果下降，50条时甚至低于原查询 BM25→MonoT5。候选或改写增多不保证收益；该对照没有隔离确定性词覆盖重排，也不是 BrowseComp 端到端实验。 |

## 当前规则能从论文中获得什么依据

这些结果表明，检索参数、候选组织和排序方式可能显著影响下游搜索，也可能引入查询漂移或关系误判。它们提供研究动机，不能提供当前规则的预期增益数值。论文观察到查询包含引号或关键词，也不能证明实体短语约束、AND/OR 混合或精确词覆盖已经经过有效性验证。

当前规则只计算词是否出现，不验证词之间的主体、时间或数量关系。高覆盖候选可能只是把多个词并列提到；相关页面也可能使用别名、词形变化或同义表达而被降序。这是规则本身的适用限制，不能用神经重排的实验增益抵消。

候选池扩至20可能增加后端取回、snippet处理、局部评分和排序成本，即使最终返回条数不变、没有新增模型请求。若原候选池较小，新对照同时改变候选池大小与排序规则；整体结果不能归为覆盖评分的独立贡献。应分别记录策略请求、后端检索及候选处理成本；现有论文未给出该组合在相同 CPU、索引、候选池和16请求预算下的直接正向证据。
