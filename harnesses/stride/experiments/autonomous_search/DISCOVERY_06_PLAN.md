# 第六轮：一次关系审阅请求

本轮检验 `relation-review-once-v1`。连续三个已完成轮次成功执行搜索、没有新的原文窗口交付，且不在 FINAL、至少剩余四次模型请求时，用一次关系审阅请求替代下一次普通决策。每个 episode 最多一次，不额外增加模型请求。没有已读原文也可以触发，此时只能指出尚未证实的关系，不能宣称完成事实核验。

该请求保留原 SYSTEM 与工作流合同，追加通用任务：从原题选择一条识别关系，核对主体、时间、数量、单位和比较边界；仅用本次可见原文区分支持、矛盾和尚未证实，选择正常的 search/read/find 动作取得所缺证据。原题的歧义和单位原样保留，不自动改题。指令不包含题号、候选、标准答案或历史分析。短审阅文本是未经验证的模型输出，不自动写入结论或证据。

这一次请求重新组织输入：完整原题；当前容量候选历史与 shelf 已获授权的原文；search/read/find 的原始调用 ID、名称、参数和回执；真实导航、阶段、预算及来源范围。上述历史作为不可信数据包呈现，带原轮次与对象哈希，不伪造原生助手/工具配对。省略旧助手散文、提供方推理、notes、repair、feedback 和 gap 判断。其他工具只保留 ID、名称与哈希，省略其参数与回执正文。旧检索参数中的候选仍然可见，不能把本机制描述为完全清除旧假设。

只在这一次请求提供原 search/read/find schema；batch 上限及字段不变，执行器明确拒绝其他工具。保留原参数解析、来源检查、只读 CPU 检索、缓存、计量与停止规则，不强制 tool_choice，不加 strict，不自动读取或改写查询。容量检查计量实际请求，每次容量候选都重建输入。预构建不消费触发次数，正式请求归档后、发送前消费并记录规则、SYSTEM、工具、请求及输入来源哈希。下一次普通请求恢复仍被保留的原历史，并加入这次真实响应与工具结果。

设计针对已审阅开发轨迹中的具体问题：混淆奖项与作者/作品的关系，把原题条件当作候选事实，以及搜索后从未读取来源。第五轮 q775 的两臂虽然提交，但引用窗口不能支持关键推断；q774 候选在 CPU 错误处停止，不能据此形成完整准确率比较。现有独立 CPU 诊断复现了 SQLite 进度回调中断，未发现必须修复索引的证据；本轮保持原后端和超时设置，发生同类异常仍封存停队列。

论文依据见 LITERATURE_RELATION_REVIEW.md。已有研究支持把关系拆分和外部证据核查作为研究方向，也记录了核查使正确答案变错的风险；没有论文证明本轮一次请求、十六轮总预算下的具体机制有效。本轮是提前声明的局部假设，不是对论文完整方法的复现。

固定新空 episode 顺序：q775 基线→候选，q774 候选→基线，q771 基线→候选，q778 候选→基线。难题每槽最多 16 次，控制题每槽 4 次，每槽 600 秒；最多 80 次策略请求和 8 次 judge。使用原部署、实际响应模型身份、temperature=0、完整工作流及整数答案合同；唯一实验变量是这里明确列出的决策协议。所有策略封存后才读取标准答案并执行项目 judge，不把标准答案送入策略请求。

冻结前窗口已使用 224/1000 次，余额 776；沿用原持久总账，失败与未知状态发送前占额，不重试。保留至少 360 次用于达到开发条件后的独立十二题复验。第六轮两臂均在迁移后的 D 盘工作树写入新私有记录；迁移经过全部文件哈希核验，模型服务、索引、原运行数据与总账未移动或改写。

先完成离线回归并冻结代码和计划，再自动执行。开发阶段必须正确数增加、两个控制题不退步、已交付来源支持答案，才能进入主计划规定的十二题新对照；最终仍须满足独立复验增益，不能以审阅文本看起来合理、少搜几次或一次正确提交替代。准确率、来源支持、模型请求、工具与后端成本分别报告；原官方 6/12 保持不变。
