# 固定候选池中的查询词覆盖重排

本次比较 baseline 与 `search-coverage-rank-v1`，检验同一查询的有限检索结果顺序是否影响有来源支持的正确答案。CPU索引、原OR查询编译器和上游BM25排序保持不变；候选臂每条实际后端search固定取20条，按查询词在返回URL标题和完整导航摘要中的覆盖重新排序，再返回模型原先请求的top_k条。没有辅助模型、向量索引、全文扫描、模型改写或自动原文读取。

## 精确规则与边界

仅适用于明确声明的 stride-cpu-or-1 后端及 compiler=cpu-or-1 元数据。不同查询词取原编译器terms，逐词casefold并去重；URL标题与完整原snippet按Unicode正则词提取后casefold。排序键为不同查询词的精确命中数降序、原候选顺序升序。没有子串匹配、词干化、人工停用词、同义词、题号或答案权重。覆盖数只是词面属性，不表示候选关系得到验证。

原search工具参数类型、top_k合法范围和模型填写值不变。实际后端参数top_k=20如实记录；候选池最多20个唯一docid，全池完成字段和有限数值score检查后再排序。原docid、URL、snippet、score逐字保留，不能把覆盖数写成原BM25 score。只为实际返回的top_k注册可见导航文档，池内未显示的文档不获得来源或读取授权。

原后端wire与候选池、原排名、覆盖词及覆盖数、重排顺序、选中docid、规则hash都有审计关联。缓存key包含规则与池大小；同一查询命中缓存时返回同一已排序结果，不产生新CPU请求或假装新的排名进展。一个search仍可能包含多条query，各自占用原后端计数。取20候选可能增加SQL、snippet构造和序列化成本，不能因HTTP数不变就称免费。

模型可见的retriever_capabilities明确区分上游BM25排序和当前本地覆盖重排。保留其原OR、非短语/非site过滤、URL标题和来源边界说明；不更改SYSTEM、工具定义或其他控制状态。R1预期只在该能力声明上有差异；原题、schema、原始Config、离散预算、model和temperature相同。候选独立启用，不叠加搜索自动原文、历史省略、阶段只读或额外错误提示机制；baseline入口保持原样。

## 依据与风险

已封存失败显示，长OR查询多次返回人物合集、婚姻故事及节目综述；模型容易把页面内的一次实体提及当成目标页面，随后重复检索。第十轮自动读取确实交付了许多原文，但其中多个窗口主体不相关。第十一轮省略历史分析也未解决难题，且唯一判分增益的引用不支持共同创立关系。这些记录支持检验检索呈现，不能证明排序就是根因。

论文对BrowseComp-Plus的BM25参数和神经重排有正结果，但使用不同实现、更长预算、额外模型或调参数据；没有直接验证本次精确覆盖规则。文献与负结果见 LITERATURE_COVERAGE_RANK.md。本规则可能让常见词较多的聚合页挤掉稀有实体页，摘要截断也会造成低覆盖；原BM25本来有效时重排可能有害。它不核验跨句主体、出生/成长关系或年份，也不将导航升级成证据。
