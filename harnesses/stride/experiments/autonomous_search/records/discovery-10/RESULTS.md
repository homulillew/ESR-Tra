## 方案、运行身份和验收

实际冻结运行 SHA 为 `72ec6f10d3449390de8c570e92407f7da8fed640`。唯一机制变量为 baseline 与 search-raw-window-v1：成功 search 后，只考虑首 query 的首文档，用该 query 在完整 snapshot 中确定性选择至多3000字符原文；每个 episode 最多尝试六个不同文档，不匹配不返回，不自动换文档。CPU读取计入原后端预算，原文必须实际交付后才能引用。SYSTEM及search描述同步声明原文与导航的区别，没有额外模型、人工候选、强制tool_choice或自动代答。

两臂使用同一实际 GLM 服务和返回身份、temperature=0、只读 CPU SQLite FTS5 索引、原问题、full workflow、string-integer-v1。难题每槽16次、控制4次策略请求，600秒局部单调时钟；所有原动作、输出、后端、上下文约束保持一致。四对实际R1请求检查确认只有SYSTEM与search描述不同；R1字节不相同是本机制声明所需的预期差异。详细配置、顺序、身份与规则哈希见 PLAN.json、EXECUTION_PLAN.md、RECORD_IDENTITY.json。

启动前实际完成24项定向和535项全量离线回归，均通过，日志与XML哈希及修复过程见 OFFLINE_TESTS.json。旧记录的首结果覆盖诊断只用已有snapshot，不是模型重放成功，也未取得新的CPU数据。线上开始后代码和计划未修改。八条策略全部封存后，才对五个实际提交调用项目原judge；三条无提交不伪造judge标签。

## 原文是否实际生效，以及仍然失败的原因

候选四槽共12次自动文档尝试、12次成功窗口，全部在后续实际请求中收到交付确认，共36000字符；其中一次snapshot缓存命中，实际新增自动取文档11次。另有5次重复文档跳过、9次达到六文档上限跳过；没有不匹配、取文错误或容量拒交。自动尝试分别为q775三次、q774六次、q771一次、q778两次。自动原文与模型原生read分别记录，不伪造read动作。

- **q775候选**：R2自动读到韩江作品的出版与获奖事实，R3读到奖项规则；这些窗口都实际送达。R10却突然引入另一作者和作品，没有相应原文，并在同一响应里先说该作者实际出生/成长于Istanbul，又按题目关系断言Gwangju，最终提交Gwangju，refs=e2/e3。两个引用都没有Gwangju或该作者，无法支持目标城市。项目judge判错，独立原文审阅也判断核心答案无支持。自动读取解决了部分证据获取，未解决未经验证的候选连接和自相矛盾。
- **q775基线**：R2误用字符串queries，R3修正；仅有一次原生read，读到普通Booker奖资料。后续围绕奖项和作品反复搜索，R16进入FINAL仍search，最终model_budget空答。
- **q774候选**：自动窗口多为人物死亡、长寿剧集、真实婚姻等局部事实。R5原生read截取亲属文章开头，没有目标兄妹；同轮自动读取缓存snapshot的另一窗口e7，实际找到Jessica/Richard Harmon的兄妹及剧中角色关系，并在R6交付。因此不能说关键文字从未进入上下文。但它混淆首次登场季与转为主演季；后面声称读John Murphy，实际read了Raven Reyes页面，婚姻、子女及身高条件仍未成立，R16弃答。
- **q774基线**：将异常身高单位和首次出演时间自行解释，缩窄婚姻次数，早期锚定另一剧集人物后重复搜索；没有原生read，R12在bounded-workflow FINAL弃答。两臂都未完成同一演员的条件链。
- **q771**：两臂Vakkorama均判对。候选自动窗口直接包含父子共同创立品牌的句子，后续原生read补充年轻品牌定位，三次请求完成；基线四次完成，但已交付窗口对“父子共同创立”的直接支持不完整。这是来源覆盖的局部改善，没有形成配对准确率增益；其他背景条件未全部核实。
- **q778**：两臂原始finish.answer均为JSON整数21，规则string-integer-v1生成终态字符串“21”，refs保留且有已交付报道的母亲年龄句直接支持。候选首个自动窗口不相关，第二个窗口才命中；两臂都是四次请求。完整家族/公司背景未逐项证明，核心所问年龄有支持。整数协议是已有能力，不计为本轮机制收益。
