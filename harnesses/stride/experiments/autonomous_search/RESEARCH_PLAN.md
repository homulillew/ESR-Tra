# Agent Search Harness 自主迭代计划

## 目标与固定条件

目标是在真实模型对照中提高回答准确率，并单独统计工具与 token 成本。依据用户本次指令执行论文检索、失败分析、实现、离线验收、冻结在线实验、后处理判分和下一轮机制选择，无需逐轮人工批准。

起点为 `ac39d7449d5d1974a0de9520e476bf0a1656cd29`。保留 `gap-workflow-v1` 的 full profile、`string-integer-v1`、原模型服务（请求 EB-GLM-5.2、实际期望 glm-5.2）、temperature=0、原只读 CPU SQLite FTS5 索引、来源交付和终答合同。两臂仅在命名的 `decision_protocol` 上有差异。每阶段 PLAN 记录实际全部 Config、源码/问题哈希和队列；每次阶段启动前提交冻结，阶段内不更改实现。

难题槽位最多16次策略请求，q771/q778短控制最多4次；每槽600秒；max_actions=200、max_backend_calls=120、max_output_tokens=4096、max_total_output_tokens=48000、context_limit=96000 UTF-8字节、response_reserve=4096 UTF-8字节。每槽为空episode，正式CLI入口执行。历史失败不能代替本次baseline；实验标签和论文/人工分析不进入策略请求。

## 额度刷新与审计

用户明确授权本轮 GLM 请求额度刷新为1000。在原共享 SQLite 总账中追加唯一 `allowance_epochs` 记录，将当前剩余授权设为1000；保留所有历史请求和刷新前 cap/used、历史记录哈希。同一epoch重复初始化不再次增加额度。新 cap 等于刷新时实际 used 加1000，未使用旧额度不另行叠加。此操作记录用户授权窗口，不宣称查得服务端余额。

本轮策略、辅助推理和judge的每一次真实HTTP尝试（失败、未知状态同样）均计入这1000次，发送前原子占账。子Agent的论文研究不调用GLM。每阶段还有独立策略/judge上限，基础设施、身份、完整性或预算异常停止当前队列，无自动换账号、模型、路由或重试。额度不能保证一定找到提升；如耗尽仍失败，保存结果并明确目标未达成，不能编造成功。

## 分阶段选择与停止条件

1. 开发筛选：q775、q774，以及短控制q771、q778，每题baseline和候选各一个自然槽位，交错顺序。最坏80策略＋8judge=88次。第一轮唯一变量是逐条件证据核对指令，不增加调用、工具、字段或语义硬门禁。
2. 候选只有在开发队列正确数严格增加、两个短控制没有从正确变错误时，才进入独立复验。若失败，封存并分析实际轨迹，再查论文选择另一个可分离机制；失败配置不偷偷重命名为成功。
3. 冻结12题复验：770、778、772、774、769、775、786、776、771、788、793、794，两臂各一个新自然槽位；同题预算相同，交错顺序与开发不同。最坏336策略＋24judge=360次。其余8题首次复验前不用于本轮提示设计或失败诊断。
4. 实测停止标准：开发队列与独立12题复验的准确率增益方向均为正；12题正确数至少增加1，两个短控制无正确→错误，且其余8题净正确数至少增加1。有效提交必须有已交付原文支持所问答案；若judge判对但证据/主体关系明显不支持，该个例不能作为成功停止的依据。
5. 该标准只支持小规模、已暴露开发集上的可复现改进，不等于总体或统计显著提升。报告配对胜/负、准确率差、精确配对检验及不确定性，不修改旧正式6/12。若复验已用于后续设计，后续报告明确该组也已暴露，不再称其未参与设计。
6. 至少预留360次用于一次完整复验。开发探索与辅助调用不得耗尽这一预留；达到停止标准立即结束，不为用满额度继续运行。必要的第二次冻结复验必须在剩余额度内，全部失败也完整保留。

## 判分、失败审阅与发布

所有策略槽位封存后，项目原judge只评实际submitted的完整 `terminal.answer`。无提交计为任务未完成，不伪造judge标签。标准答案只进入封存后的judge，不进入策略、机制或候选筛选提示。独立原文审阅检查核心实体、关系、引用是否真的存在，尤其记录“局部事实正确但候选错”“错误→弃答”“正确→错误”。

逐轮记录原始HTTP、工具ID/arguments、回执、原文窗口、源码/配置身份、预算占账、cache/未知token和耗时。真实运行完整轨迹先在私有新目录封存，再按用户已授权的完整发布方式脱敏，保留模型输入输出及证据原文不改、公开档案hash映射；凭证、部署地址、生产索引和共享预算库不上传。代码、文献笔记、测试、冻结计划、结果与完整轨迹提交到独立后继分支。

第一轮是论文启发的低成本迁移假设，不宣称复现 FineVerify 的多轨迹检索验证。论文中采样、额外检索或训练带来的增益不能直接归于本协议。
