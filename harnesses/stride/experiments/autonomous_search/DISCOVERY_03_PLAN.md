# 第三轮：省略中间轮的历史散文

## 问题与假设

第二轮四题对照中，基线与检索入口提示方案均为 2/4。两道难题仍未提交；提示虽正确交付，后续查询没有改查独立线索。轨迹反复出现相同候选、未证实条件被描述为已有支持，以及在 FINAL 继续搜索。完整结果见 records/discovery-02。当前没有可晋级十二题复验的候选。

本轮单独检验：在保留工具调用与原文的前提下，从后续请求中省略部分已经完成轮次的可见散文，是否减轻旧猜测反复影响新决策，并降低输入或无效重复成本。这不会纠正来源事实，也无法在当前响应内部截断重复生成。

## 唯一变量与协议

正式 CLI 使用 `decision_protocol=middle-history-v1`，对照仍为 baseline。两臂的系统提示、工具 schema、原题、GLM 服务、实际模型身份、temperature=0、CPU FTS5 索引、整数答案合同与各项预算相同。不叠加条件检查表或检索入口提示，不增加模型调用。

构建请求时，保留 episode 原始首个完整动作组及当前最新完整组的 assistant 散文。对它们之间、含有非空 tool_calls 的完整组，仅在临时副本中将 assistant.content 置为 null；tool_calls 的 ID、名称、原始 arguments 和全部工具回执/原文保持不变。只有少于三个原始组且首组仍在场时，通常没有可省略组。原始首组被已有 rolling 容量处理丢弃后，不恢复该组，也不把其他最早幸存组视为原始首组。

Anthropic 原生副本同步去掉这些组的 text 块，保留 tool_use、thinking/redacted_thinking、签名与顺序；OpenAI reasoning_content 保留。这里省略的是可见散文，不等于删除提供方所有推理字段。当前线上仍使用原 OpenAI-compatible GLM 服务。

原 HTTP 响应、归档组和 SQLite 中的原文不修改；plan.groups 保持原对象。实际请求按投影后的 wire 计量，既有容量规则可能因此保留不同数量的历史组，这是本变量的后果。上下文试构建不写事件；实际请求留档时记录规则身份、保留组轮次、变化来源轮次及被省略文本的哈希和长度。notes、未提交响应修复内容、控制状态和当前输出不在省略范围内。

## 冻结队列与验收

固定开发题 q775、q774、q771、q778，每题 baseline 与 middle-history-v1 各一个新空 episode，采用与第二轮相反的交错顺序。难题每槽最多十六次请求，短控制每槽四次，每槽六百秒；最多八十次策略请求、八次 judge。标准答案仅在全部策略封存之后进入原项目 judge，不进入模型策略或省略规则。

当前刷新窗口已用 116/1000，剩余 884。继续使用同一持久总账，失败和未知发送占额；预留至少 360 次供满足筛选条件后的完整十二题新对照。判定仍要求开发正确数严格增加、控制题无回退，并完成主计划规定的独立复验。仅输入变短、弃答增多或重复减少，均不满足准确率提升目标。

离线检查覆盖首/末组、已丢弃首组、原组不变、预构建幂等、真实投影后计量、工具 ID 配对、原文与引用范围、Anthropic 实际请求、原始 SQLite 回放和 CLI 启用。源码与测试哈希在在线前写入 PLAN.json 并提交冻结。完整既有回归必须通过；HTTP/身份/数据/预算异常或截断保存并停止当前队列，无自动重试或变更解码设置。

在线逐槽报告实际投影次数与来源轮次、正确提交、弃答/预算/截断、工具和新原文、输入/输出/cache token、CPU 后端与耗时。历史散文变短可能破坏前缀缓存，也可能丢失排除理由；这些都作为成本和失败审阅的一部分保留。

## 文献依据与限制

[Agent-Omit](https://arxiv.org/html/2602.04284v1) 的固定前缀干预显示，中间轮推理存在可省略位置，而删除最初或临近结束的推理会损害表现。其完整方案使用训练，当前启发式不复现该训练收益。

[Buried in Textual Debt](https://arxiv.org/html/2608.22963v1) 对保留工具/观测但省略推理的实验给出正负结果：定向筛选与全部省略并不等价，全部省略有明确准确率下降。其分布级筛选操作不由当前 API 提供。本轮规则只是受位置干预启发的、免训练可检验假设，不能宣传为已经证实的恢复方法。原首轮或最新轮如果恰含错误猜测，本规则仍会保留它。
