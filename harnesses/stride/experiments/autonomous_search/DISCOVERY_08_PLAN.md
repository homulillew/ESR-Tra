# 第八轮：一次只提供 read 工具的决策

本轮候选 `read-only-once-v1` 检验一个具体行为假设：连续搜索且没有取得新原文时，临时缩小一次可用工具集合，是否能让模型提前读取有用材料并提高最终正确率。连续搜索不被程序判断为语义失败；三轮阈值只是事先固定的触发条件。

触发要求连续三个已完成轮次有 executed=true 且 ok=true 的 search 回执、没有新原文实际交付；当前最终可发送上下文包含至少一个按原规则可以 read 的可见文档；非 FINAL、至少剩三次模型请求。每个 episode 最多一次，失败发送也消耗该次机会。

该次请求仅从原工具集合筛选原 read schema，字段保持不变。原 SYSTEM、题目、完整正常历史、control、notes、提供方推理及预算均原样保留，不追加阅读指令，不强制 tool_choice，不开启 strict，不叠加关系审阅、历史散文省略或记忆保留。模型自行选择已授权页面和精确范围；一个请求仍可含原 max_batch 允许的多个 read，不能称为只读一页。下一次请求恢复正常工具。

实际导航来自保留工具组及当前 control 中确实呈现的导航引用，并与引擎原 read 授权集合相交。已归档或曾授权但当前不可见的文档不能单独触发。容量候选重建时重新判断，最终导航消失则取消触发且不消费。工具集合缩短可能影响可容纳上下文，属于该变量的后果，按实际 wire 计量；不得为触发从档案补原文或导航。原 plan.groups、原响应与工具回执不改写。

真实请求归档后、发送前提交一次触发，记录观察轮次、可见合法文档、工具 schema 和最终 wire 哈希。容量预构建不修改状态。原参数解析、read 校验、来源授权、CPU 后端、缓存、范围、交付与停止规则保持不变。若模型输出其他工具或纯散文，按该阶段边界明确拒绝或走原无显式动作处理；不改写为 read，不代选页面，不额外补一次模型调用。

动机来自已封存开发轨迹：第七轮 q775 候选有78个导航但没有一次 read；q774 基线到第九轮才开始读取，后续只有亲属关系原文。本假设直接改变一次工具可用性，不假设读到页面就解决实体关系。其他已封存轨迹表明，读取错误候选、窗口不含主体或局部真关系被错误组合仍可失败；这些结果必须保留。

文献依据和反例见 LITERATURE_READ_ONLY.md。没有论文证明在同一模型、CPU索引和16次请求下，一次只提供 read 就提高正确率。本轮是局部行为实验，不是复现完整文档交互架构。

固定新空 episode 队列：q775 基线→候选，q774 候选→基线，q771 基线→候选，q778 候选→基线。难题每槽16次，控制题4次，每槽600秒；上限80策略＋8judge。模型部署和实际身份、temperature=0、full工作流、string-integer-v1、CPU索引、原问题及预算均保持一致。4次控制预算不能满足三轮后仍余三次的门槛，控制只能验证未激活路径。

代码与计划在开始前提交冻结；全部策略封存后才读取标准答案和调用项目 judge，来源支持独立审阅。HTTP、身份、截断、CPU、完整性或预算异常即封存停队列，不自动重试或换服务。当前刷新窗口已用378/1000，剩622；沿用原总账发送前原子占额。最坏本轮后仍余534，保留至少360次给满足开发条件后的十二题新对照。

分别报告触发资格、实际工具限制、模型是否自主生成合法 read、原文是否实际交付、是否涉及新实体/条件、终态与正确率，以及模型/工具/后端/token/cache/耗时。多读一次原文或少搜几次不等于任务成功。晋级和停止仍须满足主计划的开发增益、控制无退步、来源支持以及独立十二题和其余八题净增益；旧正式6/12不变。
