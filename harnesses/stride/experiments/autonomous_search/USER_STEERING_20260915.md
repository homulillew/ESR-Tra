# 研究执行期间新增的用户要求

用户在首个冻结队列运行期间补充：若研究因当天 API 调用额度耗尽而阻塞，可以保存进度，等北京时间零点额度刷新后恢复；如果当前十二题的失败问题已经解决，继续评估其他难题，把新发现的失败纳入论文检索、机制设计、冻结实验与轨迹分析的闭环。

这些要求不改变正在执行或已经封存的队列、源码和原始记录。每天的授权窗口独立记账，旧请求和旧额度记录全部保留；等待跨日不会自动重跑失败槽位或把未运行槽位改为成功。跨日恢复应明确记录恢复原因、日期与新增授权，保持同一冻结实验的身份和实际累计消耗可追溯。

扩大题集前固定选题规则与问题清单，再执行新自然运行。已被用于失败分析和方案设计的题目按已暴露开发数据报告；不会把它们重新称为未见数据。当前首轮未完成问题解决，仍先分析其真实失败并验证下一项通用机制。
